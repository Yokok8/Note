# 线程池（Thread Pool）

## 一、为什么要有线程池？

**先看问题**：以前我们每来一个任务就 `new Thread().start()` —— 这有三个大毛病：

| 问题 | 说明 |
|---|---|
| **线程创建太贵** | 每 new 一个线程，操作系统要分配栈、注册内核线程，开销不小 |
| **线程数量失控** | 请求一多就疯狂 new，几千个线程直接把内存和 CPU 打爆 |
| **没法复用** | 线程跑完 run 就死了，下一个任务得重新建一个 |

> **线程池的作用：把线程"养"在一个池子里，来任务就派一个空闲线程去干，干完不销毁，继续等下一个任务。**&#8203;
> 一句话：**线程复用 + 数量可控。**&#8203;

💡 **类比**：不是每次点外卖都临时雇一个厨师，而是**开一家餐厅，雇固定几个厨师，来单子就派一个去做。**&#8203;

---

## 二、核心原理（就是开头那张图）

线程池里有**三种"位置"**&#8203;可以安置任务：

| 位置 | 说明 |
|---|---|
| **核心线程** | 池子的"正式员工"，长期存在，随叫随到 |
| **任务队列（阻塞队列）**&#8203; | 核心线程都忙时，任务先来这里排队 |
| **临时线程** | 队列也满了，才临时招"兼职"，空闲一段时间后会被裁掉 |

**提交任务的四级判断（背下来）：**
① 核心线程有空闲 → 直接派活  
② 核心线程满了 → 任务丢进队列排队  
③ 队列也满了 → 创建临时线程来干  
④ 线程数到上限了 → 触发拒绝策略


# 线程池代码实现（Executors 工具类）

## 课件原话（背下来）

> **Executors：线程池的工具类，通过调用方法返回不同类型的线程池对象。**&#8203;

关键词：**工具类 + 返回线程池对象**。它不是线程池本身，是"**&#8203;造线程池的工厂**"。

---

## 课件方法表（+ 补充第三行）

| 方法名称 | 说明 |
|---|---|
| `public static ExecutorService newCachedThreadPool()` | 创建一个**没有上限**的线程池 |
| `public static ExecutorService newFixedThreadPool(int nThreads)` | 创建**有上限**的线程池 |
| `public static ExecutorService newSingleThreadExecutor()` | 创建**只有一个线程**的线程池（补充） |

**注意返回类型都是 `ExecutorService`** —— 这是个接口，你拿到的是"能提交任务的线程池"，不用关心具体实现类。

---

## 一、"没有上限 / 有上限"到底指什么？

**指的是【线程数量】的上限**，不是别的。

| 方法 | 线程数上限 | 谁在兜底 |
|---|---|---|
| `newCachedThreadPool()` | `Integer.MAX_VALUE`（约 **21 亿**）≈ 没有上限 | ❌ 没人兜底 |
| `newFixedThreadPool(n)` | **n**（你传多少就是多少） | ✅ 多的任务去排队 |

---

## 二、⚠️ 但"有上限"的那位，藏着一个没上限的东西

这是这张表**最值得深挖的点**：

| | 线程数 | 任务队列 |
|---|---|---|
| `newCachedThreadPool()` | ❌ 没上限（21 亿） | ✅ 不缓存（`SynchronousQueue`，直接交给线程） |
| `newFixedThreadPool(n)` | ✅ 有上限（固定 n） | ❌ **无上限**（`LinkedBlockingQueue`，能塞到内存爆） |

> **结论：两个都会 OOM，只是爆的地方不一样 —— 一个爆线程，一个爆队列。**&#8203;

---

## 三、底层参数对照（它们其实就是预设好的 ThreadPoolExecutor）

| 参数 | newCachedThreadPool() | newFixedThreadPool(n) |
|---|---|---|
| 核心线程数 | **0** | **n** |
| 最大线程数 | **Integer.MAX_VALUE** | **n** |
| 空闲存活时间 | **60 秒** | 0（核心线程不回收） |
| 任务队列 | **SynchronousQueue**（不存储） | **LinkedBlockingQueue**（无界） |

**怎么读懂这两行？**

### `newCachedThreadPool()` 的工作方式
任务来了  
├─ 有闲置线程？→ 直接复用 ✅  
└─ 没有？ → 立刻 new 一个线程（因为核心是 0，直接就往临时线程扩）  
用完的线程闲置 60 秒后自动销毁


>  **“Cached（缓存）"说的就是"把用过的线程缓存 60 秒”** &#8203; —— 适合**任务短、流量忽高忽低**的场景（比如大量小文件转码）。

### `newFixedThreadPool(n)` 的工作方式
任务来了  
├─ 线程数 < n？→ 新建线程干  
└─ 已经 n 个了？→ 全部丢进队列，排队等着（队列几乎无限大）


> **线程数一创建就固定，不会扩也不会缩** —— 适合**流量稳定、要控制并发量**的场景。

---

## 四、代码演示

```java
public class Demo {
    public static void main(String[] args) {

        // ① 没有上限：任务多就疯狂建线程
        ExecutorService cached = Executors.newCachedThreadPool();

        // ② 有上限：最多 3 个线程，其余排队
        ExecutorService fixed = Executors.newFixedThreadPool(3);

        for (int i = 1; i <= 10; i++) {
            final int n = i;
            fixed.submit(() -> {
                System.out.println(Thread.currentThread().getName() + " 执行任务" + n);
            });
        }

        // ⚠️ 用完必须关，否则 JVM 不退出
        cached.shutdown();
        fixed.shutdown();
    }
}
```

# 线程池七大参数（ThreadPoolExecutor）

> 这七个参数就是 `new ThreadPoolExecutor(...)` 括号里那一串 —— **课件只给了中文名，我把参数名和类型一起补上。**&#8203;

## 一、七大参数总表（背下来）

| 序   | 中文名                              | 参数名               | 类型                         | 一句话含义                  |
| --- | -------------------------------- | ----------------- | -------------------------- | ---------------------- |
| 1   | **核心线程数量**（不能小于0）                | `corePoolSize`    | `int`                      | 池子里**长期保留**的线程数（正式员工）  |
| 2   | **线程池中最大线程的数量**（最大数量>=核心线程数量）    | `maximumPoolSize` | `int`                      | 池子里**最多**能有的线程数（含临时工）  |
| 3   | **空闲时间（值）**&#8203;（不能小于0）        | `keepAliveTime`   | `long`                     | 临时线程空闲多久后被销毁           |
| 4   | **空闲时间（单位）**&#8203;（用TimeUnit指定） | `unit`            | `TimeUnit`                 | 上面那个数字的单位（秒/毫秒…）       |
| 5   | **阻塞队列**（不能为null）                | `workQueue`       | `BlockingQueue<Runnable>`  | 核心线程满了，任务在这排队          |
| 6   | **创建线程的方式**（不能为null）             | `threadFactory`   | `ThreadFactory`            | 怎么造线程（起名字、设守护线程）       |
| 7   | **要执行的任务过多时的解决方案**（不能为null）      | `handler`         | `RejectedExecutionHandler` | 队列和线程都满了，怎么办（**拒绝策略**） |

# 自定义线程池（任务拒绝策略）

## 课件原表（背下来）

| 任务拒绝策略 | 说明 |
|---|---|
| **`ThreadPoolExecutor.AbortPolicy`** | **默认策略**：丢弃任务并**抛出 `RejectedExecutionException` 异常** |
| `ThreadPoolExecutor.DiscardPolicy` | 丢弃任务，**但是不抛出异常**，这是不推荐的做法 |
| `ThreadPoolExecutor.DiscardOldestPolicy` | **抛弃队列中等待最久的任务**，然后把当前任务加入队列中 |
| `ThreadPoolExecutor.CallerRunsPolicy` | **调用任务的 `run()` 方法绕过线程池直接执行** |

---

## 四、代码模板（照着抄就行）
```java
ThreadPoolExecutor pool = new ThreadPoolExecutor(
        corePoolSize: 3,                       // 核心线程数，不能小于 0
        maximumPoolSize: 6,                    // 最大线程数，不能小于 0，最大数量 >= 核心线程数量
        keepAliveTime: 60,                     // 空闲线程最大存活时间，不能小于 0
        TimeUnit.SECONDS,                      // 时间单位，用 TimeUnit 指定
        new ArrayBlockingQueue<>(3),           // 任务队列，不能为 null
        Executors.defaultThreadFactory(),      // 创建线程工厂，不能为 null
        new ThreadPoolExecutor.AbortPolicy()   // 任务的拒绝策略，不能为 null
);
```

**真实代码（去掉参数名）**
```java
ThreadPoolExecutor pool = new ThreadPoolExecutor(
        3,
        6,
        60,
        TimeUnit.SECONDS,
        new ArrayBlockingQueue<>(3),
        Executors.defaultThreadFactory(),
        new ThreadPoolExecutor.AbortPolicy());
```

# 线程池多大合适？（线程数怎么算）

## 一、先按任务类型分两种

| 任务类型 | 公式 | 一句话 |
|---|---|---|
| **CPU 密集型运算** | **最大并行数 + 1** | 线程主要时间在**算** |
| **I/O 密集型运算** | **最大并行数 × 期望 CPU 利用率 × 总时间 / CPU 计算时间** | 线程主要时间在**等** |

> **判断依据：你的任务是在烧 CPU，还是在等 IO（磁盘、网络、数据库）？**

---

## 二、三个变量分别是什么

### 1️⃣ 最大并行数

**就是"逻辑处理器数"**&#8203;，超线程也算进去。

| 硬件 | 最大并行数 |
|---|---|
| 4 核 8 线程 | **8** ⚠️ 不是 4 |
| 8 核 16 线程 | 16 |
| 12 核 | 12 |

```java
// 代码里怎么拿
int cores = Runtime.getRuntime().availableProcessors();
System.out.println(cores);   // 4核8线程的机器上输出 8
```
