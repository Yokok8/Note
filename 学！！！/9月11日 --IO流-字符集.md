# 字符集（编码表）

## 常见字符集

| 字符集 | 支持 | 单字符字节数 |
|--------|------|------------|
| **ASCII** | 英文 | **1 个字节** |
| **GBK** | 英文 + 中文 | 英文 1 字节、**中文 2 字节** |
| **Unicode** | 英文 + 中文 | 常用 UTF-8（英文 1 字节、**中文 3 字节**） |

---

# ASCII 编码规则（其他字符集同理，除汉字外）

## 编码过程（字符 → 字节）

```
要存储的英文 'a'
 ↓ 查询 ASCII 表
对应的数字 97
   ↓ 编码二进制 0110 0001（前面补 0，补齐 8 位 = 1 字节）
```

## 解码过程（字节 → 字符）

```
读取到的二进制 0110 0001
   ↓ 解码（直接转十进制）
数字 97
   ↓ 查询 ASCII 表
英文 'a'
```

---
## 🔑 两个核心规则

| 规则 | 内容 |
|------|------|
| **ASCII 编码规则** |前面**补 0，补齐 8 位** |
| **ASCII 解码规则** | **直接转成十进制** |


# 计算机的存储规则（汉字）- GBK

## 编码过程（汉字 → 字节）

```
要存储的汉字'汉'
 ↓ 查询 GBK 表
对应的数字 47802
   ↓ 编码 → 二进制 101111010 101111010
```

| 规则             | 内容                                     |
| -------------- | -------------------------------------- |
| **规则 1**       | 汉字**两个字节存储**                           |
| **规则 2** ⚠️    | **高位字节**二进制**一定以 1 开头**，转成十进制之后是**负数** |
| **GBK 汉字编码规则** | **不需要变动**（直接转成二进制）                     |

编码流程：`'汉'` → 查 GBK 表 → `47802` → 编码 → `101111010 101111010`
解码流程：`101111010 101111010` → 高位是 1 → 认出是汉字，直接转成二进制 → 两字节查 GBK 表 → `'汉'`



# Unicode / UTF-8 编码规则

## 编码过程
```
要存储的英文 'a'
 ↓ 查询 Unicode 表
对应的数字 97
```

---

## 🔑 UTF-8 编码核心规则

**UTF-8 编码规则：用 1~4 个字节保存**

| 字符 | 字节数 | 特征 |
|------|--------|------|
| **ASCII（英文）**&#8203; | **1 个字节** | 二进制以 **0** 开头 |
| **简体中文** | **3 个字节** | 二进制首字节以 **1110** 开头 |

---

## 📊 UTF-8 编码方式速查表（二进制格式）

| 字节数 | 格式 | 首位标记 |例子 |
|--------|------|---------|------|
| **1 字节** | `0xxxxxxx` | **0** | 英文、数字、ASCII |
| **2 字节** | `110xxxxx 10xxxxxx` | **110** | 拉丁文、希腊字母 |
| **3 字节** | `1110xxxx 10xxxxxx 10xxxxxx` | **1110** | **中文、日文、韩文** |
| **4 字节** | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` | **11110** | emoji、罕见字符 |

---

# UTF-8是一种编码方式

# 英文字符的 UTF-8 编码（'a'字）

```
要存储的英文 'a'
 ↓ 查询 Unicode 表
对应的数字 97
 ↓ 二进制 110 0001（7 位）
 ↓ UTF-8 编码：前面补 0，补齐 8 位
0110 0001（1 个字节）
```

# 汉字的 UTF-8 编码示例（"汉"字）

```
要存储的汉字'汉'
 ↓ 查询 Unicode 表
对应的数字 27721
 ↓ 转成二进制01101100 01001001
 ↓ UTF-8 编码
11100110 10110001 10001001（3 个字节）
```



# 为什么会有乱码？

## 原因 1：读取数据时**未读完整汉字**

字节流一次只读 **1 个字节**，但汉字是 **2 字节（GBK）或 3 字节（UTF-8）**&#8203;，读不完整就会乱码。

## 原因 2：**编码和解码时方式不统一**

写入用一种编码（比如 GBK），读取用另一种编码（比如 UTF-8），规则对不上 →必然乱码。

# 如何不产生乱码？

1. **不要用字节流读取文本文件**
2. **编码解码时使用同一个码表，同一个编码方式**
