# UDP 的三种通信方式

## 核心对比表

| 方式 | 发给谁 | 用的地址 |
|---|---|---|
| ① 单播 | **一台**设备 | 对方的具体 IP（如 192.168.1.5） |
| ② 组播 | **一组**设备 | 组播地址 224.0.0.0 ~ 239.255.255.255 |
| ③ 广播 | **同一局域网内的全部**设备 | 255.255.255.255 |

## 地址细节（考点在这）

**组播地址**
- 范围：`224.0.0.0 ~ 239.255.255.255`（属于 D 类地址）
- 其中 `224.0.0.0 ~ 224.0.0.255` 是**预留**的组播地址 —— **不要用**
  （这段是给路由协议等系统用途留的，占了可能出问题）
- 自己项目里用，建议挑 `224.0.1.0 ~ 238.255.255.255` 中间的值

**广播地址**
- `255.255.255.255` 叫**受限广播地址**
- **只在当前局域网（广播域）内有效**，路由器默认不转发，跨不了网段

# TCP 通信程序（原理）

## 三句话核心（课件原文）
1. TCP 是一种**可靠**的网络协议，它在通信的**两端各建立一个 Socket 对象**
2. 通信之前**要保证连接已经建立**
3. 通过 **Socket 产生 IO 流**来进行网络通信

## 和 UDP 的根本区别

| | UDP | TCP |
|---|---|---|
| 传输单位 | 打包成 `DatagramPacket` 扔出去 | **IO 流**（像读写文件一样） |
| 连接 | 无需连接，直接发 | **必须先建立连接** |
| 两端角色 | 发送端 / 接收端（**对等**） | **客户端 / 服务器**（有主次） |
| 可靠性 | 易丢数据 | 可靠，不丢 |

**这是本章最重要的一条分界线：**
UDP 是"数据装包 → send"；TCP 是"连上之后 → 拿流读写"。

## 两个类的分工

| 类 | 谁用 | 关键动作 |
|---|---|---|
| `Socket` | **客户端** | `new Socket(IP, 端口)` —— 主动去连服务器 |
| `ServerSocket` | **服务器** | `new ServerSocket(端口)` 监听；<br>`accept()` 等客户端连上来，**返回一个 Socket** |

⚠ **最容易懵的一点：**
服务器上真正用来通信的 Socket **不是 new 出来的**，而是 `accept()` **返回**给你的。
- 客户端：`Socket s = new Socket("127.0.0.1", 10086);`
- 服务器：`Socket s = serverSocket.accept();`

## IO 流的方向

| 角色 | 发数据 | 收数据 |
|---|---|---|
| 客户端 | `socket.getOutputStream()` → | ← `socket.getInputStream()` |
| 服务器 | ← 读到客户端的输出 | `socket.getOutputStream()` → 回给客户端 |

记法：**谁拿到 OutputStream，谁就在"往外说"。两端的流方向天然相反。**&#8203;

## 一句话记
**UDP 是寄快递（打包扔出去，不管到没到），TCP 是打电话（先拨通，再对着话筒说）。**&#8203;
那个"话筒"，就是 Socket 产生的 IO 流。



# TCP 通信程序 —— 两端步骤对照

## 并排对照表（这张最重要）

| 步 | 客户端（3 步） | 服务器（4 步） |
|---|---|---|
| ① | 创建 Socket 对象，连接服务端<br>`Socket(String host, int port)` | 创建 ServerSocket 对象<br>`ServerSocket(int port)` |
| ② | **获取输出流，写数据**<br>`OutputStream getOutputStream()` | **监听客户端连接，返回一个 Socket**<br>`Socket accept()` |
| ③ | 释放资源<br>`void close()` | **获取输入流，读数据并打印到控制台**<br>`InputStream getInputStream()` |
| ④ | — | 释放资源<br>`void close()` |

## 两边的本质区别

| | 客户端 | 服务器 |
|---|---|---|
| 建哪个对象 | `Socket` —— 一 new 就去连 | `ServerSocket` —— **只负责监听，不负责连** |
| 姿态 | **主动出击** | **被动等待** |
| 阻塞点 | 没有 | `accept()` 卡住等客户端 |
| 手上用的 Socket | 自己 new 的 | **`accept()` 返回的那个** |

## 易错点（踩过就记住）
1. **必须先启动服务器，再启动客户端**
   - 服务器没起，客户端 `new Socket()` 立刻报 `ConnectException: Connection refused`
2. `accept()` 是**阻塞方法** —— 没客户端来连，程序就停在那儿不动
3. 服务器**通信用的 Socket 是 `accept()` 返回的**，千万别想着 new 一个
4. `getOutputStream()` 返回的是**字节流**，写字符串要 `.getBytes()`
5. 两边的**端口号必须一致**：客户端的 `Socket(host, port)` 里的 port ↔ 服务器的 `ServerSocket(port)`

## 一句话记
**客户端三步：连、写、关。服务器四步：开、等、读、关。**&#8203;
多出来的那一步，就是 `accept()`。

# TCP 通信完整代码（客户端 + 服务器）

## 客户端（发送）
```java
    public class Client {
        public static void main(String[] args) throws IOException {
            // 1. 创建 Socket 对象（同时连接服务端，连不上直接报错）
            Socket socket = new Socket("127.0.0.1", 10000);

            // 2. 从连接通道中获取输出流
            OutputStream os = socket.getOutputStream();
            os.write("aaa".getBytes());

            // 3. 释放资源
            os.close();
            socket.close();
        }
    }
```

## 服务器（接收）
```java
    public class Server {
        public static void main(String[] args) throws IOException {
            // 1. 创建 ServerSocket 对象
            ServerSocket ss = new ServerSocket(10000);

            // 2. 监听客户端连接
            Socket socket = ss.accept();

            // 3. 从连接通道中获取输入流读取数据
            InputStream is = socket.getInputStream();

            int b;
            while ((b = is.read()) != -1) {
                System.out.print((char) b);
            }

            // 4. 释放资源
            socket.close();
            ss.close();
        }
    }
```

# TCP 三次握手 / 四次挥手

## 三次握手（确保连接建立）

| 步 | 方向 | 内容 |
|---|---|---|
| ① | 客户端 → 服务器 | 发出连接请求，**等待服务器确认** |
| ② | 服务器 → 客户端 | 返回一个响应，告诉客户端**收到了请求** |
| ③ | 客户端 → 服务器 | 再次发出**确认信息** → **连接建立** |

## 四次挥手（确保连接断开，且数据处理完毕）

| 步 | 方向 | 内容 |
|---|---|---|
| ① | 客户端 → 服务器 | 发出**取消连接请求** |
| ② | 服务器 → 客户端 | 返回一个响应，表示**收到**取消请求 |
| ③ | 服务器 → 客户端 | 发出**确认取消信息**（这一步之前，服务器把**最后的数据处理完毕**） |
| ④ | 客户端 → 服务器 | 再次发送确认消息 → **连接取消** |

## 为什么一个 3 次、一个 4 次？（必考理解点）

| | 三次握手 | 四次挥手 |
|---|---|---|
| 关键差别 | 服务器收到请求后，**"我收到了"和"我也要建立连接"可以合并成一步** | 服务器收到断开请求后，**不能马上断** —— 它可能还有数据没发完 |
| 所以 | 2 次对话 → 合并 → **3 步** | 中间被"处理剩余数据"隔开，**2 + 2 = 4 步** |

一句话：**握手能合并，挥手不能合并。**&#8203;
挥手多出来的那一次，就是给服务器留时间**把剩下的数据发完**。

## 口语类比（这样记最快）
**三次握手 = 打电话**
- 喂，听得到吗？（请求）
- 听得到，你能听到我吗？（响应）
- 听到了，开聊！（确认）

**四次挥手 = 挂电话**
- 我要挂了啊（请求）
- 知道了（响应）
- 我这儿还有一句没说完……好了说完了（处理完数据）
- 那挂吧（确认）

## 和代码对不上？其实都对上了
- **三次握手**：发生在 `new Socket("127.0.0.1", 10000)` 那一行，系统自动完成，你看不见
- **四次挥手**：发生在 `close()` 的时候，也是自动完成

所以你写代码时不用管握手挥手，**它们是 Socket 底层替你干的活** —— 但面试常问。

## 一句话记
**握手三次建立连接，挥手四次断开连接；多一次是因为服务器还有数据要处理完。**&#8203;
