# 日志技术

## 一、为什么 System.out.println 不够用
两个痛点（课件红字）：
- **只能输出到控制台**
- **不便于扩展、维护**

想输出到文件、按天滚动、分级别过滤 → println 都做不到，所以需要专门的**日志框架**。

## 二、什么是日志
- 类比：好比**生活中的日记**，记录你的点点滴滴
- 程序中的日志：记录应用程序的**运行信息、状态信息、错误信息**

四大作用（要背）：
**数据追踪、性能优化、问题排查、系统监控**

## 三、四个日志框架（对比记忆）
| 框架 | 是什么 | 特点 |
|---|---|---|
| **JUL** | JavaSE 平台官方日志框架（java.util.logging） | 配置相对简单，但**不够灵活，性能较差** |
| **Log4j** | 一个流行的日志框架 | 提供了**灵活的配置选项，支持多种输出目标** |
| **Logback** | 基于 Log4j **升级**而来 | 提供了**更多的功能和配置选项，性能优于 Log4j** |
| **Slf4j** | **Simple Logging Facade for Java**，简单日志门面 | 提供了一套日志操作的**标准接口及抽象类**，允许应用程序使用不同的底层日志框架 |

## 四、⭐ Slf4j 的"门面"是什么意思
- 前三者（JUL / Log4j / Logback）是**干活的实现框架**
- Slf4j **不干具体活**，只提供**统一接口** —— 应用程序代码**只面向 Slf4j 写**
- 好处：**底层换框架不用改代码**（和 JDBC 思路一样：定接口，各厂商实现）

默认搭配：**Slf4j + Logback**（SpringBoot 出厂就是这样）

## 五、易错点
| 易错 | 说明 |
|---|---|
| 以为 Slf4j 能直接干活 | 它只是门面，必须搭配底层框架 |
| 以为 println 和日志效果一样 | println 只能控制台输出、无法分级、无法持久化 |
| 以为 JUL 就是最佳选择 | 官方但不好用，实际项目多用 Logback |
| Log4j 和 Logback 不分 | Logback 是 Log4j 的升级版，性能更好 |

## 六、口诀
- **println 只能控制台，日志框架才是正解**
- **日志四大作用：追踪、优化、排查、监控**
- **Slf4j 是门面只管接口，Logback 是干活的实现**
- **代码面向 Slf4j，底层换谁都不用改**

# Logback 快速入门

## 一、两步走
1. **准备工作**：引入 logback 依赖 + 配置文件 logback.xml
2. **记录日志**：定义日志记录对象 Logger，记录日志

## 二、引入依赖
    <dependency>
        <groupId>ch.qos.logback</groupId>
        <artifactId>logback-classic</artifactId>
        <version>1.4.11</version>
    </dependency>

**注意（课件红字）**&#8203;：**SpringBoot 项目中该依赖已传递**——spring-boot-starter 自带的，**不用手动加**。
（Maven 传递依赖：你依赖 A，A 依赖 B，那 B 也会被自动引入）

## 三、固定样板代码（⭐ 每个类都这么写）

    private static final Logger log = LoggerFactory.getLogger(LogTest.class);

逐段拆：

| 部分 | 含义 |
|---|---|
| private static final | 定义成**全局常量**，全类共享这一个 log |
| Logger log | 类型 Logger 是 **org.slf4j 包的（门面接口），不是 Logback 的** |
| LoggerFactory.getLogger(...) | 用工厂方法拿对象 |
| LogTest.class | **传当前类**，日志输出里会显示这条日志来自哪个类 |

这也印证了上一页说的：**代码面向 Slf4j 写，底层 Logback 干活**——看 import 就知道，写的是 slf4j，引的是 logback。

## 四、记录日志的测试代码
    @Test
    public void testLog(){
        log.debug("开始计算...");

        int sum = 0;
        int[] nums = {1, 5, 3, 2, 1, 4, 5, 4, 6, 7, 4, 34, 2, 23};
        for (int i = 0; i <= nums.length; i++) {
            sum += nums[i];
        }

        log.info("计算结果为: "+sum);
        log.debug("结束计算...");
    }

- `log.debug(...)` / `log.info(...)` —— 对应不同**日志级别**（下一页会细讲）
- 用法就像 println，但输出更专业（带时间、级别、类名、线程）

## 五、易错点
| 易错 | 说明 |
|---|---|
| import 错 Logger 类 | 必须是 **org.slf4j.Logger**，不是 java.util.logging 的 |
| getLogger 里传错类名 | 要传**当前类**（LogTest.class），否则日志里的出处不对 |
| 手动再加 logback 依赖 | SpringBoot 项目已传递，重复加可能版本冲突 |
| 直接用 log.debug 但没初始化 log | 忘写样板代码 → 编译不过 |
| 用字符串拼接 + 日志 | 正确用法就是 + 拼接（SpringBoot 常用），但生产环境更多用 `{}` 占位符 |

## 六、口诀
- **SpringBoot 不用引依赖，一行样板代码直接写**
- **Logger 是 Slf4j 的门面，Logback 才是干活的**
- **getLogger 传当前类，debug / info 分级打**

# logback.xml 配置文件详解

## 一、三个要点（课件原文）
1. 配置文件名：**logback.xml**
2. 作用：对 Logback 日志框架输出的日志进行控制，可以配置**输出的格式、位置及日志开关**等
3. 常用的两种输出日志的位置：**控制台、系统文件**

## 二、appender —— 输出目的地
    <!-- 控制台输出 -->
    <appender name="STDOUT" class="ch.qos.logback.core.ConsoleAppender">...</appender>

    <!-- 系统文件输出 -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">...</appender>

| 部分 | 含义 |
|---|---|
| appender | 决定日志**往哪输出** |
| name="STDOUT" | **自定义标签名**，随便起，但要和下面 ref 对上 |
| ConsoleAppender | 输出到**控制台** |
| RollingFileAppender | 输出到**文件**，且是**滚动**的（按时间/大小切割，不会无限变大） |

## 三、root —— 总开关 + 引用
    <root level="ALL">
        <appender-ref ref="STDOUT" />
        <appender-ref ref="FILE" />
    </root>

- `level="ALL"` → **开启**日志（课件红字）
- `level="OFF"` → **关闭**日志
- `<appender-ref ref="xxx" />` → **引用**上面定义好的 appender，ref 的值必须等于 appender 的 name

**关键关系：appender 定义"往哪输出"，root 决定"用不用它、什么级别才输出"。**&#8203;

## 四、完整结构骨架（参考）
    <configuration>
        <!-- 控制台输出 -->
        <appender name="STDOUT" class="ch.qos.logback.core.ConsoleAppender">
            <encoder>
                <pattern>%d{HH:mm:ss} %-5level %logger - %msg%n</pattern>
            </encoder>
        </appender>

        <!-- 系统文件输出 -->
        <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
            <file>logs/app.log</file>
            <encoder>
                <pattern>%d{HH:mm:ss} %-5level %logger - %msg%n</pattern>
            </encoder>
        </appender>

        <root level="ALL">
            <appender-ref ref="STDOUT" />
            <appender-ref ref="FILE" />
        </root>
    </configuration>

- `<encoder>` + `<pattern>`：控制**输出格式**（时间、级别、类名、消息）
- 文件位置在配置文件里指定，启动后会在项目目录下生成日志文件

## 五、易错点
| 易错 | 说明 |
|---|---|
| ref 和 name 对不上 | 日志不输出（静默失效，最坑） |
| 文件名写成 log4j.xml / logback-spring.xml | 前者无效；后者是 SpringBoot 专用变体，也不一样 |
| 忘了写 root 标签 | appender 定义了也没人用，什么都不输出 |
| 用 ALL 上线 | 日志会爆炸，生产上一般用 info 或 warn |
| 文件用 FileAppender 不滚动 | 文件会无限增长，要用 **RollingFileAppender** |

## 六、口诀
- **appender 定去处：STDOUT 去控制台，FILE 去文件**
- **root 是总开关，ALL 开、OFF 关，ref 要跟 name 对上**
- **文件输出记得用 Rolling，不然日志把硬盘写满**

# 日志级别

## 一、五级日志（由低到高，顺序不能乱）
| 级别 | 说明 | 记录方式 |
|---|---|---|
| **trace** | 追踪，记录程序运行轨迹【使用很少】 | log.trace("...") |
| **debug** | 调试，记录程序调试过程中的信息，实际应用中一般将其视为**最低级别**【使用较多】 | log.debug("...") |
| **info** | 记录一般信息，描述程序运行的关键事件，如：网络连接、io操作【使用较多】 | log.info("...") |
| **warn** | 警告信息，记录潜在有害的情况【使用较多】 | log.warn("...") |
| **error** | 错误信息【使用较多】 | log.error("...") |

记忆顺序：**trace → debug → info → warn → error**（由低到高）
中文对应理解：**追踪 → 调试 → 普通信息 → 警告 → 错误**

## 二、⭐ 核心规则（课件红字）
可以在配置文件中灵活地控制输出哪些类型的日志：
**大于等于配置的日志级别的日志才会输出。**&#8203;

    <root level="info">
        <appender-ref ref="STDOUT" />
        <appender-ref ref="FILE" />
    </root>

举例：配置 `level="info"` 时：

| 级别 | 是否输出 | 原因 |
|---|---|---|
| trace | ✘ | 低于 info |
| debug | ✘ | 低于 info |
| **info** | ✔ | **等于** info |
| warn | ✔ | 高于 info |
| error | ✔ | 高于 info |

换成 `level="debug"` → debug 及以上全输出（trace 仍然不输出）。

## 三、和上一页的联系
- 上一页看到的 `level="ALL"` = **所有级别都输出**（等于开启全部日志）
- `level="OFF"` = **全部关闭**
- 平时写具体级别（debug / info / warn / error）来**精细控制**

## 四、实际怎么选（经验）
| 环境 | 建议级别 | 原因 |
|---|---|---|
| 开发阶段 | **debug** | 要看详细调试信息 |
| 生产环境 | **info / warn** | 日志量太大既影响性能又占磁盘 |
| 排查线上问题 | 临时调成 debug | 改完配置重启即可 |

## 五、易错点
| 易错 | 说明 |
|---|---|
| 把 "大于等于" 记成 "等于" | 配成 info，warn / error **照样输出** |
| 把级别顺序背反 | trace 最低，error 最高 |
| 以为 trace 常用 | 使用很少，一般把 debug 当最低级别用 |
| 生产环境配 ALL | 日志爆炸，磁盘瞬间写满 |
| 配了级别但代码里没写 log | 当然没日志，级别只是"过滤门槛" |

## 六、口诀
- **trace debug info warn error，由低到高**
- **大于等于配置级别才输出，低了就被过滤**
- **ALL 全开、OFF 全关，开发 debug、生产 info**

# 案例：优化 tlias 日志记录

## 一、改了什么（两个优化点）
| 原来                      | 现在                       | 好处               |
| ----------------------- | ------------------------ | ---------------- |
| 手写 Logger 样板代码          | 类上加 **@Slf4j**           | 一行注解搞定           |
| System.out.println(...) | **log.info(...)**&#8203; | 带级别、时间、类名，可控可持久化 |

## 二、改造后的代码
    @Slf4j
    @RestController
    public class DeptController {

        @Autowired
        private DeptService deptService;

        /**
         * 根据ID删除部门
         */
        @DeleteMapping("/depts")
        public Result delete(Integer id){
            log.info("根据ID删除部门: {}", id);  // System.out.println("根据ID删除部门: " + id);
            deptService.delete(id);
            return Result.success();
        }
    }

对照着看：原来那行 `System.out.println("根据ID删除部门: " + id)` 被注释掉，换成了 `log.info("根据ID删除部门: {}", id)`。

## 三、@Slf4j 干了什么
类上加 `@Slf4j`（**Lombok 提供的注解**），编译时自动帮你生成：
    private static final Logger log = LoggerFactory.getLogger(DeptController.class);
**所以你能直接用 `log` 这个变量，不用自己声明。**&#8203; 每个类都加一个，各管各的。

（IDE 里按住 Ctrl 点 `log` 能跳进这个自动生成的字段，可以自己验证。）

## 四、⭐ `{}` 占位符：slf4j 的核心特色
| 写法 | 说明 |
|---|---|
| log.info("根据ID删除部门: {}", id) | **推荐**：占位符，**延迟拼接** |
| log.info("根据ID删除部门: " + id) | 老写法：先拼字符串再判断要不要打 |
| log.info("id={}, name={}", id, name) | 多个占位符按顺序对应多个参数 |

**为什么用 `{}` 更好**：
字符串拼接是"**先拼好**再判断级别"——如果这条日志因为级别不够不打，拼字符串的性能就白费了。
占位符是"**先判断级别，要打才拼**"，省掉无谓开销。

规则：**`{}` 的个数必须和参数个数一一对应**，多了会有一个没被替换（打印出字面的 {}），少了参数用不上。

> 小提醒：课件图上写的是 `{}, {}` 两个占位符但只传了 id 一个参数，实际应该只写一个 `{}`——按规则来，别照抄这个小笔误。

## 五、配套配置
    <root level="info">
        <appender-ref ref="STDOUT" />
        <appender-ref ref="FILE" />
    </root>
- 级别配 info → `log.info` 能输出，`log.debug` 会被过滤掉
- 想看到上面那行删除日志，级别就得调到 **debug 或 info** 及以上

## 六、易错点
| 易错 | 说明 |
|---|---|
| 忘了加 @Slf4j 就用 log | 编译不过，找不到 log 变量 |
| 占位符个数与参数不匹配 | 打印出字面的 {} 或参数用不上 |
| 级别配成 warn 以上 | info 日志不输出，以为代码没执行 |
| 用 @Slf4j 又要手写 Logger | 变量名冲突，重复定义 |
| 用 System.out.println 混着写 | 不受级别控制、打不进日志文件 |

## 七、口诀
- **@Slf4j 一行代替样板代码，log 变量直接用**
- **log.info 用 {} 占位，别用 + 拼接**
- **占位符个数 = 参数个数，级别配上才看得见**
