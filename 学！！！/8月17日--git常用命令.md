git init  :  仓库初始化，使该文件夹变成git仓库.

.gitignore  :  忽略清单，是一个文件，用于声明哪些文件不受git管理

git clone <仓库地址>：将远程仓库完整地下载到本地。

git add ：添加文件

git rm ： 删除文件

## 日常修改

commit  :  提交，每次提交的文件都会被保存，可以任意退回被保存时的状态

commit -m  :  备忘信息

git diff  :  查看工作区与暂存区的差异（改了什么还没 add）。

## 撤销与回退（修补错误）

git reset --hard <Commit Hash>  : 强制回退。把仓库强制退会到某个历史提交。把Commit Hash给ai就可以回退

git revert <Commit Hash>  :  安全撤销。生成一个新的反向提交来抵消之前的提交，这样可以保持其他提交不变。一样可以用ai给它Commit Hash并说明就可以安全撤销。

## 分支管理（团队协作核心）

branch  :  分支。分支就是代码仓库里的“独立工作副本”，让多人并行开发互不干扰，最终再合并回主分支，确保主干始终稳定可靠。

git branch <新分支名>：创建新分支（但不切换）。

git branch -d <分支名>：删除本地分支（安全删除，会检查是否合并）。

git branch -D <分支名>：强制删除（未合并也删）。

git switch <分支名>：切换分支（Git 2.23+ 推荐，比 checkout 语义更清晰）。

git switch -c <新分支名>：创建并切换到新分支（等同于旧版的 `git checkout -b`）。

git merge <分支名>：将指定分支合并到当前分支。


## 远程仓库同步（拉取与推送）

git remote -v：查看当前关联的远程仓库地址。

git fetch：只下载远程仓库的最新提交到本地（不影响工作区，安全）。

git pull：下载并合并（实际等于 git fetch + git merge）。默认拉取当前上游分支。

    推荐：git pull --rebase（用变基方式拉取，避免产生多余的合并提交）。
与git clone 不一样，git pull是下载远程仓库文件合并原本文件，git clone 直接全下

git push：将本地提交上传到远程仓库。

    git push -u origin <分支名>：首次推送并建立本地分支与远程分支的关联（设置上游）。

    git push --force 或 -f：强制推送（危险！会覆盖远程历史，仅在个人分支或紧急修复时使用）。
