# 初始网络编程
## Q1：什么是网络编程？

> **计算机跟计算机之间通过网络进行数据传输。**&#8203;

| 拆解 | 含义 |
|---|---|
| 计算机 ↔ 计算机 | 通信双方是**两台机器**（不是两个线程） |
| 通过网络 | 数据走网卡、网线、路由器 |
| 数据传输 | 一端发、一端收 |

---

## Q2：常见软件架构有哪些？

> **CS / BS** （就这两个）

| 缩写 | 全称 | 中文 |
|---|---|---|
| **CS** | **C**lient / **S**erver | 客户端服务端模式 |
| **BS** | **B**rowser / **S**erver | 浏览器服务端模式 |

---

## Q3：CS / BS 的区别和优缺点

### 核心区别（一句话）

| 架构 | 关键差别 |
|---|---|
| **CS** | **需要开发客户端**（用户要装） |
| **BS** | **不需要开发客户端**（浏览器就是客户端） |

### 完整对比

| 对比维度 | **CS 架构** | **BS 架构** |
|---|---|---|
| **要不要开发客户端** | ✅ **要**（两端都开发） | ❌ **不要**（只开发服务端） |
| 用户体验 | ✅ 画面精美，体验好 | ⚠️ 应用过大时体验受影响 |
| 用户要不要下载 | ✅ 要下载安装 | ❌ 打开浏览器就能用 |
| 更新维护 | ❌ 每次都要用户重新下载 | ✅ **服务端改完，用户刷新就生效** |
| 开发成本 | 高（两套代码） | 低（一套服务端） |
| 跨平台 | ❌ 要分别开发 Windows / Mac / 手机版 | ✅ 有浏览器就行 |

### 适用场景（课件明确给了）

| 架构 | 适合什么 | 例子 |
|---|---|---|
| **CS** | **定制专业化的办公类软件** | **IDEA、网络游戏** |
| **BS** | **移动互联网应用、可以在任何地方随时访问的系统** | 淘宝、京东、OA 系统 |

> 💡 **判断口诀**：
> **要装、要画面、要性能 → CS**（游戏、专业工具）
> **免安装、随处访问 → BS**（网站、管理系统）

# 网络编程三要素

## 一、课件原文（背下来）

| 要素 | 定义 |
|---|---|
| **IP** | **设备**在网络中的**地址**，是唯一的标识 |
| **端口号** | **应用程序**在设备中**唯一**的标识 |
| **协议** | **数据在网络中传输的规则**，常见的协议有 **UDP、TCP、http、https、ftp** |

> ⚠️ 这三个定义里，**"唯一"和"设备/应用程序"的区分是考点**：
> **IP 标识"机器"，端口标识"程序"。**&#8203;

---

## 二、它们是"三级定位"关系（理解关键）

网络  
└── 设备（靠 IP 找到）  
└── 应用程序（靠端口号找到）

| 层级    | 靠什么定位   | 类比         |
| ----- | ------- | ---------- |
| 第 1 级 | 网络      | 全国快递网      |
| 第 2 级 | **IP**  | 找到**哪栋楼**  |
| 第 3 级 | **端口号** | 找到**哪个房间** |

> **只有 IP 没有端口** → 数据到了机器，但不知道交给哪个程序（就像知道楼号不知道门牌）。
> **只有端口没有 IP** → 根本不知道发给哪台机器。

💡 **`IP + 端口` 合起来，在 Java 里就叫 `Socket`（套接字）**&#8203; —— 后面 TCP/UDP 通信的核心对象就是它。

# IP 详解 —— IPv4 与 IPv6

## Q1：IP 的作用

> **设备在网络中的地址，是唯一的标识。**&#8203;

| 要点 | 说明 |
|---|---|
| 标识谁 | **设备**（不是程序，程序靠端口） |
| 作用 | 让数据在茫茫网络中**找到目标机器** |

---

## Q2：IPv4 有什么特点

| 特点 | 说明 |
|---|---|
| **目前的主流方案** | 现在绝大多数网络还在用它 |
| **最多只有 2^32 个 IP** | 32 位地址空间 |
| **目前已耗尽** ⚠️ | 早在 2019 年全球 IPv4 地址池就正式分配完了 |

**精确数字：**
2^32 = 4,294,967,296 ≈ 43 亿个


> 💡 **对比一下**：全球人口 80 亿，IPv4 地址才 43 亿 —— **连人手一个都做不到**，更别说手机、电脑、服务器、摄像头、智能手表了。

**写法：点分十进制**
192.168.1.1  
↑ ↑ ↑ ↑  
4 组，每组 0~255（正好 8 位 × 4 = 32 位）

---

## Q3：IPv6 有什么特点

| 特点 | 说明 |
|---|---|
| **为了解决 IPv4 不够用而出现的** | 诞生目的很明确 |
| **最多有 2^128 个 IP** | 128 位地址空间 |
| **可以为地球上的每一粒沙子都设定 IP** | 课件原文的形容 |

**数量级有多夸张？**
2^128 ≈ 3.4 × 10^38 个

> **是 IPv4 的 2^96 倍** —— 这个倍数比"IPv4 总数量"还要大得多得多。
> 真的够给每一粒沙子发一个，而且能用非常久。

**写法：冒分十六进制**

# IP 补充

## 1. IPv4 不够怎么办 → 局域网 IP（私有地址）

| | 说明 |
|---|---|
| 做法 | 一个局域网只占 1 个公网 IP，内部每台机器各分一个私有 IP |
| 出网 | 靠路由器做 NAT，把私有 IP 转成公网 IP 发出去 |
| 效果 | 全世界共用极少量公网 IP，硬撑住了 43 亿的缺口 |

私有地址段（补充，实际开发常见）：
  10.0.0.0     ~ 10.255.255.255
  172.16.0.0   ~ 172.31.255.255
  192.168.0.0  ~ 192.168.255.255   ← 家里路由器最常见

## 2. 特殊 IP：127.0.0.1

- 别名 **localhost / 回环地址**，永远指向本机
- 特点：数据**不走网卡、不出网**，自己发给自己
- 用途：本机调试服务（自己写的服务器，用 127.0.0.1 访问）

三个"自己"别搞混：

| IP | 含义 | 特点 |
|---|---|---|
| 127.0.0.1 | 永远是自己 | 换到哪台机器都不变 |
| 192.168.x.x | 局域网里的自己 | 换个网络就变 |
| 公网 IP | 全世界看到的自己 | 全球唯一 |

## 3. 两个 CMD 命令

| 命令 | 作用 | 常用写法 |
|---|---|---|
| `ipconfig` | 查看本机 IP 地址 | `ipconfig /all` 看全部网卡信息 |
| `ping` | 检查网络是否连通 | `ping www.baidu.com` |

- ping 通会显示往返耗时（ms），数值越小越快；显示"请求超时"就是不通
- `ping 127.0.0.1` 能通，说明本机 TCP/IP 协议栈正常

## 口诀
IPv4 不够用 → **局域网 IP + NAT 顶上**
**127.0.0.1 永远是自己**
**ipconfig 查自己，ping 测通不通**

# InetAddress 常用方法

## 三个方法

| 方法 | 返回 | 作用 |
|---|---|---|
| `static InetAddress getByName(String host)` | InetAddress 对象 | 拿到主机名/IP 对应的 IP 地址对象 |
| `String getHostName()` | 字符串 | 获取该 IP 对应的主机名 |
| `String getHostAddress()` | 字符串 | 返回文本形式的 IP 地址字符串 |

两个关键区别：
- **getByName 是静态方法** → 用类名调用：`InetAddress.getByName(...)`
- **返回类型不同** → 第一个给对象，后两个给字符串

## 参数 host 能给什么
- 可以给 **IP 字符串**：`"192.168.1.100"`
- 也可以给 **主机名/域名**：`"www.baidu.com"`、`"LAPTOP-XXXX"`
- 给了域名 → 内部做一次 DNS 解析；解析不了就抛 `UnknownHostException`

## 完整示例

```java
    public class Demo {
        public static void main(String[] args) throws UnknownHostException {
            InetAddress ip = InetAddress.getByName("www.baidu.com");

            System.out.println(ip);                   // 主机名/IP
            System.out.println(ip.getHostName());     // www.baidu.com
            System.out.println(ip.getHostAddress());  // 39.156.66.10
        }
    }
```

配套方法：`InetAddress.getLocalHost()` —— 直接拿本机的 InetAddress。

## 易错点
- `UnknownHostException` 是**编译时异常**，必须 `throws` 或 try-catch，不处理编译不过
- 直接打印 InetAddress 对象，输出格式是 `主机名/IP`（中间那个 `/` 是固定格式，不是路径）
- `getHostName()` 拿不到主机名时会**退而返回 IP 字符串**，不会报错

## 一句话记
**getByName 拿对象，getHostName 拿名字，getHostAddress 拿 IP 串**

# 端口号

## 定义
应用程序在设备中的**唯一标识**。
一句话理解：**IP 找到设备，端口找到设备上的哪个程序。**&#8203;

## 取值范围：0 ~ 65535

| 怎么来的 | 说明 |
|---|---|
| 2 个字节 | 16 位二进制 |
| 2¹⁶ | = 65536 个值 |
| 从 0 开始 | 所以是 0 ~ 65535，不是 1 ~ 65536 |

## 三段划分

| 区间 | 用途 | 我们怎么用 |
|---|---|---|
| 0 ~ 1023 | 知名网络服务/应用占用 | **不要碰** |
| 1024 ~ 49151 | 用户/注册端口 | **自己写代码用这段** |
| 49152 ~ 65535 | 动态/临时端口 | 系统随机分配，一般不管 |

## 常见知名端口（眼熟就行）

| 端口 | 服务 | 端口 | 服务 |
|---|---|---|---|
| 21 | FTP | 80 | HTTP |
| 22 | SSH | 443 | HTTPS |
| 25 | SMTP（发邮件） | 3306 | MySQL |
| 53 | DNS | 6379 | Redis |
| 8080 | Tomcat | 8848 | Nacos |

## 重点注意
**一个端口号只能被一个应用程序使用。**&#8203;

- 范围：**同一台设备内**唯一（A 机器用 8080，B 机器也能用 8080，互不影响）
- 程序启动时端口被占，直接报错：`BindException: Address already in use`
- 排查办法：`netstat -ano | findstr 端口号` 看是谁占了

## 一句话记
**2 字节 16 位，0~65535；1023 以内是官方地盘，1024 以上随便用，一个端口只能给一个程序。**&#8203;

# 协议 —— UDP vs TCP

## 定义
**网络通信协议** = 计算机网络中，连接和通信的规则。

## 对比表（背这张）

| | UDP | TCP |
|---|---|---|
| 全称 | User Datagram Protocol<br>用户数据报协议 | Transmission Control Protocol<br>传输控制协议 |
| 连接方式 | **面向无连接** | **面向连接** |
| 发之前 | 不确认，直接发 | 先握手，确认连接成功 |
| 速度 | 快 | 慢 |
| 大小 | 有上限，单包最多 **64K** | **无大小限制**（流式） |
| 安全性 | 不安全，易丢数据 | 安全，不丢数据 |
| 首部开销 | 8 字节（轻） | 20 字节（重） |

## 三个易错点
1. **64K 是单个数据报的上限**，不是"UDP 一共只能发 64K"——超过可以拆成多个包发
2. **"面向无连接" ≠ 不知道对方地址**，IP 和端口照样要知道，只是**不建立、不维护**连接，发完就完事
3.  **“TCP 无大小限制”** &#8203; 指它是字节流，多大文件都能传，但速度受带宽和重传影响，所以"慢"

## 怎么选

| 选 UDP | 选 TCP |
|---|---|
| 直播、视频通话、网游、DNS | 网页浏览、文件下载、发邮件 |
| 追求实时，丢一两帧无所谓 | 数据必须完整，一个字节都不能少 |

判断口诀：**丢了会不会出事？会 → TCP；不会 → UDP**

## 一句话记
**UDP 快但不可靠，TCP 可靠但慢。**&#8203;
"面向连接"问的就是一件事：**发之前，要不要先确认对方在不在？**

# UDP协议练习
## UDP 发送端（四步套路）

### 四步流程

| 步骤 | 做什么 | 用谁 |
|---|---|---|
| ① 建连接 | 创建"快递公司" | `DatagramSocket` |
| ② 打包 | 把数据 + 目标地址 + 目标端口 打包成"快递" | `DatagramPacket` |
| ③ 发送 | 把包裹扔出去 | `ds.send(dp)` |
| ④ 释放 | 关闭资源 | `ds.close()` |

### 两个对象的分工（重点）
- **DatagramSocket = 快递公司**：负责发/收的能力，本身不装数据
- **DatagramPacket = 快递包裹**：装数据 + 收件地址 + 收件端口

### 完整代码
```java
    public class SendDemo {
        public static void main(String[] args) throws IOException {
            // 1. 创建 DatagramSocket（快递公司）
            DatagramSocket ds = new DatagramSocket();

            // 2. 打包数据
            String str = "你好威啊！！！";
            byte[] bytes = str.getBytes();
            InetAddress address = InetAddress.getByName("127.0.0.1");
            int port = 10086;

            DatagramPacket dp = new DatagramPacket(bytes, bytes.length, address, port);

            // 3. 发送数据
            ds.send(dp);

            // 4. 释放资源
            ds.close();
        }
    }
```

### DatagramSocket 构造（发送端 / 接收端的区别）
- **空参 `new DatagramSocket()`**：从所有可用端口里**随机挑一个**
  - 发送端就用这个 —— 反正对方回复时看包里的来源地址
- **有参 `new DatagramSocket(端口号)`**：**绑定指定端口**
  - **接收端必须用这个** —— 不指定端口，别人不知道该往哪发

### 易错点
- `DatagramPacket` 发送用的构造是**四参数**，顺序别记错：
  **数据字节数组 → 长度 → 目标 InetAddress → 目标端口**
- 第二个参数必须写 `bytes.length`，不要手写数字（写大了会多发一堆空白字节）
- `port` 要和**接收端绑定的端口一致**，否则收不到
- `getBytes()` 按平台默认编码转字节数组，IDEA 默认 UTF-8，和接收端保持一致才不会乱码
- `new DatagramSocket()` 会抛 `SocketException`，`send()` 抛 `IOException`，通常直接 `throws IOException` 一起处理

### 一句话记
**Socket 是快递公司，Packet 是包裹；先建公司，再打包，然后 send，最后 close。**&#8203;

## UDP 接收端（四步套路）
### 完整代码
```java
    public class ReceiveDemo {
        public static void main(String[] args) throws IOException {
            // 1. 创建 DatagramSocket（快递公司）—— 必须绑定端口！
            DatagramSocket ds = new DatagramSocket(10086);

            // 2. 接收数据包
            byte[] bytes = new byte[1024];
            DatagramPacket dp = new DatagramPacket(bytes, bytes.length);
            
            //会阻塞，如果发送端没启动，会一直等
            ds.receive(dp);

            // 3. 解析数据包
            byte[] data = dp.getData();
            int len = dp.getLength();
            InetAddress address = dp.getAddress();
            int port = dp.getPort();

            System.out.println("接收到数据" + new String(data, 0, len));
            System.out.println("该数据是从" + address + "这台电脑中的" + port + "这个端口发出的");

            // 4. 释放资源
            ds.close();
        }
    }
```
### 发送端 vs 接收端（最容易混，重点背）

|           | 发送端                                   | 接收端                                              |
| --------- | ------------------------------------- | ------------------------------------------------ |
| Socket 构造 | `new DatagramSocket()` **空参**<br>随机端口 | `new DatagramSocket(10086)` **有参**<br>**必须绑定端口** |
| Packet 构造 | **四参**：数据 / 长度 / IP / 端口              | **双参**：空数组 / 长度                                  |
| 核心方法      | `send(dp)`                            | `receive(dp)`                                    |
| 阻塞        | 不阻塞                                   | **会阻塞等数据**                                       |

一句话：**发的人随便挑端口，收的人必须守在固定端口上。**&#8203;

### 接收端特有的三步

**第 2 步 · 准备容器**
- `byte[] bytes = new byte[1024]` —— 这是**接数据的空盒子**
- `new DatagramPacket(bytes, bytes.length)` —— **双参构造**，只告诉它盒子多大

**第 3 步 · 解析（拆快递）**&#8203;

| 方法 | 拿到什么 |
|---|---|
| `dp.getData()` | 装数据的那个字节数组 |
| `dp.getLength()` | 本次**实际**收到多少字节 |
| `dp.getAddress()` | 发送方的 IP 地址 |
| `dp.getPort()` | 发送方的端口号 |

**第 4 步**：`ds.close()`

### 易错点
- 一定要用 `dp.getLength()`，**不能写 `data.length`**
  - 数组固定 1024，写 `data.length` 会打印出一大串空白字符
- `new String(data, 0, len)` 是**三参数**：数组、起始下标、取多少个 —— 只取有效部分
- `receive(dp)` 是**阻塞方法**：没有数据就卡在那儿不动，程序不会往下走
- `getAddress()` 拿到的是**发送方**的地址，不是自己的

### 一句话记
**收件人必须先开门（绑定端口），准备空箱子，receive 等包裹，拆开用 get… 四件套，最后 close。**&#8203;
