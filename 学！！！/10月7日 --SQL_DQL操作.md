# DQL 开篇 —— 完整语法框架

## 一、完整语法（背下来，以后写查询都在这个框里拼）

    select   字段列表
    from     表名列表
    where    条件列表
    group by 分组字段列表
    having   分组后条件列表
    order by 排序字段列表
    limit    分页参数

## 二、五种查询（就是上面七行的组合）

| # | 查询 | 用到的部分 |
|---|---|---|
| 1 | **基本查询** | `select ... from ...` |
| 2 | **条件查询** | `where` |
| 3 | **分组查询** | `group by` |
| 4 | **排序查询** | `order by` |
| 5 | **分页查询** | `limit` |

**不是五种不同的语法，是同一个骨架逐层加零件。**&#8203;

## 三、书写顺序口诀
**select → from → where → group by → having → order by → limit**

（写的时候必须按这个顺序，写反了直接语法报错）

## 四、补充：实际执行顺序不一样（面试常问）

    from → where → group by → having → select → order by → limit

| 由此得出的结论 | 为什么 |
|---|---|
| `where` 里**不能用字段别名** | 别名是 `select` 阶段才起的，`where` 跑得更早 |
| `where` 里**不能用聚合函数** | 分组还没发生，`count()` 这些没有数据可算 |
| `having` 里**可以用别名和聚合函数** | 它在 `select` 之后、分组之后 |

**一句话：`where` 是"分组前筛行"，`having` 是"分组后筛组"。**&#8203;

## 五、一句话记
**`select 字段 from 表 where 条件 group by 分组 having 组条件 order by 排序 limit 分页`**
**先记住这七行，后面五张课件就是往每一行里填具体内容。**&#8203;

# DQL —— 基本查询

## 一、四种写法（背这张表）

| 写法 | 语法 |
|---|---|
| 查询**多个字段** | `select 字段1, 字段2, 字段3 from 表名;` |
| 查询**所有字段** | `select * from 表名;` |
| **设置别名** | `select 字段1 [as 别名1], 字段2 [as 别名2] from 表名;` |
| **去除重复记录** | `select distinct 字段列表 from 表名;` |

## 二、课件注意（原文）
**`*` 号代表查询所有字段，在实际开发中尽量少用（不直观、影响效率）。**&#8203;

| 为什么少用 `*` | 说明 |
|---|---|
| **不直观** | 看代码不知道这接口到底要哪几列；表加了一列，返回结果就悄悄变了 |
| **影响效率** | 多余字段要**多读磁盘、多走网络**；还可能让**索引覆盖**失效 |

所以正式项目里都是**把需要的字段一个个列出来**。

## 三、几个实用细节

**别名 `as` 可以省略：**

    select name as 姓名, age as 年龄 from tb_user;   -- 完整写法
    select name 姓名, age 年龄 from tb_user;         -- 省略 as，等价

**别名带空格要加引号：**

    select name as '用户 姓名' from tb_user;

**`distinct` 的位置：**

    select distinct gender from tb_user;            -- ✅ 去重
    select gender distinct from tb_user;            -- ❌ 位置错，语法报错

## 四、易错点

| # | 坑 |
|---|---|
| 1 | **`distinct` 去重的是"整行字段组合"**&#8203; —— `select distinct gender, age` 是"性别+年龄"的组合去重，不是单独去重性别 |
| 2 | **`distinct` 必须紧跟在 `select` 后面**，写在字段后面无效 |
| 3 | **`distinct` 后面跟多个字段时不能只想去重第一个** —— 想要单字段去重，就只 select 那一个字段 |
| 4 | **别名不能用在 `where` 里** —— 上一页讲过，`where` 比 `select` 先执行 |
| 5 | 中文别名建议加引号，避免编码/空格问题 |
| 6 | `select 1 + 1;` 这类不带 from 的查询也合法（MySQL 里可以用来做计算），但不是常规用法 |

## 五、一句话记
**`select 字段 [as 别名] from 表名;` —— 想全都要就用 `*`（但正式项目别用），想只留一份就用 `distinct`。**&#8203;
**别名 `as` 可省；`distinct` 必须紧跟 `select`，且是按"整行组合"去重。**&#8203;

# DQL —— 条件查询

## 一、语法

    select 字段列表 from 表名 where 条件列表 ;

## 二、四类运算符（对照上图）

### ① 比较运算

| 符号 | 含义 | 符号 | 含义 |
|---|---|---|---|
| `>` | 大于 | `>=` | 大于等于 |
| `<` | 小于 | `<=` | 小于等于 |
| `=` | 等于 | `<>` 或 `!=` | **不等于** |

### ② 范围判断

| 写法 | 含义 |
|---|---|
| `between ... and ...` | 在某个范围之内（**含最小、最大值**） |
| `in (...)` | 在 in 之后的列表中的值，**多选一** |

### ③ 模糊与空值

| 写法 | 含义 |
|---|---|
| `like 占位符` | 模糊匹配（`_` 匹配**单个**字符，`%` 匹配**任意个**字符） |
| `is null` | 是 null |

### ④ 逻辑组合

| 写法 | 含义 |
|---|---|
| `and` 或 `&&` | 并且（多个条件**同时**成立） |
| `or` 或 `\|\|` | 或者（多个条件**任意一个**成立） |
| `not` 或 `!` | 非，不是 |

## 三、四个重点用法

    -- 年龄大于 20 的
    select * from tb_user where age > 20;

    -- 年龄在 18 到 30 之间（含 18 和 30）
    select * from tb_user where age between 18 and 30;

    -- 年龄是 18、20、22 中的任意一个
    select * from tb_user where age in (18, 20, 22);

    -- 姓"张"的（% 任意个字符）
    select * from tb_user where name like '张%';

    -- 名字共 2 个字、姓张的（_ 一个字符）
    select * from tb_user where name like '张_';

    -- 第二个字是"天"的
    select * from tb_user where name like '_天%';

    -- 性别为空的
    select * from tb_user where gender is null;

## 四、`like` 的四种写法（重点理解）

| 写法 | 匹配什么 | 举例（name） |
|---|---|---|
| `like '张%'` | **以张开头** | 张三、张无忌 |
| `like '%张'` | **以张结尾** | 小张、老张 |
| `like '%张%'` | **包含张** | 张三、小张飞 |
| `like '_张%'` | **第二个字是张** | 小张飞 |

`%` 和 `_` 的区别一句话：**`%` 管"多少个字节"，`_` 管"就一个"。**&#8203;

## 五、易错点

| # | 坑 |
|---|---|
| 1 | **`between 18 and 30` 是闭区间**，含 18 和 30 两端（等价于 `>= 18 and <= 30`） |
| 2 | **`between` 小值必须写前面** —— 写成 `between 30 and 18` 查不到任何数据，且**不报错**（很难发现） |
| 3 | **`in` 是"多选一"**&#8203;，不是范围：`in (18, 20, 22)` 只匹配这三个值，中间的不算 |
| 4 | **判断 null 不能用 `=`** —— `where gender = null` **永远查不到**（NULL 参与比较结果是"未知"，不是真），必须 `is null` |
| 5 | **`and` 的优先级高于 `or`** —— `a or b and c` 会先算 `b and c`；混用时**一定加括号**明确意图 |
| 6 | **`like '%张%'` 用不上索引** —— 左模糊（`%` 开头）会让索引失效，数据量大时很慢 |
| 7 | 字符串条件**必须加引号**：`where name = '张三'`，漏引号会当成列名 |
| 8 | `!=` 和 `<>` 等价，团队里统一用一种就行（`<>` 是标准 SQL 写法） |
| 9 | `not in (...)` 里**只要有一个 null，整个条件就查不出结果**，这是经典陷阱 |

## 六、一句话记
**`where` 后面就是一堆条件，运算符分四类：比较、范围、模糊空值、逻辑组合。**&#8203;
**`between` 含两端且小在前，`in` 是多选一，`like` 里 `%` 管多个 `_` 管一个，判空只用 `is null`。**&#8203;

# DQL —— 分组查询（聚合函数）

## 一、定义（课件原文）
**聚合函数：将一列数据作为一个整体，进行纵向计算。**&#8203;

关键词是**纵向** —— 它不是逐行处理，而是**把一整列"捏"成一个值**。
（对比：`where` 是**横向**筛选行，聚合是**纵向**压缩列）

## 二、五个聚合函数

| 函数 | 功能 |
|---|---|
| `count` | 统计数量 |
| `max` | 最大值 |
| `min` | 最小值 |
| `avg` | 平均值 |
| `sum` | 求和 |

## 三、基本用法

    -- 统计员工总数
    select count(*) from emp;

    -- 统计平均工资
    select avg(salary) from emp;

    -- 一次查多个聚合值
    select count(*), max(salary), min(salary), avg(salary), sum(salary) from emp;

**注意：聚合函数是对"列"算的，所以必须写 `函数名(字段名)`，不能只写函数名。**&#8203;

## 四、课件两条注意（核心）

### 注意 1：null 值不参与所有聚合函数的运算

假设 salary 是 `8600 / null / 9200`：

| 写法 | 结果 | 为什么 |
|---|---|---|
| `count(*)` | **3** | 数的是行数，null 也算一行 |
| `count(salary)` | **2** | **跳过 null 那一行** |
| `avg(salary)` | **(8600+9200)/2 = 8900** | 分母是"非 null 的个数"，不是 3 |
| `sum(salary)` | **17800** | null 不参与相加（当成不存在） |

👉 **最容易踩的坑：`avg` 的分母会自动变小** —— 统计出来的平均值可能偏高或偏低，你还不容易发现。

### 注意 2：count 的三种写法

| 写法 | 统计什么 | 推荐 |
|---|---|---|
| `count(*)` | **所有行**（包括有 null 的行） | ✅ **推荐** |
| `count(字段)` | 该字段**非 null** 的行数 | 需要"只数有值的"时用 |
| `count(常量)`（如 `count(1)`） | 所有行 | 效果同上，写法略随意 |

InnoDB 对 `count(*)` 有专门优化（自动挑最小的索引树来数），性能最好。

## 五、易错点

| # | 坑 |
|---|---|
| 1 | **`avg` / `sum` 里混了 null 时结果和预期不符** —— 想按总行数算平均，得先把 null 处理掉：`avg(ifnull(salary, 0))` |
| 2 | **`count(字段)` 和 `count(*)` 结果可能不同** —— 一个数"非空值"，一个数"行" |
| 3 | **`max` / `min` 也能用于字符串和日期** —— 比如 `max(name)` 按字典序，`max(entrydate)` 拿最晚日期 |
| 4 | **聚合函数不能直接写在 `where` 里** —— `where count(*) > 3` 报错（分组还没发生），要用 `having` |
| 5 | **不分组时，聚合函数会作用在整张表上** —— `select avg(salary) from emp;` 得到的是全员平均 |
| 6 | 聚合函数要写在 `select` 后面（或 `having` 里），不是 `where` 里 |

## 六、一句话记
**聚合函数 = 把一列"竖着"算成一个值：`count` 数、`max` 大、`min` 小、`avg` 平、`sum` 和。**&#8203;
**null 不参与运算 —— 所以 `count(字段)` 会漏，`avg` 的分母会变小。数行数就用 `count(*)`。**&#8203;

# DQL —— 分组查询（group by / having）

## 一、语法

    select 字段列表 from 表名 [ where 条件列表 ]
    group by 分组字段名 [ having 分组后过滤条件 ] ;

## 二、`where` 与 `having` 的区别（课件原文两条，必考）

| # | 区别 | 说明 |
|---|---|---|
| 1 | **执行时机不同** | `where` 是**分组之前**过滤，**不满足 where 条件的行不参与分组**；<br>`having` 是**分组之后**对结果过滤 |
| 2 | **判断条件不同** | `where` **不能**对聚合函数进行判断；`having` **可以** |

**一句话：`where` 筛的是"行"，`having` 筛的是"组"。**&#8203;

## 三、课件两条注意（原文）

| # | 注意 |
|---|---|
| 1 | **分组之后，查询的字段一般为聚合函数和分组字段，查询其他字段无任何意义** |
| 2 | **执行顺序：`where` > 聚合函数 > `having`** |

第 1 条为什么？—— 分组后一组只剩"一行"了，你 `select name` 到底该显示组里哪个人的名字？**没有答案，所以无意义。**&#8203;

## 四、常用写法

    -- 1. 按性别分组，统计每组人数
    select gender, count(*) from emp group by gender;

    -- 2. 按性别分组，统计每组的平均年龄
    select gender, avg(age) from emp group by gender;

    -- 3. where + group by：先筛行，再分组
    select gender, count(*) from emp where age > 20 group by gender;

    -- 4. having：分组后再筛（能带聚合函数）
    select gender, avg(age) from emp group by gender having avg(age) > 20;

    -- 5. where + group by + having 一起用
    select gender, count(*) from emp
    where age > 20
    group by gender
    having count(*) > 3;

第 5 条读法：**先把 20 岁以下的剔掉（行），再按性别分组，最后只留人数超过 3 的组。**&#8203;

## 五、易错点

| # | 坑 |
|---|---|
| 1 | **`where` 里写聚合函数** → 报错（分组还没发生），只能写 `having` |
| 2 | **`select` 里写非分组字段** → MySQL 8 默认开启 `ONLY_FULL_GROUP_BY`，直接报错；即使不报错，值也是**随机取组内某一行的**，不可信 |
| 3 | **顺序写反** → `group by` 必须在 `where` **之后**；整体顺序是 `where → group by → having → order by → limit` |
| 4 | **`having` 里用别名** → MySQL 支持，但 `where` 里**不支持**（别名是 select 阶段才有的） |
| 5 | **分组的字段有 null** → null 会**自成一组**，统计时容易多出一组"未知值" |
| 6 | **不写 `group by` 只用聚合函数** → 等价于"整张表分一组"，结果只有一行 |
| 7 | **`having` 能放前面就用 `where`** → 能用 `where` 过滤的**优先用 `where`**，因为它在分组前执行、**参与分组的数据更少、效率更高** |

## 六、一句话记
**`group by` 按某列把行"叠成几摞"，聚合函数对每摞纵向算一次。**&#8203;
**`where` 在分组前筛行（不能带聚合），`having` 在分组后筛组（能带聚合）—— 顺序是 `where` → 聚合 → `having`。**&#8203;

# DQL —— 排序查询（order by）

## 一、语法

    select 字段列表 from 表名
    [ where 条件列表 ]
    [ group by 分组字段名 having 分组后过滤条件 ]
    order by 排序字段 排序方式 ;

**`order by` 是 `select` 语句里"倒数第二段"**&#8203; —— 后面只剩 `limit`。

## 二、排序方式

| 方式 | 关键字 | 说明 |
|---|---|---|
| 升序 | `asc` | **默认值，可以不写** |
| 降序 | `desc` | 从大到小 |

    select * from emp order by age asc;    -- 年龄升序（小 → 大）
    select * from emp order by age;        -- 不写 = asc，效果一样
    select * from emp order by age desc;   -- 年龄降序（大 → 小）

## 三、课件注意（原文）
**如果是多字段排序，当第一个字段值相同时，才会根据第二个字段进行排序。**&#8203;

    -- 先按年龄降序，年龄相同的再按入职时间升序
    select * from emp order by age desc, entrydate asc;

**读法：年龄大的排前面；两个人年龄一样时，才用第二个字段（入职时间）来分先后。**&#8203;

⚠️ **每个字段各自带排序方式** —— `order by age desc, entrydate asc`；
写 `order by age, entrydate desc` 意思是"年龄升序 + 入职时间降序"，**和你想的不一样**。

## 四、三个实用写法

    -- 1. 按别名排序（order by 在 select 之后执行，所以别名可用）
    select name, age as 年龄 from emp order by 年龄 desc;

    -- 2. 按表达式排序
    select name, salary * 12 from emp order by salary * 12 desc;

    -- 3. 分组后按聚合结果排序（很常用）
    select gender, avg(age) from emp group by gender order by avg(age) desc;

## 五、易错点

| # | 坑 |
|---|---|
| 1 | **`order by` 不能写在 `where` 前面** —— 顺序固定：`where` → `group by` → `having` → `order by` → `limit` |
| 2 | **多字段排序时忘了给每个字段写排序方式** —— 不写就是默认升序，容易和意图不符 |
| 3 | **`where` 里不能用别名，`order by` 里可以** —— 因为执行顺序不同（这也是 `order by` 唯一"特殊"的地方） |
| 4 | **null 的排序位置** —— MySQL 里 null 视为**最小**，`asc` 时排最前，`desc` 时排最后（业务上常需要排除 null） |
| 5 | **排序会消耗性能** —— 没索引的字段排序会走"文件排序"，数据量大时很慢；排的字段最好有索引 |
| 6 | **只想拿前几条时记得配 `limit`** —— `order by` 排完是全部数据，不是只给一条 |
| 7 | 字符串排序按**字符集/字典序**（不是拼音），中文排序结果可能和直觉不同 |

## 六、一句话记
**`order by 字段 asc|desc` —— asc 是默认，可以不写。**&#8203;
**多字段排序：先按第一个排，第一个值相同时才看第二个；每个字段都要写自己的排序方式。**&#8203;
**它在 `select` 之后执行，所以能用别名；`where` 在它前面，所以不能。**&#8203;

# DQL —— 分页查询（limit）

## 一、语法（到这儿，DQL 骨架就拼完整了）

    select 字段 from 表名
    [ where 条件 ]
    [ group by 分组字段名 having 过滤条件 ]
    [ order by 排序字段 ]
    limit 起始索引, 查询记录数 ;

完整顺序：**select → from → where → group by → having → order by → limit**

## 二、课件三条说明

| # | 说明 |
|---|---|
| 1 | **起始索引从 0 开始** |
| 2 | **分页查询是数据库的方言**，不同数据库有不同实现，**MySQL 中是 `LIMIT`** |
| 3 | 如果**起始索引为 0，可以省略**，直接简写为 `limit 10` |

### 第 2 条"方言"是什么意思
SQL 有统一标准，但**分页写法各数据库不一样**：

| 数据库 | 分页写法 |
|---|---|
| **MySQL** | `limit 起始索引, 条数` |
| Oracle | 用 `rownum` 套子查询 |
| SQL Server | `offset ... rows fetch next ... rows only` |

所以换数据库时，分页语句要改 —— 这也是 MyBatis-Plus 这类框架帮你屏蔽掉的事。

## 三、核心公式（必须记）

    起始索引 = （页码 − 1） × 每页条数

对照上图（每页 10 条）：

| 页码 | 起始索引 | 写法 |
|---|---|---|
| 第 1 页 | (1−1)×10 = **0** | `limit 0, 10` 或简写 `limit 10` |
| 第 2 页 | (2−1)×10 = **10** | `limit 10, 10` |
| 第 3 页 | (3−1)×10 = **20** | `limit 20, 10` |
| 第 n 页 | (n−1)×10 | `limit (n-1)*10, 10` |

**总页数 = ⌈总条数 ÷ 每页条数⌉**（向上取整）
例：63 条、10 条/页 → 6.3 → **共 7 页**，第 7 页只有 **3 条**。

## 四、常用写法

    -- 每页 10 条，取第 1 页
    select * from emp limit 10;

    -- 每页 10 条，取第 2 页
    select * from emp limit 10, 10;

    -- 分页配合排序（标准做法）
    select * from emp order by entrydate desc limit 20, 10;

    -- 另一种写法：limit 条数 offset 起始索引（等价）
    select * from emp limit 10 offset 20;

## 五、易错点

| # | 坑 |
|---|---|
| 1 | **起始索引从 0 开始，不是 1** —— 想拿第一条却写 `limit 1, 10`，会把第 1 条**跳过** |
| 2 | **分页不写 `order by` 顺序就不确定** —— 数据库不保证返回顺序，翻页时可能出现**同一条数据在两页里重复出现** |
| 3 | **两个参数的顺序是"起始索引, 条数"**&#8203; —— 不是"页码, 条数"，写反了数据全乱 |
| 4 | **省略起始索引只在第 1 页成立** —— 第 2 页开始必须写 `limit 10, 10`，不能只写 `limit 10` |
| 5 | **最后一页可能不足每页条数** —— 属于正常现象，前端要能处理 |
| 6 | **起始索引算错是最常见的分页 bug** —— 前端传的是"页码"，后端必须自己换算成起始索引 |
| 7 | 数据量大时不要用**超大 offset**（如 `limit 1000000, 10`）—— 会先扫描再丢弃，很慢，改用"上一页最后一条的 id"做游标分页 |

## 六、一句话记
**`limit 起始索引, 查询记录数` —— 起始索引从 0 开始，第一页可省略。**&#8203;
**起始索引 = （页码 − 1）× 每页条数；总页数 = 总条数 ÷ 每页条数向上取整。**&#8203;
**分页必须配 `order by`，否则翻页会乱。**&#8203;
