# 员工信息统计SQL· CASE 函数统计各职位人数

## 一、要做什么

统计页面要画「职位分布」的图表，需要的数据是：

| 职位（中文） | 人数 |
|---|---|
| 班主任 | ? |
| 讲师 | ? |
| 学工主管 | ? |
| 教研主管 | ? |
| 咨询师 | ? |

问题在于：`emp` 表里 `job` 存的是**数字**，不是中文。

图右上角的标注就是这张对照表：

| job | 职位 |
|---|---|
| 1 | 班主任 |
| 2 | 讲师 |
| 3 | 学工主管 |
| 4 | 教研主管 |
| 5 | 咨询师 |

所以这条 SQL 要干两件事：**① 把数字翻成中文（CASE）② 按职位分组数人数（group by + count）**&#8203;

## 二、CASE 函数的完整语法（图第 11 行注释原文）

    -- case函数: case when 条件表达式1 then result1 when 条件表达式2 then result2 .... else ... end

拆开看五个部件：

| 部件 | 作用 |
|---|---|
| `case` | 开始 |
| `when 条件 then 结果` | 一对一对地判断，条件成立就返回对应结果 |
| `else 结果` | 所有 when 都不成立时返回什么（**可选，但强烈建议写**） |
| `end` | 结束（**必须有**） |

## 三、两种写法（本图核心）

### 写法一：简写（图上半部分，红框那段）

    select
        (case job when 1 then '班主任'
                  when 2 then '讲师'
                  when 3 then '学工主管'
                  when 4 then '教研主管'
                  when 5 then '咨询师'
                  else '其他' end) pos,
        count(*) num
    from emp group by job order by num ;

- 特点：**`job` 只在 `case` 后面写一次**，每个 `when` 后面只跟一个「值」
- 语义：拿 `job` 的值去和 1、2、3、4、5 逐个**等于比较**

### 写法二：完整（图下半部分）

    select
        (case when job=1 then '班主任'
              when job=2 then '讲师'
              when job=3 then '学工主管'
              when job=4 then '教研主管'
              when job=5 then '咨询师'
              else '其他' end) pos,
        count(*) num
    from emp group by job order by num ;

- 特点：**每个 `when` 后面都写完整的条件表达式**，`job = N` 重复了五次
- 语义：每个条件单独判断，成立就返回

### 两者对照

| | 简写 `case 表达式 when 值 then` | 完整 `case when 条件 then` |
|---|---|---|
| 判断方式 | **只能等值**（= ） | **任意条件**（>、<、between、and、or、is null…） |
| 代码量 | 少（字段只写一次） | 多（每个 when 重复写字段） |
| 适合 | 按数字/枚举翻译成文字 | 分段统计（如按薪资区间、年龄段分组） |
| 结果 | 完全一样 | 完全一样 |

**只要需要"范围判断"，就一定得用完整形式**，例如按年龄段统计：

    case when salary < 5000 then '低'
         when salary between 5000 and 10000 then '中'
         else '高' end

## 四、整条 SQL 逐句拆解

| 片段 | 作用 | 说明 |
|---|---|---|
| `(case ... end) pos` | 把 job 数字翻成中文，**别名 pos** | 括号包住整个 case，`pos` 是给图表 x 轴用的名字 |
| `count(*) num` | 数每组的行数，**别名 num** | `num` 给图表 y 轴用（列名不能直接叫 count） |
| `from emp` | 数据来源 | 只查员工表 |
| `group by job` | 按 **job（原始字段）**&#8203; 分组 | 数字分组，一组一个职位 |
| `order by num` | 按人数排序 | **order by 可以用 select 的别名** |

### 为什么要用 count(*) 而不是 count(字段)

- `count(*)`：数行数，包含 null 行
- `count(字段)`：**跳过该字段为 null 的行**
- 统计"这个职位有多少人"应该用 `count(*)`

## 五、结果长什么样

    +----------+------+
    | pos      | num  |
    +----------+------+
    | 讲师     |  13  |
    | 班主任   |   8  |
    | 咨询师   |   6  |
    | 教研主管 |   2  |
    | 学工主管 |   1  |
    | 其他     |   1  |
    +----------+------+

（具体数字随数据变化，这里是示意）

- 前端拿到结果后，直接 `pos` 当横轴、`num` 当纵轴画饼图/柱状图
- 所有 num 相加 = 员工总数（这也是自检点）

## 六、易错点

| 问题 | 后果 |
|---|---|
| **忘了 `else`** | 没有匹配值时返回 **NULL**，图表上出现一个空标签的柱子 |
| 忘了 `end` | SQL 语法错误 |
| `then` 后面的字符串不加单引号 | 被当成列名，报 unknown column |
| 在 `when` 之间加逗号 | 语法错误（CASE 的 when 之间**不加逗号**，和 `<foreach>` 的 `separator` 完全不同） |
| `group by pos`（用别名） | MySQL 里能跑，但标准 SQL 不支持，**规范写法是按原字段 `group by job`** |
| `where` 里用 `num` 这种别名 | **报错**，where 执行在 select 之前，拿不到别名 |
| `job` 是数字却写成 `when '1'` | 靠隐式转换能跑，但索引失效、语义不清 |
| 漏了 `count(*)` 的别名 | 列名变成 `count(*)`，前端取值麻烦 |
| 用 `count(字段)` 统计 | 该字段为 null 的行被漏掉，总数偏少 |

## 七、口诀

> **case when 条件 then 结果 … else 结果 end**
> **简写：case 字段 when 值，只能等值；完整：case when 条件，能写范围**
> **case 翻中文、count(*) 数人、group by 原字段、order by 别名**
> **else 别省，不然出现 NULL 标签**

# 员工信息统计 · 职位统计（分析 + 完整实现）

## 一、需求：给前端图表供两个数组

「员工职位统计」是柱状图：**横轴职位名，纵轴人数**。ECharts 要的数据形状是：

    xAxis.data = ['班主任', '讲师', '咨询师', ...]     // 职位列表
    series.data = [8, 13, 6, ...]                     // 对应人数

**两个数组的下标必须一一对应**：第 1 个职位配第 1 个数。

## 二、核心痛点：SQL 给的形状和前端要的不一样

| | 形状 | 例子 |
|---|---|---|
| **SQL 查出来** | **一行一条记录** | pos=班主任, num=8 / pos=讲师, num=13 |
| **图表要的** | **一列一个数组** | jobList=[班主任,讲师] / dataList=[8,13] |

把"行"变成"列"，叫**行列转换**。这个转换放在 **Service** 里做。

## 三、JobOption（承载两个数组）

    @Data
    @NoArgsConstructor
    @AllArgsConstructor
    public class JobOption {
        private List jobList;   // 职位列表（建议写 List<String>）
        private List dataList;  // 人数列表（建议写 List<Object>）
    }

- 封装成一个类，是为了两个 List **一起传、顺序对齐**
- 三个注解：`@Data`（getter/setter）、`@NoArgsConstructor`、`@AllArgsConstructor`（`new JobOption(jobList, dataList)` 靠它）
- 课件写的是裸 `List`，你实际写建议加泛型，少一次强转

## 四、三层职责

    Chrome → Controller → Service → Mapper → MySQL

| 层 | 职责 |
|---|---|
| **Controller** | ① 接收请求 ② 调用 Service 方法 ③ 响应结果 |
| **Service** | ① 调用 mapper 获取统计数据 ② **解析数据封装统计结果（JobOption）**&#8203; |
| **Mapper** | 执行 SQL |

⚠️ **这套类放在 `Report` 模块下**：`ReportController` / `ReportService` / `ReportServiceImpl` / `ReportMapper`。
统计属于报表业务，不塞进 `EmpController`——这是模块划分的常识，别搞错。

## 五、完整代码（四段，可直接抄）

### ① ReportController

    @Slf4j
    @RestController
    @RequestMapping("/report")
    public class ReportController {

        @Autowired
        private ReportService reportService;

        @GetMapping("/empJobData")
        public Result getEmpJobData() {
            log.info("统计各个职位的员工人数");
            JobOption jobOption = reportService.getEmpJobData();
            return Result.success(jobOption);
        }
    }

- 类上 `@RequestMapping("/report")` + 方法上 `/empJobData` → 完整路径 **`GET /report/empJobData`**
- Controller 极简：没有参数，只做转发

### ② ReportService 接口

    public interface ReportService {
        JobOption getEmpJobData();
    }

### ③ ReportServiceImpl

    @Service
    public class ReportServiceImpl implements ReportService {

        @Autowired
        private ReportMapper empMapper;

        @Override
        public JobOption getEmpJobData() {
            // 1. 调用 Mapper 获取职位统计数据
            List<Map<String, Object>> list = empMapper.countEmpJobData();

            // 2. 解析数据：把"行"拆成两个"列"
            List<Object> jobList = list.stream().map(dataMap -> dataMap.get("pos")).toList();
            List<Object> dataList = list.stream().map(dataMap -> dataMap.get("num")).toList();

            // 3. 封装统计结果
            return new JobOption(jobList, dataList);
        }
    }

### ④ ReportMapper（接口 + XML）

    @Mapper
    public interface ReportMapper {
        List<Map<String, Object>> countEmpJobData();
    }

    <select id="countEmpJobData" resultType="java.util.Map">
        select
            (case when job = 1 then '班主任'
                  when job = 2 then '讲师'
                  when job = 3 then '学工主管'
                  when job = 4 then '教研主管'
                  when job = 5 then '咨询师'
                  else '其他' end) as pos,
            count(*) as num
        from emp
        group by job order by num
    </select>

## 六、逐段拆解

### ① `resultType="java.util.Map"` 是什么意思

> 把**每一条查询结果**封装成一个 Map，key 是**列名 / 别名**，整批结果就是 `List<Map<String, Object>>`。

    结果集2行 → [ {pos=班主任, num=8}, {pos=讲师, num=13} ]

- 因为 `pos` 和 `num` **都不是 `Emp` 的属性**，所以不能用 `resultType="com.itheima.pojo.Emp"`（那样映射不上，全是 null）
- **必须给 `count(*)` 起别名 `num`**，否则 Map 的 key 会变成 `count(*)` 这个字面量
- `count(*)` 返回的类型是 **Long**（不是 Integer），`get("num")` 拿到的是 Long 对象

### ② 那条 SQL 在算什么

| 片段 | 作用 |
|---|---|
| `case when job = 1 then '班主任' ... else '其他' end as pos` | 把数字 `job` 翻成中文，别名 `pos` |
| `count(*) as num` | 每组行数，别名 `num` |
| `group by job` | 按原始字段分组（**不是按别名 pos**） |
| `order by num` | 按人数排序（**order by 可以用别名**，where 不行） |

`job` 的数字含义：1 班主任、2 讲师、3 学工主管、4 教研主管、5 咨询师。

### ③ Stream 那两行在干什么

    list.stream()                       // 把 List 变成流
        .map(dataMap -> dataMap.get("pos"))   // 每个 Map 取出 pos 这一列
        .toList();                      // 收回成 List

- 第一行取 `pos` 列 → `jobList`
- 第二行取 `num` 列 → `dataList`
- 读法就是"**把这一列抽出来**"，比写 for 循环直观

### ④ Stream 写法 vs for 循环写法（结果一样）

    // 课件写法：遍历两遍
    List<Object> jobList  = list.stream().map(m -> m.get("pos")).toList();
    List<Object> dataList = list.stream().map(m -> m.get("num")).toList();

    // 等价写法：只遍历一遍
    List<String> jobList = new ArrayList<>();
    List<Object> dataList = new ArrayList<>();
    for (Map<String, Object> m : list) {
        jobList.add((String) m.get("pos"));
        dataList.add(m.get("num"));
    }

| | Stream | for 循环 |
|---|---|---|
| 遍历次数 | **2 次** | 1 次 |
| 可读性 | 好（声明式） | 一般 |
| 返回值 | `.toList()` 得到**不可变集合** | 可变 ArrayList |

- 统计数据只有几行，性能差别忽略不计
- 如果后面还要往这个 List 里 add，用 `collect(Collectors.toList())` 代替 `.toList()`

## 七、易错点

| 问题 | 后果 |
|---|---|
| Mapper 用 `resultType="com.itheima.pojo.Emp"` | pos / num 映射不上，值全 null |
| `count(*)` 没起别名 | Map 的 key 变成 `count(*)`，`get("num")` 拿到 null |
| `get("POS")` 大小写写错 | 值为 null，图表空白 |
| 两个 List 只取了一列 | 长度不一致或数据错位，图表乱 |
| 把 `get("num")` 强转成 Integer | count 返回 Long，抛 `ClassCastException` |
| 类上的 `@RequestMapping("/report")` 漏了 | 前端按 `/report/empJobData` 请求直接 404 |
| Service 返回 `List<Map>` 而不是 JobOption | 前端结构对不上，取不到 jobList |
| JobOption 少了 `@AllArgsConstructor` | `new JobOption(a, b)` 编译不过 |
| 忘了 `@Data` | 序列化拿不到 getter，返回的 JSON 是空的 |
| 建类建到 Emp 模块里 | 能跑，但工程结构混乱（应独立 Report 模块） |

## 八、口诀

> **图表要两个平行数组，SQL 只给一行一行 → Service 做行列转换**
> **`resultType="java.util.Map"`：一行一个 Map，key 就是列别名**
> **Stream 两行：`.stream().map(m -> m.get("pos")).toList()`**
> **Controller 只转发，SQL 里 case 翻中文、count 数人、group by 原字段**

# 员工信息统计 · 性别统计（饼图）

## 一、需求

页面上是个**饼图**，统计男女员工各多少人。

对比一下两种图表要的数据，就能理解这页为什么和上一页不一样：

|                | 职位统计（柱状图）         | 性别统计（饼图）             |     |
| -------------- | ----------------- | -------------------- | --- |
| 图表             | 柱状图               | **饼图**               |     |
| 前端要的数据         | 两个平行数组（x 轴 + y 轴） | **一个对象数组**           |     |
| 需要 JobOption 吗 | **需要**            | **不需要**              |     |
| Service 干了什么   | 遍历解析、行列转换         | **一行透传**             |     |
| SQL 的别名        | `pos` / `num`     | **`name` / `value`** |     |

**核心认知：要不要封装类，取决于前端图表要什么格式，不是固定的套路。**&#8203;

## 二、ECharts 饼图要的样子

    series: [{
      type: 'pie',
      data: [
        { "name": "男", "value": 18 },
        { "name": "女", "value": 15 }
      ]
    }]

而 `List<Map<String,Object>>` 序列化出来的 JSON 正好长这样：

    [
      { "name": "男", "value": 18 },
      { "name": "女", "value": 15 }
    ]

**所以完全不用加工，Mapper 查出来直接返回给前端就行。**&#8203;

## 三、完整代码（四段，可直接抄）

### ① ReportController

    @GetMapping("/empGenderData")
    public Result getEmpGenderData() {
        log.info("统计员工性别信息");
        List<Map> genderList = reportService.getEmpGenderData();
        return Result.success(genderList);
    }

- 路径 `/empGenderData`，配合类上的 `@RequestMapping("/report")` → **`GET /report/empGenderData`**
- 返回值直接是 `List<Map>`，**没有 JobOption**
- `Result.success(genderList)` 把 List 塞进 data 字段

### ② ReportServiceImpl（只有一行）

    @Override
    public List<Map> getEmpGenderData() {
        return empMapper.countEmpGenderData();
    }

- **这就是"透传"**&#8203;：不做任何解析、不拆 List、不封装，直接 return
- 对比职位统计的 Service：那边有 2 行 stream 做行列转换，这边一行搞定

### ③ EmpMapper 接口

    List<Map> countEmpGenderData();

- 返回 `List<Map>`，因为 `name` / `value` 不是任何实体类的属性
- ⚠️ 课件这里的接口放在 **EmpMapper** 里（图左下角标题），而 Controller / Service 都在 `Report` 模块下 —— 略显不一致，**实际项目建议统一放 `ReportMapper`**，模块职责更清晰

### ④ EmpMapper.xml

    <!-- 统计员工的性别信息 -->
    <select id="countEmpGenderData" resultType="java.util.Map">
        select
            if(gender = 1, '男', '女') as name,
            count(*) as value
        from emp
        group by gender
    </select>

- 还是 `resultType="java.util.Map"` → 每行一个 Map，key 就是别名 `name` / `value`
- ⚠️ 课件笔误：图上 `count(*)` 写成了 **`ccount(*)`**，抄的时候注意
- 图上的 SQL 末尾带了个分号 `;`。这里没有 PageHelper 拼 limit，能正常执行，但**统一不写分号**更保险

## 四、`if()` 函数（本页新知识点）

### 语法

    if(条件表达式, 条件为 true 时的值, 条件为 false 时的值)

相当于 Java 里的三目运算符 `条件 ? 值1 : 值2`。

    if(gender = 1, '男', '女')

意思就是：`gender` 等于 1 就是"男"，否则"女"。

### 和 CASE 的对比

| | `if()` | `case when` |
|---|---|---|
| 分支数 | **只能两个**（真 / 假） | 任意多个 |
| 写法 | `if(条件, 值1, 值2)` | `case when 条件1 then 值1 ... else 值 end` |
| 适合 | **男女、启用/停用、是否** 这类二元判断 | 职位（5 种）、薪资区间等多元判断 |
| 是否 MySQL 专有 | 是（MySQL 特有函数） | 否（标准 SQL，各库通用） |

- 上一节职位统计有 5 种职位 → **只能用 CASE**
- 这一节性别只有 2 种 → **用 `if()` 更简洁**

### ⚠️ `if()` 的隐患

`if(gender = 1, '男', '女')` 会把**所有不是 1 的**（包括 2、null、脏数据）都算成"女"。

如果数据里可能有不规范的值，用 CASE 更稳：

    case when gender = 1 then '男'
         when gender = 2 then '女'
         else '未知' end as name

## 五、这条 SQL 逐句拆

| 片段 | 作用 |
|---|---|
| `if(gender = 1, '男', '女') as name` | 把 1/2 翻成中文，**别名必须是 name** |
| `count(*) as value` | 数每组人数，**别名必须是 value** |
| `from emp` | 数据来源 |
| `group by gender` | 按性别分成两组 |

生成的 JSON：

    {
      "code": 1,
      "msg": "success",
      "data": [
        { "name": "男", "value": 18 },
        { "name": "女", "value": 15 }
      ]
    }

- 两个 value 相加 = 员工总数，可以作为自检手段

## 六、易错点

| 问题 | 后果 |
|---|---|
| **别名写成 `pos` / `num`** | 前端饼图取不到 `name` / `value`，图直接空白 |
| `count(*)` 忘起别名 | Map 的 key 变成 `count(*)` 字面量，取不到 |
| 用 `if()` 处理三种以上情况 | 只能写两个分支，多的没法写，必须换 CASE |
| `if()` 没考虑 null / 脏数据 | 非 1 的全算成"女"，统计偏差 |
| Service 里又去拆 List、包 JobOption | 多余，前端结构反而对不上 |
| Service 返回 `Result` 而不是 `List<Map>` | 返回类型错，`Result` 只应该在 Controller 层包 |
| 方法名的 id 与 XML 不一致 | `Invalid bound statement (not found)` |
| `List<Map>` 写成 `List<HashMap>` | 泛型太具体，MyBatis 映射类型不匹配 |
| Controller 漏写 `@RequestMapping("/report")` | 前端按 `/report/empGenderData` 请求 404 |

## 七、口诀

> **柱状图要两个数组 → 用 JobOption；饼图要 name/value 对象数组 → 直接透传**
> **别名必须叫 name 和 value，这是 ECharts 饼图认的键**
> **`if(条件, 值1, 值2)` 只能二选一，多分支用 CASE**
> **Service 一行 return：Mapper 查出来什么样，就给前端什么样**
