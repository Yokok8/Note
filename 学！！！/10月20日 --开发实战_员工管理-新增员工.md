# 员工管理 - 新增员工（思路）

## 一、需求：一个表单，两张表

新增员工的页面上有两大块内容，分别存到不同的表：

| 页面区域 | 存哪张表 | 关系 |
|---|---|---|
| 上半部分：用户名、姓名、性别、职位、入职日期、部门、手机号、薪资 | **emp**（员工基本信息） | 一条记录 |
| 下半部分：工作经历（公司、职位、开始时间、结束时间，可加多条） | **emp_expr**（工作经历） | **多条记录** |

- emp ↔ emp_expr 是**一对多**：一个员工有多条工作经历
- 所以一次新增，实际要往**两张表**写数据

## 二、前端传来的请求体

    {
      "username": "lininghui",
      "name": "林子",
      "gender": 1,
      "job": 1,
      "entrydate": "2022-09-18",
      "deptId": 1,
      "phone": "1880901234",
      "salary": 8000,
      "exprList": [
        {
          "company": "百渡科技股份有限公司",
          "job": "java开发",
          "begin": "2012-07-01",
          "end": "2019-03-01"
        },
        {
          "company": "阿里空科技股份有限公司",
          "job": "架构师",
          "begin": "2019-03-25",
          "end": "2023-01-01"
        }
      ]
    }

### 结构分析（重点）

    {
      ...emp 表的字段...          ← 外层平铺，直接对应 Emp 的属性
      "exprList": [ { ... }, { ... } ]   ← 数组，对应 List<EmpExpr>
    }

- 外层是**员工基本信息**，键名就是 Emp 的属性名
- `exprList` 是**工作经历数组**，每个元素是一条 EmpExpr
- 所以 **Emp 实体类必须再加一个属性**：

    @Data
    public class Emp {
        private Integer id;
        private String username;
        private String password;
        private String name;
        private Short gender;
        private String image;
        private Short job;
        private LocalDate entrydate;
        private Integer deptId;
        private LocalDateTime createTime;
        private LocalDateTime updateTime;

        private String deptName;              // 分页查询用的，非表字段

        private List<EmpExpr> exprList;       // ★ 新增：工作经历列表，接收嵌套 JSON
    }

## 三、三层职责

| 层 | 要做的事 |
|---|---|
| Controller | ① 接收请求参数（员工信息，用 `@RequestBody Emp`）② 调用 Service 方法 ③ 响应结果 |
| Service | ① 保存员工基本信息（插入 emp）② 批量保存工作经历信息（插入 emp_expr） |
| Mapper | 两条 SQL：① `insert into emp(...) values(...)` ② `insert into emp_expr(...) values(...),(...)` |

> 一句话总结：**保存基本信息 + 批量保存工作经历**，两步都在 Service 里串起来。

## 四、执行顺序（这页真正要理解的）

### 为什么不能随便写

emp_expr 表里有一个 `emp_id` 外键，指向刚插入的员工。

**但新增时员工 id 是数据库自增生成的**——不插入的那一刻，Java 代码根本不知道这个 id 是多少。

### 所以必须按这个顺序

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| 1 | 插入 emp（一条） | **插入后要把自增主键回填到 emp.id** |
| 2 | 遍历 exprList，给每条 EmpExpr 设置 `empId = emp.getId()` | 这一步全靠第 1 步回填的 id |
| 3 | 批量插入 emp_expr（一条 SQL 多组 values） | 用 `<foreach>` 拼 |
| 4 | 整体放在**一个事务**里 | 任一步失败，两张表全部回滚 |

### Mapper 两条 SQL 的形态

    insert into emp (username, password, name, gender, image, job, entrydate, dept_id, create_time, update_time)
    values (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)

    insert into emp_expr (emp_id, begin, end, company, job)
    values (?, ?, ?, ?, ?), (?, ?, ?, ?, ?), (?, ?, ?, ?, ?)

- 第一条：普通单条 insert，但要**回填主键**
- 第二条：**批量 insert**，`values` 后面跟多组括号，用逗号分隔


## 五、易错点

| 问题 | 后果 |
|---|---|
| Emp 里没加 `List<EmpExpr> exprList` | JSON 的 exprList 接不到，工作经历一条都存不进去 |
| 插入 emp 没设置 keyProperty | `emp.getId()` 为 null → emp_expr 的 emp_id 全 null |
| 没加 `@Transactional` | 一半成功一半失败，留下脏数据 |
| 批量插入忘写 `separator` | 多组 values 之间没逗号，SQL 语法错 |
| 日期字段 | JSON 反序列化用 `@JsonFormat`，URL 参数用 `@DateTimeFormat`，用错会 400 |
| JSON 键名大小写与属性名不一致 | 该字段静默为 null |
| 一次插一条 emp_expr（循环调 Mapper） | 能跑但性能差，标准做法是批量 |

## 六、口诀

> **一个表单两张表：emp 存人，emp_expr 存经历**
> **先插人拿到 id，再给经历塞 empId，最后批量插**
> **主键要回填、批量靠 foreach、两步同一事务**

# 员工管理 - 新增员工（保存基本信息）

## 一、这页做的事

上一页思路里的**第 1 步**：先把员工基本信息插进 `emp` 表，工作经历暂时不处理。

一句话：**Controller 收 JSON → Service 补两个时间 → Mapper 插 11 列**。

## 二、三层代码（完整）

### EmpController

    @PostMapping
    public Result save(@RequestBody Emp emp) {
        log.info("请求参数emp: {}", emp);
        empService.save(emp);
        return Result.success();
    }

### EmpServiceImpl

    @Override
    public void save(Emp emp) {
        // 1. 补全基础属性
        emp.setCreateTime(LocalDateTime.now());
        emp.setUpdateTime(LocalDateTime.now());

        // 2. 保存员工基本信息
        empMapper.insert(emp);
    }

### EmpMapper

    @Insert("insert into emp(username, name, gender, phone, job, salary, image, entry_date, dept_id, create_time, update_time) " +
            "values (#{username},#{name},#{gender},#{phone},#{job},#{salary},#{image},#{entryDate},#{deptId},#{createTime},#{updateTime})")
    void insert(Emp emp);

## 三、逐层拆解

### Controller 三个点

| 点 | 说明 |
|---|---|
| `@PostMapping` 不写路径 | 类是 `@RequestMapping("/emps")`，拼接后就是 **POST /emps** |
| `@RequestBody` | 必须加！把请求体的 **JSON 转成 Emp 对象** |
| `Result.success()` | 用的是**无参**版本，data 为 null，只表示"成功" |

- `log.info("请求参数emp: {}", emp)` 打整个对象 → 依赖 `@Data` 生成的 toString

### Service 两个点

- **只补 2 个字段**：`createTime`、`updateTime`（后端生成，前端不传）
- 补完立刻调 `empMapper.insert(emp)`，方法返回 `void`（新增不需要返回值）

### Mapper 两个点

- `@Insert` 里手写**列名**：`entry_date`、`dept_id`、`create_time` 全是**下划线**
- `#{}` 里写的是**实体属性名**：`#{entryDate}`、`#{deptId}`、`#{createTime}` 是**驼峰**

> ⚠️ 这是本页最容易翻车的地方：**列名用下划线，占位符用驼峰**，两边不能写反。

## 四、11 个字段从哪来

| 来源 | 字段 |
|---|---|
| 前端 JSON 传（9 个） | username、name、gender、phone、job、salary、image、entryDate、deptId |
| Service 补（2 个） | createTime、updateTime |
| **合计插入 11 列** | 上面这些 |

**没有插的两列：**

- `id`：数据库自增，不用管
- `password`：课件这里漏了 → 实际项目应在 Service 补一个初始密码（如 `123456`），否则新员工无法登录

## 五、这页留下的三个问题（下一页就要面对）

### ① 主键没有回填 ⚠️ 最关键

现在的 `@Insert` 少了这一行：

    @Options(useGeneratedKeys = true, keyProperty = "id")

- 不加的话，插入成功后 `emp.getId()` 仍然是 **null**
- 下一节要批量插 `emp_expr`，每条记录都需要 `emp_id` → 没有 id 就填不进去

### ② 没有事务

    @Transactional
    @Override
    public void save(Emp emp) { ... }

- 下一步要连插两张表，必须加事务，否则员工插成功、经历失败会产生脏数据

### ③ 没有初始密码

- 建议 Service 里补：`emp.setPassword("123456");`（真实项目应加密存储）

## 六、易错点

| 问题 | 后果 |
|---|---|
| 没加 `@RequestBody` | 收到的 emp 全是 null（JSON 没被解析） |
| `#{}` 里写成 `#{entry_date}` | 报找不到该属性（`#{}` 里是属性名不是列名） |
| SQL 列名写成 `entryDate` | 数据库不认识这列，报 unknown column |
| 忘了补 createTime / updateTime | 两个字段存 null，页面显示异常 |
| 用 `Result.success(data)` 传 emp | 新增一般不需要回数据，无参版就够 |
| 方法写成 `@GetMapping` | 新增必须用 POST |

## 七、口诀

> **Post 收 JSON 要 RequestBody，成功后 Result.success() 无参**
> **Service 只补两个时间，Mapper 手写十一列**
> **列名下划线、占位符驼峰，别写反**
> **（下一步）主键要回填、事务要加、密码要补**

# 员工管理 - 批量保存工作经历

## 一、需求

新增员工页面的「工作经历」区域可以点「+ 新增工作经历」，用户能加任意多条：

| 时间 | 公司 | 职位 |
|---|---|---|
| 2019-10-01 ~ 2021-11-01 | 小米科技有限责任公司 | java开发 |
| 2021-11-05 ~ 2022-11-05 | 高通科技有限公司 | 架构师 |
| 2021-11-10 ~ 2023-11-01 | 字节跳动科技有限公司 | 架构师 |

- 这块数据在请求体里是 `exprList` 数组 → 对应 **`List<EmpExpr>`**
- 每条经历 5 个字段：`emp_id`（属于哪个员工）、`begin`、`end`、`company`、`job`

## 二、为什么要"批量"

    -- 循环插 3 次：3 条 SQL、3 次数据库往返
    insert into emp_expr(...) values (...);
    insert into emp_expr(...) values (...);
    insert into emp_expr(...) values (...);

    -- 批量：1 条 SQL、1 次往返
    insert into emp_expr(...) values (...),(...),(...);

- 经历条数越多，差距越明显
- 批量插入靠 MyBatis 的 `<foreach>` 标签拼出来

## 三、EmpExprMapper 接口

    public void insertBatch(List<EmpExpr> exprList);

- 参数是**一个 List**，返回 void
- ⚠️ 建议写成 `@Param("exprList") List<EmpExpr> exprList`，显式指定集合名，不依赖编译参数名保留

## 四、EmpExprMapper.xml

    <insert id="insertBatch">
        insert into emp_expr (emp_id, begin, end, company, job) values
        <foreach collection="exprList" item="expr" separator=",">
            (#{expr.empId}, #{expr.begin}, #{expr.end}, #{expr.company}, #{expr.job})
        </foreach>
    </insert>

### 生成的 SQL 长这样

    insert into emp_expr (emp_id, begin, end, company, job) values
    (?,?,?,?,?), (?,?,?,?,?), (?,?,?,?,?)

- `values` 只写一次
- `<foreach>` 负责把每组 `(...)` 循环拼出来
- 组与组之间的逗号 = `separator=","`

### 三个占位符要点

| 写法 | 说明 |
|---|---|
| `#{expr.empId}` | item 是 `expr`，取它的属性用点号 |
| `#{expr.begin}` / `#{expr.end}` | begin/end 是列名也是属性名 |
| `emp_id` 列 ↔ `empId` 属性 | 列名下划线，属性名驼峰 |

## 五、`<foreach>` 五个属性（重点背）

| 属性 | 含义 | 必填 |
|---|---|---|
| `collection` | **集合名称**（要遍历哪个集合） | ✅ |
| `item` | 集合遍历出来的**元素/项**，起个名字给后面 `#{}` 用 | ✅ |
| `separator` | 每一次遍历使用的**分隔符** | 可选 |
| `open` | 遍历**开始前**拼接的片段 | 可选 |
| `close` | 遍历**结束后**拼接的片段 | 可选 |

> **`<foreach>` 的作用：遍历集合 / 数组，把集合里的元素按模板循环拼成 SQL 片段。**&#8203;

### open / close 什么时候用

本例不需要，因为 `values` 和括号都是手写的。如果 SQL 是这样的场景才用得上：

    where id in
    <foreach collection="ids" item="id" open="(" separator="," close=")">
        #{id}
    </foreach>

- `open="("` 拼出左括号，`close=")"` 拼出右括号 → 生成 `in (1,2,3)`

## 六、Service 里把两步串起来（完整版）

    @Transactional
    @Override
    public void save(Emp emp) {
        // 1. 补全基础属性
        emp.setCreateTime(LocalDateTime.now());
        emp.setUpdateTime(LocalDateTime.now());

        // 2. 保存员工基本信息（这一步必须回填主键！）
        empMapper.insert(emp);

        // 3. 保存工作经历
        List<EmpExpr> exprList = emp.getExprList();
        if (exprList != null && !exprList.isEmpty()) {
            // 给每条经历设置所属员工的 id
            exprList.forEach(expr -> expr.setEmpId(emp.getId()));
            // 批量插入
            empExprMapper.insertBatch(exprList);
        }
    }

对应地，`empMapper.insert` 必须加：

    @Options(useGeneratedKeys = true, keyProperty = "id")
    @Insert("insert into emp(...) values(...)")
    void insert(Emp emp);

## 七、思考题（课件最后一页）

### 1. 在插入数据之后，如何获取到主键值？

    @Options(useGeneratedKeys = true, keyProperty = "id")

- 贴在 insert 方法上（注解方式），或 XML 里写 `<insert useGeneratedKeys="true" keyProperty="id">`
- `useGeneratedKeys = true`：使用数据库自动生成的主键
- `keyProperty = "id"`：把生成的主键值**回填到实体的 id 属性**
- 执行完 `insert(emp)` 后，直接 `emp.getId()` 就能拿到新 id

### 2. `<foreach>` 动态 SQL 标签的作用？属性含义？

- **作用**：遍历集合 / 数组
- **属性**：

| 属性 | 含义 |
|---|---|
| `collection` | 集合名称 |
| `item` | 集合遍历出来的元素/项 |
| `separator` | 每一次遍历使用的分隔符（可选） |
| `open` | 遍历开始前拼接的片段（可选） |
| `close` | 遍历结束后拼接的片段（可选） |

## 八、易错点

| 问题 | 后果 |
|---|---|
| `collection` 写错名（默认 key 是 `list`） | 报 "Parameter 'xxx' not found"，或按规范加 `@Param` 解决 |
| 忘写 `separator` | 多组 values 之间没逗号 → SQL 语法错 |
| `#{expr.empId}` 写成 `#{empId}` | 报找不到属性（item 里要加点号取元素属性） |
| 忘了给每条 expr 设 empId | 插入成功但 emp_id 全 null，数据挂不上员工 |
| insert emp 没加 `@Options` | `emp.getId()` 为 null，导致上一条全军覆没 |
| 循环调 insertBatch 一条一条插 | 逻辑写错，应该整个 List 一次传进去 |
| 没加 `@Transactional` | 员工插成功、经历失败 → 脏数据 |
| begin/end 不加反引号 | MySQL 里 begin/end 是保留字，建议写成 \`begin\` |

## 九、口诀

> **`<foreach>` 遍历集合：collection 找集合、item 起名字、separator 连逗号**
> **open 和 close 负责括号，values 只写一次**
> **主键要 `@Options(useGeneratedKeys=true, keyProperty="id")` 回填，再 setEmpId，再批量插**
> **两步同事务，缺一不可**
