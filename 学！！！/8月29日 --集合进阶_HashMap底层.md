# HashMap 的 put 方法知识点总结

---

## 一句话记住 put 干了啥

往 HashMap 里放一个键值对，分三步走：**算位置 → 看情况放 → 检查扩容**。

---

## 一、put 方法的入口

```java
hm.put("aaa", 111);
```

底层调用关系：

```
put(key, value)
    └→ 先用 hash(key) 算出哈希值
         └→ 再调用 putVal(...) 真正去放
```

---

## 二、hash 方法是干嘛的

```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

**简单说：** 把 key 的 hashCode 高 16 位和低 16 位"搅一搅"，让哈希值分布更均匀，减少冲突。

> 为什么要搅？因为数组长度小时，只有低位参与计算桶下标，高位不参与容易扎堆。

---

## 三、桶下标怎么算

```java
i = (n - 1) & hash;    // n 是数组长度
```

等价于 `hash % n`（取余数），但位运算更快。

**前提条件：** 数组长度必须是 2 的幂次（16、32、64……），这样 `& (n-1)` 才等于取模。

---

## 四、put 的三种情况（⭐ 重点）

### 情况 1：数组位置是空的

```
桶里啥都没有 → 直接把新节点放进去
```

```java
if (p == null) {
    tab[i] = newNode(hash, key, value, null);
}
```

---

### 情况 2：数组位置有元素，但 key 不重复

```
桶里已经有元素了，但 key 不一样 → 挂在下面形成链表/红黑树
```

**如果下面是链表：**
- 从第一个节点开始往后遍历
- 一直找到链表末尾
- 用**尾插法**把新节点挂在最后

```java
for (int binCount = 0; ; ++binCount) {
    if ((e = p.next) == null) {
        p.next = newNode(hash, key, value, null);  // 挂在末尾
        // 链表长度 ≥ 8，考虑转红黑树
        if (binCount >= 7)
            treeifyBin(tab, hash);
        break;
    }
    // ...
    p = e;  // 往后移一位继续找
}
```

**链表转红黑树的条件（两个都要满足）：**
1. 链表长度 ≥ 8
2. 数组长度 ≥ 64

> 如果数组长度不够 64，就**只扩容不树化**（扩容能更有效地分散元素）。

---

### 情况 3：数组位置有元素，且 key 相同

```
找到了一样的 key → 用新值覆盖旧值
```

**可能在三个地方找到相同 key：**
- 数组中的第一个节点（头节点）
- 链表中的某个节点
- 红黑树中的某个节点

**找到后统一处理：**

```java
if (e != null) {
    V oldValue = e.value;   // 先存一下旧值
    e.value = value;        // 用新值覆盖旧值
    return oldValue;        // 返回被覆盖的旧值
}
```

**关于 onlyIfAbsent 参数：**
- `put()` 传的是 `false` → **一定会覆盖**
- `putIfAbsent()` 传的是 `true` → **旧值为 null 才覆盖**

---

## 五、什么时候扩容

```java
if (++size > threshold) {
    resize();
}
```

- `size`：当前元素个数
- `threshold`：扩容阈值 = 数组长度 × 0.75
- 比如默认 16 × 0.75 = **12**，加到第 13 个元素就扩容

**扩容规则：** 每次扩为原来的 **2 倍**

---

## 六、完整流程图（一眼看懂）

```
put(key, value)
    │
    ▼
  ① 用 hash(key) 算出哈希值
    │
    ▼
  ② 数组是空的吗？
    ├─ 是 → resize() 创建数组（默认长度 16）
    └─ 否 → 继续
    │
    ▼
  ③ (n-1) & hash 算出桶下标
    │
    ▼
  ④ 桶位置是空的吗？
    ├─ 是 → 【情况1】直接放进去 → 检查扩容 → 结束
    └─ 否 → 继续
    │
    ▼
  ⑤ 头节点的 key 相同吗？
    ├─ 是 → 【情况3】记录 e，准备覆盖 → goto ⑦
    └─ 否 → 继续
    │
    ▼
  ⑥ 是红黑树还是链表？
    ├─ 红黑树 → putTreeVal 插入/查找
    └─ 链表 → 遍历链表
    │         ├─ 找到相同 key → 【情况3】记录 e
    │         └─ 没找到 → 【情况2】尾插法挂末尾
    │                  └─ 链表≥8且数组≥64 → 转红黑树
    │
    ▼
  ⑦ 有相同 key 吗（e 不为 null）？
    ├─ 是 → 覆盖 value，返回旧值 → 结束
    └─ 否 → 继续
    │
    ▼
  ⑧ size+1 后超过阈值了吗？
    ├─ 是 → resize() 扩容
    └─ 否 → 不扩容
    │
    ▼
  返回 null（没覆盖任何元素）
```

## 七、详细总结

### 7.1 putVal 方法中的关键变量

| 变量 | 类型 | 作用 |
|------|------|------|
| `tab` | `Node<K,V>[]` | 临时变量，存哈希表数组的地址值（避免每次都去读成员变量） |
| `p` | `Node<K,V>` | 临时变量，当前桶位置的节点（用来遍历链表/树） |
| `e` | `Node<K,V>` | 临时变量，记录"找到的相同 key 的节点"，没找到就是 null |
| `n` | `int` | 数组的长度 |
| `i` | `int` | 计算出的桶下标（数组索引） |
| `hash` | `int` | key 经过扰动后的哈希值 |
| `k` | `K` | 临时变量，存节点的 key，用来比较 |
| `binCount` | `int` | 链表遍历计数器，用来判断链表长度是否达到树化阈值 |
| `onlyIfAbsent` | `boolean` | key 重复时是否保留旧值（false=覆盖，true=不覆盖） |

> **记忆技巧：** p 是"当前节点"，e 是"找到的目标节点"（equal 的 e）。遍历时 p 一步步往前走，找到了就把节点赋值给 e。

---

### 7.2 三种情况对比表

| | 情况1 | 情况2 | 情况3 |
|---|-------|-------|-------|
| **描述** | 桶位置为空 | 桶不为空，key 不重复 | 桶不为空，key 重复 |
| **动作** | 直接放数组里 | 挂在链表/红黑树下面 | 覆盖旧值 |
| **e 的值** | 不涉及 e | e = null（没找到相同 key） | e 指向旧节点 |
| **size 变化** | size + 1 | size + 1 | size 不变 |
| **返回值** | null | null | 被覆盖的旧值 |
| **是否可能扩容** | 是 | 是 | 否（直接返回了） |

---

### 7.3 关键数值速记

| 数值 | 含义 | 说明 |
|------|------|------|
| **16** | 默认初始容量 | 数组默认长度 |
| **0.75** | 默认负载因子 | 空间和时间的折中 |
| **12** | 默认扩容阈值 | 16 × 0.75 = 12 |
| **2 倍** | 扩容倍数 | 每次扩容为原来的 2 倍 |
| **8** | 树化阈值 | 链表长度达到 8 考虑转红黑树 |
| **64** | 树化的数组最小长度 | 数组长度 < 64 时只扩容不树化 |
| **6** | 退化阈值 | 红黑树节点 ≤ 6 退化为链表 |

> **为什么树化是 8、退化是 6？** 留个缓冲区间，避免在边界反复增删导致链表和红黑树来回切换。

---

### 7.4 为什么容量必须是 2 的幂次

```
核心原因：位运算求桶下标

n = 16（二进制 10000）
n - 1 = 15（二进制 01111）

hash & (n - 1) = hash & 15
= 取 hash 的低 4 位
= hash % 16（取余数）

如果 n 不是 2 的幂次，比如 n = 10：
n - 1 = 9（二进制 1001）
hash & 9 就不等于 hash % 10，分布会不均匀
```

**好处：**
1. 位运算比取模快很多
2. 扩容时元素位置有规律（要么不动，要么移旧容量的距离）

---

### 7.5 扩容时元素去哪了

扩容后数组长度翻倍（16 → 32），元素的新位置只有两种可能：

```
判断方法：hash & oldCap

  结果为 0 → 留在原位置（不变）
  结果非 0 → 移到 原位置 + oldCap

原理：扩容后多了一位参与运算，
     这一位正好就是 oldCap 对应的那一位。
```

**举例（oldCap = 16）：**

```
元素 A 的 hash 第 4 位是 0 → 留在原位置
元素 B 的 hash 第 4 位是 1 → 移到 原位置 + 16
```

### 7.6 常见面试题一句话答案

| 问题 | 一句话答案 |
|------|-----------|
| HashMap 底层数据结构？ | JDK8 是数组+链表+红黑树 |
| put 过程说一下？ | 算 hash → 算桶下标 → 空则直接放，冲突挂链表/树，key 重复覆盖，超阈值扩容 |
| 为什么用位运算不用取模？ | 更快，且容量是 2 的幂次时等价 |
| 为什么要 hash 扰动？ | 让高位也参与桶下标的计算，减少冲突 |
| 链表什么时候转红黑树？ | 链表长度 ≥ 8 且数组长度 ≥ 64 |
| 为什么数组小于 64 不树化？ | 扩容比树化更能有效分散元素 |
| 扩容后元素位置怎么变？ | hash & oldCap 为 0 留原位，否则移原位+oldCap |
| JDK7 和 JDK8 插入区别？ | JDK7 头插法，JDK8 尾插法 |
| 头插法有什么问题？ | 并发扩容可能形成环形链表，死循环 |
| HashMap 是线程安全的吗？ | 不是，多线程用 ConcurrentHashMap |

### 7.7 putVal 完整源码（带中文注释）

```java
final V putVal(int hash, K key, V value, boolean onlyIfAbsent, boolean evict) {
    Node<K,V>[] tab;    // 哈希表数组
    Node<K,V> p;        // 当前节点
    int n;              // 数组长度
    int i;              // 桶下标

    tab = table;

    // ① 数组为空或长度为0 → 扩容/初始化
    if (tab == null || (n = tab.length) == 0) {
        tab = resize();
        n = tab.length;
    }

    // ② 计算桶下标
    i = (n - 1) & hash;
    p = tab[i];

    // ③ 桶位置为空 → 情况1：直接放
    if (p == null) {
        tab[i] = newNode(hash, key, value, null);
    } else {
        Node<K,V> e;    // 记录找到的相同 key 的节点
        K k;

        // ④ 头节点 key 相同 → 情况3
        if (p.hash == hash &&
            ((k = p.key) == key || (key != null && key.equals(k)))) {
            e = p;
        }
        // ⑤ 是红黑树节点 → 红黑树方式插入
        else if (p instanceof TreeNode) {
            e = ((TreeNode<K,V>)p).putTreeVal(this, tab, hash, key, value);
        }
        // ⑥ 是链表 → 遍历链表
        else {
            for (int binCount = 0; ; ++binCount) {
                // 到链表末尾了 → 情况2：尾插法插入
                if ((e = p.next) == null) {
                    p.next = newNode(hash, key, value, null);
                    // 链表长度 ≥ 8 → 考虑树化
                    if (binCount >= TREEIFY_THRESHOLD - 1)
                        treeifyBin(tab, hash);
                    break;
                }
                // 链表中找到相同 key → 情况3
                if (e.hash == hash &&
                    ((k = e.key) == key || (key != null && key.equals(k))))
                    break;
                p = e;  // p 后移，继续遍历
            }
        }

        // ⑦ e 不为 null → 有相同 key，覆盖
        if (e != null) {
            V oldValue = e.value;
            if (!onlyIfAbsent || oldValue == null)
                e.value = value;
            afterNodeAccess(e);
            return oldValue;
        }
    }

    // ⑧ size + 1，超过阈值就扩容
    if (++size > threshold)
        resize();

    return null;
}
```

```
一算二看三插入，
空桶直接放进去，
冲突就挂链表底，

装多了就扩两倍去。
```
