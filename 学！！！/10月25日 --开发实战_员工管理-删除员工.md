# 员工管理 - 删除员工（批量删除）· 思路

## 一、需求

员工列表页每行前面有复选框，勾选多条后点「批量删除」：

| 页面元素 | 作用 |
|---|---|
| 表头复选框 | 全选 / 取消全选 |
| 每行复选框 | 勾选要删的员工 |
| 批量删除按钮 | 把勾选的 id 一起提交 |

- 注意：这次不是"删一个"，而是**一次删多条** → 参数是**一个 ID 集合**

## 二、接口文档（图右上角）

| 项 | 内容 |
|---|---|
| 请求方式 | **DELETE** |
| 接口描述 | 该接口用于**批量删除员工**的数据信息 |
| 参数格式 | **查询参数** |
| 参数名 | `ids` |
| 类型 | **数组 array** |
| 示例 | `1,2,3` |
| 请求样例 | `DELETE /emps?ids=1,2,3` |

关键点：**不是 `?id=7` 单个值，而是 `?ids=1,2,3` 逗号分隔的数组**。

## 三、三层职责（图下半部分）

| 层 | 职责 |
|---|---|
| **Controller** | ① 接收请求参数（ID 值）② 调用 Service 方法 ③ 响应结果 |
| **Service** | ① 批量删除员工基本信息 ② 批量删除员工的工作经历信息 |
| **Mapper** | 两条 SQL：删 emp、删 emp_expr |

### ⚠️ 这次要多删一张表

| 表 | 为什么要删 |
|---|---|
| `emp` | 员工本体，勾选的就是它 |
| `emp_expr` | 员工的工作经历，挂在这个员工下 |

- 只删 `emp` 不删 `emp_expr` → 工作经历变成**孤儿数据**，永远挂在已删除的 emp_id 上
- 所以 Service 里必须**两次删除**，而且放在**同一个事务**里

# Controller 接收请求参数（数组 / 集合）

## 一、这次要接的请求

    DELETE /emps?ids=1,2,3

- 参数名 `ids`，值是一串用**逗号分隔**的数字
- 后端要把它变成一个"能装多个 id 的容器"→ 两种选择：**数组** 或 **集合**

## 二、方式一：用数组接收

    @DeleteMapping
    public Result delete(Integer[] ids) {
        log.info("根据id批量删除员工:{} ", ids);
        return Result.success();
    }

- **特点：可以不写 `@RequestParam`**，Spring 照样能接上
- 类型是 `Integer[]`，不是 `int[]`（用包装类，避免 null 拆箱报空指针）

## 三、方式二：用集合接收

    @DeleteMapping
    public Result delete(@RequestParam List<Integer> ids) {
        log.info("根据id批量删除员工:{} ", ids);
        return Result.success();
    }

- **特点：必须加 `@RequestParam`**，不加就接不到（或直接报错）
- 类型写 `List<Integer>`，接口类型用 `List` 而不是 `ArrayList`

## 四、为什么两种差一个注解（原理）

| 类型 | Spring 的处理方式 | 是否需要注解 |
|---|---|---|
| **数组** `Integer[]` | 知道它"装不下一个对象"，只能从请求参数里**按同名逐个取**（`ids=1,2,3` 自动拆成三个） | **不需要** |
| **集合** `List<Integer>` | 接口类型，Spring 判断不出你是"要一批同名参数"还是"要封装成一个对象"，默认按对象绑定（ModelAttribute）走 | **必须 `@RequestParam` 指明参数名** |

- 一句话：**数组是"天生就是一组值"，集合是"可能装对象也可能装值"，所以要靠注解说明**

## 五、两种参数格式都支持

| URL 写法 | 说明 |
|---|---|
| `/emps?ids=1,2,3` | 逗号分隔（本项目接口文档约定的） |
| `/emps?ids=1&ids=2&ids=3` | 同名多值（复选框默认的提交格式） |

两种写法，数组和集合都能正确解析，不用额外处理。

## 六、⚠️ 打印时的坑（图里代码有隐患）

    log.info("根据id批量删除员工:{} ", ids);     // ids 是数组

**数组的 `toString()` 打印的是哈希地址**，控制台会输出：

    [Ljava.lang.Integer;@1b6d3586

看不出任何值。正确写法：

    log.info("根据id批量删除员工:{}", Arrays.toString(ids));   // [1, 2, 3]

而**用 List 就没有这个问题**，List 的 `toString()` 本来就会输出 `[1, 2, 3]`：

    log.info("根据id批量删除员工:{}", ids);      // ids 是 List → [1, 2, 3] 正常

> 这个坑很隐蔽：代码能跑、日志也不报错，只是打出来一堆看不懂的乱码，调试时容易懵。

## 七、两种写法怎么选

| 对比项 | `Integer[] ids` | `List<Integer> ids` |
|---|---|---|
| 需要 `@RequestParam` | 不需要 | **必须** |
| 日志打印 | 要额外 `Arrays.toString()` | 直接可读 |
| 配合 Mapper 的 `<foreach>` | 要 `Arrays.asList()` 转换 | **直接传** |
| Service 层处理 | 数组转集合多一点代码 | 直接用 |
| 判断空集合 | `ids.length == 0` | `ids.isEmpty()` |

**推荐用 `List<Integer>`**：后面 Service 传给 Mapper、XML 里 `<foreach>` 遍历，都是 List 最顺手。

## 八、易错点

| 问题 | 后果 |
|---|---|
| 集合参数漏写 `@RequestParam` | ids 为 null，或 `Failed to instantiate List` 类报错 |
| 写成 `@RequestParam ArrayList<Integer> ids` | 无法实例化接口/具体类，绑定失败，用 `List` |
| 用 `int[] ids` | 空值拆箱抛 `NullPointerException`，用 `Integer[]` |
| 数组直接塞进 `log.info("{}", ids)` | 打印哈希地址，看不到值 |
| 加了 `@RequestBody` | 参数在 URL 上不是 JSON 体，直接 400/415 |
| 方法名/路径写成 `/emps/{ids}` | 那是路径参数，和文档的 `?ids=` 不一致，404 |

## 九、口诀

> **`?ids=1,2,3` → 数组或集合都能接**
> **数组可以不加注解，集合必须 `@RequestParam`**
> **打日志别直接打数组，要么 `Arrays.toString` 要么用 List**
> **后续给 Mapper 用，选 `List<Integer>` 最省事**

# 删除员工 - Service & Mapper 实现

## 一、EmpServiceImpl

    @Transactional(rollbackFor = {Exception.class})
    public void deleteByIds(List<Integer> ids) {
        //1. 根据ID删除员工基本信息
        empMapper.deleteByIds(ids);

        //2. 根据ID删除员工的工作经历信息
        empExprMapper.deleteByEmpIds(ids);
    }

### 三点拆解

| 点 | 说明 |
|---|---|
| `@Transactional(rollbackFor = {Exception.class})` | 两次删除**要么全成、要么全回滚**；加 rollbackFor 是为了受检异常也能回滚 |
| 两次 Mapper 调用 | 一个删 `emp`，一个删 `emp_expr`，**缺一不可** |
| 返回 `void` | 删除不需要返回值，Controller 里用 `Result.success()` 无参版 |

### 关于删除顺序

课件是先删 `emp`，再删 `emp_expr`。本项目**能跑**，因为用的是**逻辑外键**（数据库层面没有约束）。

但如果将来加上物理外键约束，这个顺序会直接报错：

    Cannot delete or update a parent row: a foreign key constraint fails

保险习惯是**先删子表（emp_expr），再删主表（emp）**&#8203;。两边都无所谓的时候，按安全的方向写不会吃亏。

## 二、EmpMapper.xml

    <!-- 根据ID批量删除员工信息 -->
    <delete id="deleteByIds">
        delete from emp where id in
        <foreach collection="ids" item="id" separator="," open="(" close=")">
            #{id}
        </foreach>
    </delete>

### 生成的 SQL

    delete from emp where id in (?,?,?)

- `in (` 由 `open="("` 拼出
- 三个 `?` 由循环生成，个数 = ids 的个数
- 中间的逗号由 `separator=","` 拼出
- 最后的 `)` 由 `close=")"` 拼出

### foreach 五个属性（这里全用上了）

| 属性 | 值 | 作用 |
|---|---|---|
| `collection` | `ids` | 要遍历的集合名 |
| `item` | `id` | 每个元素在循环里的名字，供 `#{id}` 引用 |
| `separator` | `,` | 元素之间的分隔符 |
| `open` | `(` | 循环前拼上 |
| `close` | `)` | 循环后拼上 |

## 三、EmpExprMapper.xml

    <!--根据员工ID批量删除员工工作经历信息-->
    <delete id="deleteByEmpIds">
        delete from emp_expr where emp_id in
        <foreach collection="empIds" item="empId" separator="," open="(" close=")">
            #{empId}
        </foreach>
    </delete>

- SQL 生成：`delete from emp_expr where emp_id in (?,?,?)`
- 注意这里删的是 `emp_expr` 表，条件是 **`emp_id`**（不是 `id`）——这是子表关联主表的外键字段

## 四、⭐ 两个 XML 的 collection 值为什么不一样

| 文件 | collection | item |
|---|---|---|
| EmpMapper.xml | `ids` | `id` |
| EmpExprMapper.xml | **`empIds`** | **`empId`** |

因为对应的 **Mapper 接口形参名不同**：

    @Mapper
    public interface EmpMapper {
        void deleteByIds(List<Integer> ids);
    }

    @Mapper
    public interface EmpExprMapper {
        void deleteByEmpIds(List<Integer> empIds);
    }

### 关键规则

> **`collection` 认的是 Mapper 接口的形参名（或 `@Param` 的值），跟调用处传进去的变量名叫什么毫无关系。**&#8203;

- Service 里写的是 `empExprMapper.deleteByEmpIds(ids)`，变量叫 `ids`
- 但接口形参叫 `empIds`，所以 XML 必须写 `collection="empIds"`
- 如果 XML 里写成 `collection="ids"` → 报 `Parameter 'ids' not found`

### 更稳的写法：加 @Param

    void deleteByEmpIds(@Param("empIds") List<Integer> empIds);

- 加了 `@Param` 后，`collection` 就明确认注解里的字符串
- 优点：不依赖编译时保留参数名（如果有人没开 `-parameters`，不加注解就会报 not found）

## 五、完整三层代码汇总（可对照抄）

### EmpController

    @DeleteMapping
    public Result delete(@RequestParam List<Integer> ids) {
        log.info("根据id批量删除员工:{}", ids);
        empService.deleteByIds(ids);
        return Result.success();
    }

### EmpService / EmpServiceImpl

    void deleteByIds(List<Integer> ids);

    @Transactional(rollbackFor = {Exception.class})
    public void deleteByIds(List<Integer> ids) {
        empMapper.deleteByIds(ids);
        empExprMapper.deleteByEmpIds(ids);
    }

### EmpMapper（接口 + XML）

    void deleteByIds(List<Integer> ids);

### EmpExprMapper（接口 + XML）

    void deleteByEmpIds(List<Integer> empIds);

## 六、易错点

| 问题 | 后果 |
|---|---|
| `collection` 名字对不上形参名 | `Parameter 'xxx' not found`，启动或调用时报错 |
| 以为 `collection` 是调用处的变量名 | 同上，这是最常见的误解 |
| 只删 emp 忘了 emp_expr | 孤儿数据，经历表一直残留 |
| 忘了 `@Transactional` | 一条成功一条失败 → 数据不一致 |
| ids 是空集合 | 拼成 `in ()`，SQL 语法错误，Service 里先判空 |
| `#{id}` 写成 `${id}` | SQL 注入风险 |
| XML namespace 写错 | `Invalid bound statement (not found)` |
| 两张表用一个 foreach 的 item 名 | 逻辑能跑但可读性差，建议各起各的名字 |

## 七、口诀

> **Service 两行调用 + 一个 `@Transactional(rollbackFor)`**
> **XML 三件套：`delete from 表 where 字段 in` + foreach**
> **foreach 五属性：collection、item、separator、open、close**
> **collection 只认形参名（或 @Param），跟调用处变量名无关**
> **先子表后主表，将来加外键不返工**
