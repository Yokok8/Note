# 前后端分离开发

## 一、是什么
前端项目、后端项目 —— 开发和部署都是分开的。

| | 传统模式（JSP） | 前后端分离 |
|---|---|---|
| 页面 | 后端写（JSP 里混 Java） | 前端独立工程 |
| 数据 | 后端直接吐 HTML | 后端只吐 JSON |
| 部署 | 一个包一起上 | 两个项目分开部署 |
| 问题 | 前后端互相等、改页面要动后端 | 解耦，各干各的 |

一句话：**后端只负责给数据（JSON），前端负责把数据渲染成页面。**&#8203;

## 二、开发流程（五步）
需求分析 → 接口设计 → 前后端并行开发 → 测试 → 联调

| 步骤 | 干什么 | 关键点 |
|---|---|---|
| 需求分析 | 搞清要做什么功能 | 看需求文档 |
| 接口设计 | 定好每个接口的 **地址 / 请求方式 / 参数 / 返回值** | 产出**接口文档** |
| 并行开发 | 前端照文档开发页面，后端照文档写逻辑 | 前端可用 mock 数据，**不用等后端** |
| 测试 | 前后端各自测自己那部分 | 后端用 Postman 测接口 |
| 联调 | 前后端拼一起跑通 | 对不上多半是**接口没对齐** |

## 三、为什么"接口设计"是核心
接口文档 = 前后端之间的**合同**。
- 有了它，前端不用等后端写完就能开工 → 这就是"并行"
- 联调时出错，先拿出文档对一遍：地址对不对、参数名对不对、返回结构对不对

## 四、口诀
- **开发分开、部署也分开，后端给 JSON，前端管渲染**
- **先定接口再动手，前端后端不互等**
- **联调报错先对文档，地址参数返回值**

# RESTful 风格

## 一、是什么
REST = **RE**presentational **S**tate **T**ransfer，表述性状态转换，是一种**软件架构风格**（不是规定）。

是一套**设计 Web API 的约定/架构风格**。它主要用来让接口更统一、可读、易维护，尤其适合前后端分离、微服务、开放平台等场景。

## 二、传统风格 vs REST 风格

| 需求 | 传统风格 URL | 请求方式 | REST 风格 URL | 请求方式 |
|---|---|---|---|---|
| 查 id=1 用户 | /user/getById?id=1 | GET | /users/1 | GET |
| 新增用户 | /user/saveUser | POST | /users | POST |
| 修改用户 | /user/updateUser | POST | /users | PUT |
| 删除 id=1 用户 | /user/deleteUser?id=1 | GET | /users/1 | DELETE |
| 评价 | 动作写在 URL 里 → **不规范、难维护** | 混用 | **URL 定位资源，动词描述操作 → 简洁规范优雅** | |

## 三、核心思想（一句话）
**URL 用名词定位"操作谁"，请求方式用动词说明"干什么"。**&#8203;
- 操作的是**资源**，所以 URL 里出现的是 `users`、`books`，不出现 get/save/update/delete
- 同一个 URL `/users`，靠 GET / POST / PUT / DELETE 区分四个操作

## 四、注意（课件红字）
1. REST 是**风格、是约定**，不是硬规定，**可以打破**（实际项目里也有人写成 `/user/getById`，能跑）
2. 描述功能模块**通常用复数形式**（加 s）：`users`、`books` —— 表示**这类资源**的整体，而不是单个资源
   - `/users` 表示用户资源集合；`/users/1` 才表示其中某一个

## 五、易错点
| 易错                | 说明                                                  |
| ----------------- | --------------------------------------------------- |
| 删除用 GET           | 传统风格里常见，但 GET 不该改数据（会被浏览器预加载、爬虫误触）→ REST 强制用 DELETE |
| 新增/修改都用 POST      | REST 里 POST 管新增、PUT 管修改，要分清                         |
| URL 写成 /user/1 单数 | 模块名习惯用复数 /users/1                                   |
| 以为必须遵守            | 它是**约定**，公司内部统一就行                                   |

## 六、口诀
- **名词放 URL，动词看方式**
- **增 POST、删 DELETE、改 PUT、查 GET**
- **复数表一类，风格非铁律**

# Apifox

## 一、是什么
一款集成了 **Api 文档 + Api 调试 + Api Mock + Api 测试**的**一体化协作平台**。

课件原文：`Apifox = Postman + Swagger + Mock + JMeter`
→ 以前要装 4 个工具干 4 件事，现在一个 Apifox 全包，而且**文档和调试不脱节**。

## 二、三大作用（重点记）
| 作用          | 干什么                   | 对应开发流程哪一步 |
| ----------- | --------------------- | --------- |
| **接口文档管理**  | 写/维护接口文档，前端照着开发       | 接口设计      |
| **接口请求测试**  | 发请求、看响应，验证接口通不通       | 测试 / 联调   |
| **Mock 服务** | 后端没写完时，先造**假数据**返回给前端 | 前后端并行开发   |

## 三、官网
https://apifox.com/ —— 提供**客户端下载**和 **Web 版**两种用法

## 四、为什么需要它
- 传统方式：文档写在 Word/Excel，改一次要通知一圈，**文档和代码对不上**
- Apifox：文档直接由它管理、能直接发请求调试，**改一处前后端同步看到**
- 对我们后端来说最关键的一条：**写完 Controller 就用它测**，不用等前端页面做好

## 五、口诀
- **文档、调试、Mock、测试，四合一**
- **接口文档管理 + 请求测试 + Mock 服务**（三大作用）
- **后期测试联调，主力工具就是它**

# 实战·工程搭建

## 一、三步走
1. 创建 SpringBoot 工程，勾选依赖：**web 起步依赖、mybatis、mysql 驱动、lombok**
2. 创建数据库表 **dept**，在 application.yml 中配置数据库基本信息
3. 准备基础代码结构，引入实体类 **Dept** 和统一响应结果封装类 **Result**

### 构建项目步骤

#### 1.创建空项目

#### 2.配置JDK，Maven，文件编码格式

#### 3.创建SpringBoot模块，引入web开发起步依赖、mybiatis、mysql驱动、lombok


## 二、依赖勾选对照（IDEA 新建工程界面）
| 勾选项 | 作用 |
|---|---|
| Spring Web | 提供内嵌 Tomcat + SpringMVC，能写 Controller |
| MyBatis Framework | 持久层框架，简化 JDBC |
| MySQL Driver | 数据库驱动 jar，连接 MySQL 必须 |
| Lombok | 用 @Data 自动生成 getter/setter/toString |

版本选 **2.x 稳定版**（课件用 3.2.6），勾好依赖省得后面手改 pom。

## 三、application.yml 配置
以下内容整体缩进一级贴进你的 yml 文件：

    spring:
      datasource:
        driver-class-name: com.mysql.cj.jdbc.Driver
        url: jdbc:mysql://localhost:3306/tlias
        username: root
        password: 1234

要点：① 和 properties 写法一一对应；② 库名要和建表所在库一致；③ 只能空格缩进，不能用 Tab。

## 四、Result 统一响应结果封装
    @Data
    public class Result {
        private Integer code; // 编码：1 成功，0 失败
        private String msg;   // 错误信息
        private Object data;  // 数据
    }

返回给前端的 JSON：
- 成功：{"code": 1, "msg": "操作成功", "data": ...}
- 失败：{"code": 0, "msg": "密码错误", "data": ...}

**为什么要封装**：不封装的话，查全部返回数组、查单个返回对象、新增返回 null，前端每种情况都要单独判断；封装后**前端只认 code / msg / data 这一套结构**。

## 五、易错点
| 易错 | 说明 |
|---|---|
| 忘勾 MyBatis / 驱动 | 启动直接报找不到驱动或无法注入 |
| password 写空 | 报 Access denied |
| 库名写错 | 报 Unknown database |
| code 用 int | 用包装类 Integer，避免 null 问题 |
| data 写成具体类型 | 必须是 Object，才能装 List / 对象 / 字符串 |

## 六、口诀
- **勾依赖四件套：Web、MyBatis、MySQL、Lombok**
- **建表 dept → 配 yml → 写 Dept 和 Result**
- **Result 三字段：code 成败、msg 提示、data 数据**
