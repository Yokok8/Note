# 数据库与 MySQL（入门概念）

## 一、五个概念一张表

| 概念 | 是什么 | 类比 |
|---|---|---|
| **数据** | 一条条记录 | 书 |
| **表** | 数据按行、列存放 | 书架 |
| **数据库（DB）**&#8203; | 存放数据的仓库，里面是多张表 | 书库 |
| **MySQL（DBMS）**&#8203; | 管理数据库的**软件** | 图书管理员 |
| **SQL** | 操作数据库的语言 | 对管理员说的话 |

**关系链：数据 → 表 → 数据库 ← MySQL 管理 ← 用 SQL 操作**

## 二、什么是数据库
存储和管理数据的**仓库**，数据**有组织**地存放（分库、分表、分行列）。

结构示例：

    tlias（数据库）
      ├── user 表（id, username, name, age）
      └── dept 表（id, name）

一行 = 一条记录（一个用户 / 一个部门）。

## 三、什么是 MySQL
**数据库管理系统（DBMS）**&#8203; —— 管理数据库的软件。
- 你不直接翻仓库，而是**对 MySQL 说 SQL**，它替你存取
- MySQL 是**关系型**数据库：数据用**二维表**存，表与表之间能建关联
- 同类产品：Oracle、PostgreSQL、SQL Server

## 四、一句话记
**数据库是仓库，MySQL 是管理员，SQL 是你说的话。**&#8203;
表是书架，一行数据是一本书。

# MySQL 数据模型

## 一、关系型数据库（定义）
建立在**关系模型**基础上，由**多张相互连接的二维表**组成的数据库。

两个关键词：
- **二维表** —— 数据都放在表里
- **相互连接** —— 表与表之间有关系（不是孤立的）

## 二、两个特点（背这两句）

| 特点 | 说的是什么 |
|---|---|
| 使用**表**存储数据，**格式统一，便于维护** | 所有数据都是"行 + 列"，结构整齐 |
| 使用 **SQL 语言**操作，**标准统一，使用方便，可用于复杂查询** | 一种语言操作所有关系型库（MySQL/Oracle 通用） |

## 三、表与表怎么"连接"（看图）

**员工表 → 部门表**，靠**编号**对应：

员工表：

    编号   姓名     工作        部门
    1     金庸     总裁        5
    2     张无忌   教研主管     2
    3     杨逍     讲师        2
    4     韦一笑   讲师        2
    5     常遇春   讲师        2

部门表：

    编号   名称
    1     学工部
    2     教研部
    3     咨询部
    4     就业部
    5     校办

**读法：员工表"部门"列里存的是数字（如 5），拿它去部门表里找"编号 = 5"那一行，就知道是"校办"。**&#8203;

## 四、为什么这样设计？（关键理解）

| 方案 | 员工表里存什么 | 要改"教研部"的名字时 |
|---|---|---|
| 不关联 | 直接存 `"教研部"` | **改一堆行**，容易漏、容易写错 |
| **关联（现在）**&#8203; | 只存编号 `2` | **改部门表一行**，全部自动跟着变 |

**所以：数据分表存、靠编号连——改一处就够，这就是"便于维护"。**&#8203;

## 五、一句话记
**关系型数据库 = 一堆二维表，表之间靠"编号"连起来。**&#8203;
**存编号不存文字，改一次全跟着变。**&#8203;
