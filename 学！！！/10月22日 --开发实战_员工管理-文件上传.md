# 文件上传

## 一、前端页面三要素（缺一不可）

    <form action="/upload" method="post" enctype="multipart/form-data">
        姓名: <input type="text" name="name"> <br>
        年龄: <input type="text" name="age"> <br>
        图像: <input type="file" name="file"> <br>
        <input type="submit" value="上传文件" name="submit">
    </form>

| 序号  | 要素                              | 写在哪       | 不加会怎样                 |
| --- | ------------------------------- | --------- | --------------------- |
| ①   | `method="post"`                 | form 标签上  | GET 请求传不了文件体，直接失败     |
| ②   | `enctype="multipart/form-data"` | form 标签上  | 文件内容无法封装进请求，后端收到 null |
| ③   | `type="file"`                   | input 标签上 | 只是普通输入框，选不了文件         |

- **三要素是绑在一起的**：只加 `type="file"` 不改 enctype，照样传不上去
- 三个名字（`name`、`age`、`file`）就是后端接收的变量名

## 二、为什么必须改 enctype

form 表单默认的编码是 `application/x-www-form-urlencoded`，它只能拼成：

    name=张三&age=18

**纯文本键值对，装不下二进制文件内容。**&#8203;

改成 `multipart/form-data` 后，整个请求体被切成多段（每段叫一个 part）：

| part | 内容 |
|---|---|
| 第 1 段 | `name="name"` → 张三 |
| 第 2 段 | `name="age"` → 18 |
| 第 3 段 | `name="file"; filename="1.jpg"` → 文件二进制 + 文件类型 |

- 每段用 `boundary`（边界串）分隔，所以请求头里有 `Content-Type: multipart/form-data; boundary=----xxxx`
- 这也是为什么普通字段和文件能**放在同一个请求里一起传**

## 三、服务端接收

    @Slf4j
    @RestController
    public class UploadController {

        @PostMapping("/upload")
        public Result handleFileUpload(String name, Integer age, MultipartFile file) {
            log.info("文件上传:{}", file);
            return Result.success();
        }
    }

### 三个关键点

| 点 | 说明 |
|---|---|
| `@PostMapping("/upload")` | 路径和 form 的 `action="/upload"` 对应 |
| 普通字段 `String name, Integer age` | 照常按名字绑定，不用加注解 |
| 文件字段 **`MultipartFile file`** | 必须用这个类型，**不能**用 String 或 File |

### ⚠️ 参数名必须和前端 name 一致

    <input type="file" name="file">      ← 前端叫 file
    MultipartFile file                    ← 后端也叫 file

- 名字对不上 → 后端收不到文件，报 `Required request part 'file' is not present`
- 这就是课件那条红虚线想强调的

## 四、MultipartFile 常用方法（实战必备）

| 方法 | 作用 |
|---|---|
| `getOriginalFilename()` | 获取原始文件名（如 `1.jpg`） |
| `getSize()` | 文件大小，单位**字节** |
| `transferTo(File dest)` | 把文件保存到磁盘指定位置 |
| `getBytes()` | 拿到字节数组（适合传对象存储/OSS） |
| `getInputStream()` | 拿到输入流（适合大文件流式处理） |
| `isEmpty()` | 判断是否为空文件 |

### 一个最小的保存示例

    @PostMapping("/upload")
    public Result upload(MultipartFile file) throws IOException {
        String originalName = file.getOriginalFilename();
        file.transferTo(new File("D:/images/" + originalFilename));
        return Result.success();
    }

## 五、必须配的大小限制（默认很小）

SpringBoot 默认限制：

| 项 | 默认值 |
|---|---|
| 单个文件最大 | **1MB** |
| 单次请求最大 | **10MB** |

超过就抛 `MaxUploadSizeExceededException`。改配置：

    spring:
      servlet:
        multipart:
          max-file-size: 10MB        # 单个文件上限
          max-request-size: 100MB    # 整个请求上限

- 真实项目传图片/视频，这两个值基本都要调大

## 六、易错点

| 问题 | 报错 / 现象 |
|---|---|
| 忘写 `enctype="multipart/form-data"` | 后端 file 为 null，或 `Required request part 'file' is not present` |
| 前端 name 与后端参数名不一致 | 同上，收不到文件 |
| 文件字段声明成 `String file` | 类型转换失败 / 拿不到内容 |
| form 用了 `method="get"` | 文件根本发不出去 |
| 文件超过默认 1MB | `MaxUploadSizeExceededException` |
| `transferTo` 的目标目录不存在 | `FileNotFoundException` |
| 直接用原始文件名存盘 | 同名文件会被覆盖，还可能有路径穿越风险，要重命名成 UUID |

## 七、口诀

> **前端三要素：post 提交、multipart 编码、input 用 file 类型**
> **后端 MultipartFile 接，参数名和 name 一字不差**
> **默认只给 1MB，记得改 max-file-size**

# 文件上传 - 本地存储

## 一、这页要做的事

上一节只把文件"接住"了（`MultipartFile file`），文件其实还在**临时目录**里，请求结束就没了。
这一节要真正把它**存到服务器本地磁盘**，用一个自定义目录（图上是 `D:/images/`）永久保存。

一句话流程：

    MultipartFile → 取原始文件名 → 生成唯一文件名 → transferTo 写到磁盘

## 二、完整代码（图 1 重述）

    @PostMapping("/upload")
    public Result handleFileUpload(MultipartFile file) throws Exception {
        log.info("文件上传:{}", file);

        // 生成唯一文件名
        String uniqueFileName = generateUniqueFileName(file.getOriginalFilename());

        // 保存文件
        file.transferTo(new File("D:/images/" + uniqueFileName));

        return Result.success();
    }

    private String generateUniqueFileName(String originalFilename) {
        String randomStr = UUID.randomUUID().toString().replaceAll("-", "");
        String extension = originalFilename.substring(originalFilename.lastIndexOf("."));
        return randomStr + extension;
    }

⚠️ **课件笔误**：图上形参名是 `file`，但保存那句写成了 `image.transferTo(...)`。
`image` 这个变量根本不存在，正确写法是 `file.transferTo(...)`。

## 三、两个核心 API（图 2 思考题答案 ①）

| API | 作用 | 返回什么 |
|---|---|---|
| `file.getOriginalFilename()` | 获取**原始文件名** | `1.jpg` 这样的字符串 |
| `file.transferTo(File dest)` | 将文件**转存到磁盘文件** | void |

- `transferTo` 的参数是 `java.io.File`，所以要先 `new File(目录 + 文件名)` 拼出完整路径
- 声明了 `throws Exception`，因为 `transferTo` 会抛 `IOException`
- 目标目录**必须已存在**，`D:/images/` 不存在会抛 `FileNotFoundException`，需要先 `mkdirs()` 建目录

## 四、为什么要生成唯一文件名（重点）

如果直接用原始文件名存盘，会有四个问题：

| 问题 | 后果 |
|---|---|
| **同名覆盖** | 两个用户都传 `1.jpg` → 后一个把前一个覆盖掉 |
| **路径穿越** | 文件名传成 `../../etc/passwd` → 文件被写到目录外（安全漏洞） |
| **非法字符** | 中文、空格、`#`、`?` 等在某些系统/URL 里出问题 |
| **超长 / 信息泄露** | 原文件名可能很长，还可能暴露业务信息 |

所以统一改成：**随机串 + 原扩展名**，原始名只存数据库（或干脆不存）。

## 五、generateUniqueFileName 拆解

### ① 生成随机串

    String randomStr = UUID.randomUUID().toString().replaceAll("-", "");

- `UUID.randomUUID()` → 生成一个全局唯一的 UUID
- `.toString()` → 36 位字符串，形如 `9f8e7d6c-5b4a-4f0e-8c1d-2b3a4c5d6e7f`（带 **4 个横线**）
- `.replaceAll("-", "")` → 把横线全删掉，剩 **32 位**纯十六进制字符

### ② 取扩展名

    String extension = originalFilename.substring(originalFilename.lastIndexOf("."));

- `lastIndexOf(".")` → 最后一个点的下标（`1.jpg` → 返回值是 1）
- `substring(下标)` → 从该点开始截到末尾 → 得到 **`.jpg`**（**带点**！）
- 用 `lastIndexOf` 而不是 `indexOf`，因为 `my.photo.jpg` 要取最后一个点后面的部分

⚠️ 如果文件名**没有点**（如 `README`），`lastIndexOf` 返回 `-1`，`substring(-1)` 直接抛
`StringIndexOutOfBoundsException`。严谨写法要先判断 `>= 0`。

### ③ 拼接

    return randomStr + extension;      // 9f8e7d6c5b4a4f0e8c1d2b3a4c5d6e7f.jpg

### ④ 存盘

    file.transferTo(new File("D:/images/" + uniqueFileName));

- 最终路径 = 目录 + 唯一文件名，例：`D:/images/9f8e7d6c...e7f.jpg`
- **扩展名一定要保留**，否则图片在浏览器里无法识别类型

## 六、思考题 ② 上传文件大小受限怎么办

> 默认上传文件的最大大小为 **1MB**，超过大小需要在配置文件中配置。

    spring:
      servlet:
        multipart:
          max-file-size: 10MB        # 最大单个文件大小
          max-request-size: 100MB    # 最大请求总大小（包括所有文件和表单数据）

| 配置项 | 含义 | 默认值 |
|---|---|---|
| `max-file-size` | **单个文件**上限 | 1MB |
| `max-request-size` | **整个请求**上限（所有文件 + 表单字段） | 10MB |

- 两个都要调，只调 `max-file-size` 而请求总量超了照样报错
- 超限异常：`MaxUploadSizeExceededException`（返回给前端是 500 或 413）
- 记忆点：**单个看 max-file-size，总量看 max-request-size**

## 七、真实项目的改法（课件没写但要知道）

| 课件写法 | 生产建议 |
|---|---|
| `D:/images/` 硬编码 | 抽到 yml，如 `file.upload-dir: D:/images/`，用 `@Value` 注入 |
| Windows 盘符路径 | Linux 服务器没有 D 盘，部署到云上会失败 |
| 目录直接用 | 先 `new File(dir).mkdirs()`，否则报目录不存在 |
| 本地磁盘 | 多台服务器/集群时需要共享存储，一般换 **OSS / MinIO** 等对象存储 |
| 只存文件名 | 数据库里建议存**可访问的 URL** 或相对路径，前端才能拼出来 |
| 不校验类型 | 应校验扩展名/ContentType，防止上传 jsp、exe 等危险文件 |

## 八、易错点

| 问题 | 后果 |
|---|---|
| `image.transferTo(...)`（课件笔误） | 编译不过，`image` 未定义 |
| 目标目录不存在 | `FileNotFoundException: D:\images\xxx.jpg (系统找不到指定的路径)` |
| 用原始文件名直接存 | 同名覆盖 + 路径穿越漏洞 |
| `substring` 忘了带点 | 得到 `jpg` 而不是 `.jpg`，拼出来是 `xxxjpg` |
| 用 `indexOf(".")` 取点 | `my.photo.jpg` 会截成 `.photo.jpg`，错 |
| 文件名没有扩展名 | `substring(-1)` 抛 `StringIndexOutOfBoundsException` |
| 只配 `max-file-size` | 请求总量超 10MB 仍报 `MaxUploadSizeExceededException` |
| 忘了 `throws IOException` | 编译报错（未处理的受检异常） |

## 九、口诀

> **getOriginalFilename 取原名，transferTo 写磁盘**
> **原名不能直接用：UUID 去横线 + 扩展名（带点）**&#8203;
> **目录先建、路径别硬编码**
> **单文件 1MB 默认限，max-file-size 管单个、max-request-size 管总量**
