# 员工管理 - 条件分页查询（完整笔记）

## 一句话理解

> **条件分页 = 普通分页 + 4 个查询条件**
> 分页的事交给 PageHelper，条件的事交给 Mapper 的 XML，**两者互不干扰**

## 一、思路：请求到返回走一遍

| 步骤 | 谁在干 | 干什么 |
|---|---|---|
| 1 | 前端 | 发 `GET /emps?name=张&gender=1&begin=2007-09-01&end=2022-09-01` |
| 2 | EmpController | 接收 **6 个参数**（2 个分页 + 4 个条件）打日志后调 Service |
| 3 | EmpService | 用 **PageHelper** 分页，把 4 个条件原样传给 Mapper |
| 4 | EmpMapper + XML | 执行带 where 的 SQL，**不写 limit** |
| 5 | MySQL | 实际跑两条 SQL：`count` 算总数、`limit` 取本页 |
| 6 | 逐层返回 | XML → Mapper → Service 封装 PageResult → Controller 包 Result → 前端 |

**6 个参数分成两路，互不交叉：**

- `page` / `pageSize` → **PageHelper 内部消化**（自动拼 limit、自动生成 count），不写进 SQL
- `name` / `gender` / `begin` / `end` → **传给 Mapper**，在 XML 里拼 where

## 二、完整代码（可直接抄）

### ① PageResult（上一节已封装，直接复用）

    @Data
    @NoArgsConstructor
    @AllArgsConstructor
    public class PageResult<T> {
        private Long total;        // 总记录数
        private List<T> rows;      // 当前页数据

### ② EmpController

    @Slf4j
    @RestController
    @RequestMapping("/emps")
    public class EmpController {

        @Autowired
        private EmpService empService;

        @GetMapping
        public Result page(@RequestParam(defaultValue = "1") Integer page,
                           @RequestParam(defaultValue = "10") Integer pageSize,
                           String name, Integer gender,
                           @DateTimeFormat(pattern = "yyyy-MM-dd") LocalDate begin,
                           @DateTimeFormat(pattern = "yyyy-MM-dd") LocalDate end) {
            log.info("分页查询, 参数: {}, {}, {}, {}, {}, {}", page, pageSize, name, gender, begin, end);
            PageResult<Emp> pageResult = empService.page(page, pageSize, name, gender, begin, end);
            return Result.success(pageResult);
        }
    }

### ③ EmpService 接口

    public interface EmpService {
        PageResult<Emp> page(Integer page, Integer pageSize, String name,
                             Integer gender, LocalDate begin, LocalDate end);
    }

### ④ EmpServiceImpl（课件图里没给，按分页规则推导）

    @Service
    public class EmpServiceImpl implements EmpService {

        @Autowired
        private EmpMapper empMapper;

        @Override
        public PageResult<Emp> page(Integer page, Integer pageSize, String name,
                                    Integer gender, LocalDate begin, LocalDate end) {
            PageHelper.startPage(page, pageSize);                    // 1. 设置分页参数
            List<Emp> empList = empMapper.list(name, gender, begin, end);  // 2. 执行条件查询
            Page<Emp> p = (Page<Emp>) empList;                       // 3. 强转取总数
            return new PageResult<>(p.getTotal(), p.getResult());    // 4. 封装返回
        }
    }

### ⑤ EmpMapper 接口

    @Mapper
    public interface EmpMapper {
        public List<Emp> list(String name, Integer gender, LocalDate begin, LocalDate end);
    }

- 这里**没有 @Select 注解** → SQL 写到了 XML 里

### ⑥ EmpMapper.xml

    <?xml version="1.0" encoding="UTF-8" ?>
    <!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
    <mapper namespace="com.itheima.mapper.EmpMapper">
        <select id="list" resultType="com.itheima.pojo.Emp">
            select e.*, d.name as deptName
            from emp e left join dept d on e.dept_id = d.id
            where e.name like concat('%', #{name}, '%')
              and e.gender = #{gender}
              and e.entry_date between #{begin} and #{end}
        </select>
    </mapper>

### ⑦ application.yml 必须配

    mybatis:
      mapper-locations: classpath:mapper/*.xml
      configuration:
        map-underscore-to-camel-case: true

## 三、三个条件的写法（对照表）

| 条件 | SQL 片段 | 参数说明 |
|---|---|---|
| name | `e.name like concat('%', #{name}, '%')` | 用 **concat 拼 %**，Java 里只传"张" |
| gender | `e.gender = #{gender}` | 直接传 1 / 2 |
| begin、end | `e.entry_date between #{begin} and #{end}` | **一个条件占两个占位符**，含边界值 |

**为什么用 concat 而不是 `"%" + name + "%"`？**
`#{}` 是在 SQL 层面的占位符注入，不能写在字符串拼接里；直接在 SQL 里用 concat 拼更安全也更直观。

## 四、易错点清单

| 问题 | 后果 |
|---|---|
| 日期不加 `@DateTimeFormat` | 前端传 2007-09-01 直接 **400** |
| 日期格式写成 `2007/09/01` 或 `2007年09月01日` | Pattern 不匹配，400 |
| 忘了 concat 的 `%` | 只能查出名字**恰好**叫"张"的人 |
| XML 的 namespace 或 id 写错 | `Invalid bound statement (not found)` |
| yml 没配 mapper-locations | 同上，XML 找不到 |
| XML 里自己写了 `limit` | 和插件拼的 limit 冲突 |
| SQL 结尾加了分号 `;` | 拼接后语法错误 |
| 占位符个数 ≠ 参数个数 | 最后几个参数打不出来 / 绑定失败 |

⚠️ **遗留问题**：这条 SQL 是"四个条件都传"的静态写法，任意条件为 null 就查不出数据 → 下一步必须用**动态 SQL**（`<if>` + `<where>`）改造。

---

## 五、记忆口诀

> **二四分工：两个分页参数走插件，四个查询条件进 XML**
> **like 用 concat 戴百分号，between 吃两个占位符**
> **日期必须标 pattern，XML 不写 limit，结尾不带分号**

# 请求参数接收优化 · 方案（用对象封装）

## 一、为什么要改

> 如果 Controller 方法的参数较多，且未来可能继续增加，会使得**方法签名变得复杂难以维护**，此时可以考虑**将多个请求参数封装为一个对象**。

- 现状：上一节的 Controller 有 6 个形参，光注解就写了好几行
- 隐患：以后每加一个查询条件（比如按部门查、按状态查），方法签名就再长一截，改 Controller 要连带改 Service 签名
- 方案：**把 6 个参数打包成一个对象传**

## 二、请求参数长什么样

    /emps?name=张&gender=1&begin=2007-09-01&end=2022-09-01&page=1&pageSize=10

- 共 6 个参数，正好对应封装类的 6 个属性

## 三、EmpQueryParam 封装类

    @Data
    public class EmpQueryParam {
        private Integer page = 1;        // 当前页码
        private Integer pageSize = 10;   // 每页记录数
        private String name;             // 员工姓名
        private Integer gender;          // 员工性别
        @DateTimeFormat(pattern = "yyyy-MM-dd")
        private LocalDate begin;         // 入职日期
        @DateTimeFormat(pattern = "yyyy-MM-dd")
        private LocalDate end;           // 入职日期
    }

两处关键变化：

| 原来写在形参上 | 现在写在哪 |
|---|---|
| `@RequestParam(defaultValue = "1")` | **字段初始值** `= 1` |
| `@RequestParam(defaultValue = "10")` | **字段初始值** `= 10` |
| `@DateTimeFormat(pattern = ...)` | 挪到**字段**上 |

## 四、EmpController 改造后

    @GetMapping
    public Result page(EmpQueryParam empQueryParam) {
        log.info("分页查询, 参数: {}", empQueryParam);
        PageResult<Emp> pageResult = empService.page(empQueryParam);
        return Result.success(pageResult);
    }

- **形参上一个注解都没有**——这是本页最反直觉、也最容易写错的地方
- 原因：这是 GET 请求，参数在 URL 上，Spring 会**按属性名自动绑定**（调 setter），不需要 `@RequestBody`，也不需要 `@RequestParam`
- 如果手贱加了 `@RequestBody` → 报不支持的内容类型（400 / 415）

## 五、Service 层跟着改

    public interface EmpService {
        PageResult<Emp> page(EmpQueryParam param);
    }

    @Service
    public class EmpServiceImpl implements EmpService {

        @Autowired
        private EmpMapper empMapper;

        @Override
        public PageResult<Emp> page(EmpQueryParam param) {
            PageHelper.startPage(param.getPage(), param.getPageSize());   // 从对象里取分页参数
            List<Emp> empList = empMapper.list(param);                    // 对象整个传给 Mapper
            Page<Emp> p = (Page<Emp>) empList;
            return new PageResult<>(p.getTotal(), p.getResult());
        }
    }

    @Mapper
    public interface EmpMapper {
        public List<Emp> list(EmpQueryParam param);
    }

- Mapper 方法也从 4 个参数变成 1 个对象
- XML 里写法和之前完全一样：`#{name}`、`#{gender}`、`#{begin}`、`#{end}` 都是对象的属性名，不用改

## 六、注意事项

| 点 | 说明 |
|---|---|
| 参数名必须一致 | URL 的 `pageSize` 要能对上属性 `pageSize`，拼错就绑不上（静默为 null） |
| 必须有 setter | `@Data` 已生成，若手写类不能用 record（Spring 绑定需要 setter） |
| 不能加 @RequestBody | GET 请求，加了直接报错 |
| 日期格式仍要管 | `@DateTimeFormat` 不能省，否则 2007-09-01 解析失败 |
| 默认值只在"不传"时生效 | 前端传 `page=`（空值）可能绑定失败，前端要保证不传就不带这个 key |
| 放哪个包 | 一般放 `pojo` 或 `dto` 包，和 Emp 平级，命名 xxxQueryParam / xxxDTO |

## 七、两种方式怎么选

| 场景 | 推荐 |
|---|---|
| 参数 1~3 个且稳定 | 直接用 `@RequestParam` 散装 |
| 参数多、或未来会增 | **封装成 QueryParam 对象**（本项目就这么做） |
| 参数是 JSON 请求体（POST/PUT） | 用实体/对象接收 + `@RequestBody` |

## 八、口诀

> **参数一多就打包，Controller 只剩一行形参**
> **默认值写字段，日期注解搬字段，一个注解都不用挂**
> **Service 从对象取页码，Mapper 整个对象往下传**

# 员工管理 - 动态 SQL（解决条件写死）

## 一、问题：现在的 SQL 是写死的

上一节的 EmpMapper.xml 里，where 三个条件是**固定写上去的**：

    where e.name like concat('%', #{name}, '%')
      and e.gender = #{gender}
      and e.entry_date between #{begin} and #{end}

但真实页面上，查询栏是这样的：

| 查询项 | 控件 | 用户可能不填 |
|---|---|---|
| 姓名 | 输入框 | ✅ 可以空 |
| 性别 | 下拉框 | ✅ 可以"请选择" |
| 入职时间 | 开始日期 ~ 结束日期 | ✅ 可以都不选 |

**所以实际会出现的 SQL 有好几种：**

    select * from emp e ... where e.name like ?
    select * from emp e ... where e.gender = ?
    select * from emp e ... where e.name like ? and e.gender = ?
    select * from emp e ... where e.gender = ? and e.entry_date between ? and ?

- 只剩姓名 → 不该有 gender 条件
- 只剩性别 → 不该有 name 条件
- 三个可选条件（name、gender、时间范围）→ 最多 **8 种组合**，不可能写 8 条 SQL

**结论：SQL 必须能"按条件动态拼"，这就是动态 SQL。**&#8203;

## 二、动态 SQL 是什么

> **随着用户的输入或外部条件的变化而变化的 SQL 语句，我们称为动态 SQL。**&#8203;

MyBatis 提供了两个标签来解决这个问题：

| 标签 | 作用 |
|---|---|
| `<if>` | 判断条件是否成立，**成立（true）才拼接这段 SQL** |
| `<where>` | 根据查询条件**生成 where 关键字**，并**自动去除条件前面多余的 and 或 or** |

## 三、`<if>` 单独看

    <if test="gender != null">
        and e.gender = #{gender}
    </if>

- `test` 里写的是**判断表达式**，为 true 才把里面的 SQL 拼进去
- `test` 里的名字是**参数对象的属性名**（因为传进来的是 `EmpQueryParam`，所以直接写 `gender`，不用 `param.gender`）

### test 里怎么写判断

| 字段类型 | 判断写法 | 说明 |
|---|---|---|
| Integer（gender） | `gender != null` | 数字只需判 null |
| String（name） | `name != null and name != ''` | **null 和空串都要判** |
| LocalDate（begin/end） | `begin != null and end != null` | 两个条件必须同时成立 |

- 逻辑运算符用 `and` / `or`，**不是** `&&` / `||`
- 不等号写 `!=` 即可

## 四、`<where>` 为什么必须有

如果只用 `<if>` 不加 `<where>`，会拼出这种坏 SQL：

    ... d.id where and e.gender = ?        ← 多了一个 and，语法错误

`<where>` 帮你做两件事：

1. 有内容时**自动补上 `where` 关键字**
2. 自动**删掉开头多余的 `and` / `or`**

举例：用户只填了性别

| 阶段 | SQL 片段 |
|---|---|
| if 拼出来的 | `and e.gender = #{gender}` |
| where 处理后 | `where e.gender = ?` |

- 注意只删**开头**那一个，中间的 and 不受影响
- 如果三个条件全不成立 → `<where>` 内部为空 → **连 where 关键字都不生成**，直接查全部（这是正确行为，不是 bug）

## 五、完整代码

### EmpMapper.xml（最终版）

    <?xml version="1.0" encoding="UTF-8" ?>
    <!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
    <mapper namespace="com.itheima.mapper.EmpMapper">

        <select id="list" resultType="com.itheima.pojo.Emp">
            SELECT e.*, d.name AS deptName
            FROM emp e LEFT JOIN dept d ON e.dept_id = d.id
            <where>
                <if test="name != null and name != ''">
                    e.name like concat('%',#{name},'%')
                </if>
                <if test="gender != null">
                    and e.gender = #{gender}
                </if>
                <if test="begin != null and end != null">
                    and e.entry_date between #{begin} and #{end}
                </if>
            </where>
            order by e.update_time desc
        </select>

    </mapper>

### Mapper 接口 / Service / Controller（都不用改）

    @Mapper
    public interface EmpMapper {
        public List<Emp> list(EmpQueryParam param);
    }

    @Override
    public PageResult<Emp> page(EmpQueryParam param) {
        PageHelper.startPage(param.getPage(), param.getPageSize());
        List<Emp> empList = empMapper.list(param);
        Page<Emp> p = (Page<Emp>) empList;
        return new PageResult<>(p.getTotal(), p.getResult());
    }

- **动态 SQL 只改 XML 一个文件**，Java 三层代码一行不动
- PageHelper 依然生效，count 会按动态条件生成（where 相同，total 才准）

## 六、四个细节

- **第一个 `<if>` 里没写 and** → 因为它是第一个，写了也会被 where 删掉，但不写更直观
- **`</where>` 后面才接 order by**，别把 order by 写进 where 标签里
- **begin 和 end 必须一起判断**：只判一个的话，另一个为 null 会让 `between null and xxx` 查出空结果
- **`<if test="...">` 里的字符串比较用单引号**：`name != ''`（外层是双引号，内层用单引号，不冲突）

## 七、易错点

| 问题 | 后果 |
|---|---|
| `<if>` 里的 SQL 之间**漏写 and** | 两个条件拼起来变成 `where e.name like ? e.gender = ?` 语法错 |
| String 只判 `!= null` 不判 `!= ''` | 前端传空串 `name=` 时会拼上 `like '%%'`，虽然不报错但查询白跑 |
| 写了 `<if>` 却忘了 `<where>` | 出现 `where and ...` 或干脆没有 where |
| test 里写成 `#{name} != null` | test 里不写 `#{}`，直接写属性名 |
| test 里用 `&&` | 解析失败，要用 `and` |
| 在 `</where>` 里写 order by | 排序会被当条件处理，可能被误删 |
| XML 里写 `<` `>` 不转义 | 解析报错，要写 `&lt;` `&gt;`（或用 `<![CDATA[ ]]>`） |

## 八、口诀

> **条件会变 → 动态 SQL；`<if>` 判真假，`<where>` 补 where 删 and**
> **字符串判 null 还要判空串，日期两个必须一起判**
> **只改 XML，不改 Java；全空不拼条件，直接查全部**
