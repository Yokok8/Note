# DML（数据操作语言）

## 一、一句话定义
**DML 英文全称是 Data Manipulation Language（数据操作语言），用来对数据库中表的数据记录进行增、删、改操作。**&#8203;

关键词  **“表的数据记录”** &#8203; —— 作用对象是**表里的行**，不是表结构。

## 二、三个操作

| 操作 | 英文 | 对应 SQL |
|---|---|---|
| 添加数据 | **INSERT** | `insert into ...` |
| 修改数据 | **UPDATE** | `update ... set ...` |
| 删除数据 | **DELETE** | `delete from ...` |

**口诀：增 INSERT、改 UPDATE、删 DELETE —— 还记得 `CRUD` 里除了 R，剩下三个就是它。**&#8203;

## 三、和 DDL 划清界限（最容易混）

| | DDL | DML |
|---|---|---|
| 管什么 | **结构**：库、表、字段 | **数据**：表里的记录行 |
| 例子 | `create table`、`alter table`、`drop table` | `insert`、`update`、`delete` |
| 打个比方 | **画表格、改表格边框** | **往格子里填字、改字、擦字** |

一句话：**DDL 动"骨架"，DML 动"血肉"。**&#8203;

## 四、对照你以后要写的代码
| DML 操作 | 对应前端/接口 |
|---|---|
| `INSERT` | 新增用户的按钮 → `POST /users` |
| `UPDATE` | 编辑弹窗的保存 → `PUT /users` |
| `DELETE` | 列表里的删除 → `DELETE /users/1` |

后面写 SpringBoot 案例时，Dao 层写的 SQL 就是这三样。

## 五、一句话记
**DML = 数据操作语言，管表里那一行行记录：INSERT 增、UPDATE 改、DELETE 删。**&#8203;
**DDL 管结构，DML 管数据。**&#8203;

# DML —— insert 添加数据

## 一、四种写法（背这张表）

| 写法 | 语法 |
|---|---|
| **指定字段** | `insert into 表名(字段名1, 字段名2) values (值1, 值2);` |
| **全部字段** | `insert into 表名 values (值1, 值2, ...);` |
| **批量（指定字段）**&#8203; | `insert into 表名(字段名1, 字段名2) values (值1, 值2), (值1, 值2);` |
| **批量（全部字段）**&#8203; | `insert into 表名 values (值1, 值2, ...), (值1, 值2, ...);` |

**只有两个变量：**
1. 表名后面**带不带 `(字段名)`** → 决定是"指定字段"还是"全部字段"
2. `values` 后面**一组括号还是多组括号** → 决定是"单条"还是"批量"

所以四种写法不用背，**是这两个变化组合出来的**。

## 二、对照例子

    -- 指定字段：只给 id 和 name，其余字段走默认值 / 允许为 null
    insert into tb_user(id, name) values (1, '令狐冲');

    -- 全部字段：值的顺序必须和建表时字段顺序完全一致
    insert into tb_user values (2, 'yin', '殷天正', 55, '男');

    -- 批量（指定字段）
    insert into tb_user(id, name) values (3, '张三'), (4, '李四');

    -- 批量（全部字段）
    insert into tb_user values (5,'li','李四',20,'男'), (6,'wang','王五',25,'男');

## 三、课件三条注意（原文，必须记住）

| # | 注意 |
|---|---|
| 1 | 插入数据时，**指定的字段顺序需要与值的顺序是一一对应的** |
| 2 | **字符串和日期型数据应该包含在引号中**（单引号、双引号都可以） |
| 3 | 插入的数据**大小 / 长度，应该在字段的规定范围内** |

第 1 条是最容易出错的：**`(name, age)` 配 `('张三', 23)` 才对；
写成 `(name, age)` 配 `(23, '张三')` 语法不报错，但数据全错位了 —— 这种错很隐蔽。**

## 四、易错点（补充）

| # | 坑 |
|---|---|
| 1 | **全字段写法不能漏字段** —— 值的个数必须等于表的字段个数，少一个就报错 |
| 2 | **全字段写法的顺序 = 建表时的字段顺序**，不是你随便排的（写错就串列） |
| 3 | **批量插入用逗号分隔多组括号**，最后一组后面**不加逗号** |
| 4 | **有自增主键（`auto_increment`）时，主键字段可以不写** —— MySQL 自动给值 |
| 5 | **有非空约束的字段必须给值**，否则报错；有 `default` 的字段不写就用默认值 |
| 6 | **日期值也要加引号**：`'2026-10-07'`；也可以用 `now()` 取当前时间 |
| 7 | **批量插入比一条条插快得多** —— 一次网络往返 vs N 次，数据量大时差别明显 |
| 8 | `insert into` 的 `into` **可以省略**，但建议写上（可读性好） |

## 五、一句话记
**`insert into 表名(字段) values (值);` —— 有没有字段列表，决定"指定字段"还是"全部字段"；几组括号，决定单条还是批量。**&#8203;
**顺序要对齐、字符串和日期加引号、长度别超，这三条踩了必报错或必串列。**&#8203;

# DML —— update 修改数据

## 一、语法

    update 表名 set 字段名1 = 值1 , 字段名2 = 值2 , .... [ where 条件 ] ;

三段拆解：

| 部分 | 作用 |
|---|---|
| `update 表名` | 改哪张表 |
| `set 字段名 = 值` | 改成什么（多列用**逗号**分隔） |
| `[where 条件]` | **改哪些行**（可选，但必须写） |

## 二、课件注意（原文，最重要的一条）
**修改语句的条件可以有，也可以没有，如果没有条件，则会修改整张表的所有数据。**&#8203;

| 写法 | 结果 |
|---|---|
| `update tb_user set name='A' where id=1;` | **只改 id=1 那一行** |
| `update tb_user set name='A';` | **3 行全被改成 A** |

👉 **`where` 不是"可选的装饰"，它是"安全阀"。**&#8203; 少写一次，整张表的数据就全废了 —— 这是运维圈里最经典的事故类型之一。

## 三、常见写法

    -- 改一行的一个字段
    update tb_user set name = '张三' where id = 1;

    -- 改一行的多个字段（逗号分隔，最后一个不加逗号）
    update tb_user set name = '张三', age = 23 where id = 1;

    -- 按条件批量改（符合条件的所有行）
    update tb_user set gender = '女' where age > 30;

## 四、易错点

| # | 坑 |
|---|---|
| 1 | **忘写 `where` → 改全表**。习惯：先写 `where` 再回头补 `set`，或者写完先 `select` 验证条件 |
| 2 | **`set` 里多个赋值用逗号分隔**，最后一个**不能加逗号** |
| 3 | **字符串值必须加引号**：`set name = '张三'`，写成 `= 张三` 会当成列名 → 报 `Unknown column` |
| 4 | **判断 null 不能用 `=`**，要用 `is null`：`where name is null`，写 `= null` 永远查不到 |
| 5 | **`where` 条件写得太宽会误伤**，比如 `where age > 20` 可能匹配一堆行；先用 `select` 确认命中几条 |
| 6 | 修改主键值要谨慎 —— 它可能被别的表引用着 |
| 7 | 生产环境执行前先 **备份** 或 **开启事务**（`begin` → 确认 → `commit` / 出错 `rollback`） |

## 五、一句话记
**`update 表名 set 字段 = 值, 字段 = 值 where 条件;`**
**`where` 决定"改谁" —— 忘了它，就是给全表洗了个改。**&#8203;

# DML —— delete 删除数据

## 一、语法

    delete from 表名 [ where 条件 ] ;

| 部分 | 作用 |
|---|---|
| `delete from 表名` | 从哪张表删 |
| `[where 条件]` | **删哪些行**（可选，但必须写） |

⚠️ **注意 `delete from` 中间没有 `*`** —— 删的是"行"，不是"列"，所以不需要指定字段。
（`delete * from` 是**语法错误**，这是从 `select *` 顺手写错的高频坑）

## 二、课件两条注意（原文）

| # | 注意 |
|---|---|
| 1 | DELETE 语句的条件**可以有，也可以没有**，如果**没有条件，则会删除整张表的所有数据** |
| 2 | DELETE 语句**不能删除某一个字段的值**（如果要操作，可以使用 **UPDATE**，将该字段的值置为 **NULL**） |

### 第 2 条怎么理解
**DELETE 的删除单位是"行"，不是"列"。**&#8203;

| 我想做 | 该用 |
|---|---|
| 删掉"张三"这个人（整行记录） | `delete from tb_user where name = '张三';` |
| 把"张三的年龄"这个值清空，人还留着 | `update tb_user set age = null where name = '张三';` |

**删行用 DELETE，清空某个字段的值用 UPDATE ... SET 字段 = NULL。**&#8203;

## 三、三种"删除"的对比（高频考点）

| | `delete from` | `truncate table` | `drop table` |
|---|---|---|---|
| 属于 | **DML** | DDL | DDL |
| 删什么 | **行**（可加 where 挑着删） | **全部行**（不能加 where） | **表和结构一起删** |
| 表结构 | 保留 | 保留 | **没了** |
| 自增计数器 | **不重置** | **重置回 1** | 表都没了 |
| 能否回滚 | **能**（事务里） | 不能 | 不能 |
| 速度 | 慢（逐行删、记日志） | 快 | 快 |
| 典型用法 | 删指定数据 | 清空测试表 | 废弃整张表 |

记忆：**DELETE 一勺一勺挖，TRUNCATE 整锅倒掉但锅还在，DROP 连锅一起扔。**&#8203;

## 四、易错点
1. **忘写 `where` → 整表数据清空**（表还在，但一行不剩）
   - 保命习惯：**先 `select` 出要删的数据确认，再把 `select *` 换成 `delete`**
2. **`delete * from` 是错的** —— 没有 `*` 这个写法
3. **DELETE 后自增主键不重置** —— 删光后新插入的 id 会接着之前的号往下走（想重置用 `truncate`）
4. **`where` 里删 null 要用 `is null`**（`delete from tb_user where name is null;`）
5. **DELETE 也要加引号**：`where name = '张三'`，字符串漏引号会报 `Unknown column`
6. **想保留表结构又清空数据** → 用 `truncate table 表名;`（更快），但**没有 where**，慎用
7. **有外键引用时可能删不掉** —— 会报外键约束错误（这也是外键实际项目少用的原因之一）
8. 生产环境删除前**先备份 / 开事务**：`begin;` → `delete ...` → 确认无误 `commit;`，出错 `rollback;`

## 五、一句话记
**`delete from 表名 where 条件;` —— 删的是"行"，不是"列"，所以没有 `*`。**&#8203;
**忘写 where 就清空整张表；想清空某个字段的值，得用 UPDATE 置 NULL。**&#8203;
