# 多线程入门 —— 进程 & 线程

## 官方定义（背下来）

| 概念 | 定义 |
|---|---|
| **进程** | 进程是**程序的基本执行实体** |
| **线程** | 线程是操作系统能够进行**运算调度的最小单位**。它被包含在**进程**之中，是进程中的**实际运作单位** |

> 划重点：**线程被包含在进程之中** —— 一个进程可以有多个线程，但一个线程一定属于某个进程。

简单理解：线程：应用软件中互相独立，可以同时运行的功能

---

## 一张表看懂区别

| | **进程（Process）**&#8203; | **线程（Thread）**&#8203; |
|---|---|---|
| 是什么 | 程序的基本执行实体 | 运算调度的最小单位 |
| 地位 | **资源分配**的基本单位 | **CPU 调度**的基本单位 |
| 内存 | 有**独立**内存空间 | **共享**所属进程的内存 |
| 切换成本 | 大（要换整个内存空间） | 小（只换执行路径） |
| 通信方式 | 麻烦（需要进程间通信 IPC） | 简单（直接读写共享变量） |
| 数量级 | 少（几十个） | 多（成百上千个） |
| 崩溃影响 | 一个进程挂了不影响别的 | **一个线程挂了，整个进程可能全挂** |

---

## 生活类比（最好记）

| 现实 | 对应 |
|---|---|
| 一家工厂 | **进程** |
| 工厂里的工人 | **线程** |
| 工厂的场地、水电、仓库 | 进程的**内存和系统资源**（所有工人共用） |
| 工人越多干得越快，但抢工具会打架 | 线程越多并发越高，但**共享资源会出线程安全问题** |

> **一句话**：进程是"分资源的单位"，线程是"干活的单位"。

---

## Java 里的体现

```java
public class Demo {
    public static void main(String[] args) {
        // 这行代码跑在「主线程」里
        System.out.println("Hello");
    }
}
```


# 并发 & 并行（一字之差，本质不同）

## 官方定义（要背的原话）

| 概念 | 定义 |
|---|---|
| **并发** | 在同一时刻，有多个指令在**单个 CPU** 上**交替执行** |
| **并行** | 在同一时刻，有多个指令在**多个 CPU** 上**同时执行** |

## 抓关键词（考试的得分点）

| 概念 | CPU 数量 | 执行方式 |
|---|---|---|
| 并发 | **单个** CPU | **交替**执行 |
| 并行 | **多个** CPU | **同时**执行 |

> 记忆钩子：**并发 = 交替（一个 CPU 轮流伺候）；并行 = 同时（多个 CPU 各干各的）。**&#8203;

---

## 最直观的生活类比

| 现实场景 | 类型 |
|---|---|
| 一个厨师同时炒 3 个菜（炒一下这个、翻一下那个） | **并发** |
| 3 个厨师各炒一个菜，同时进行 | **并行** |
| 一个人一边吃饭一边刷手机（手交替做两件事） | **并发** |
| 两个人，一个吃饭、一个刷手机 | **并行** |
| 一个收银台排两队（交替收银） | **并发** |
| 三个收银台各排一队 | **并行** |

---

## 深入理解：一个是"看起来同时"，一个是"真的同时"

| | 并发 | 并行 |
|---|---|---|
| 宏观（你看上去） | 像同时在跑 | 同时在跑 |
| 微观（CPU 眼里） | **同一时刻只有一个在跑**，只是切换快到你看不出来 | **同一时刻真的有好几个在跑** |
| 本质 | **逻辑上**的同时 | **物理上**的同时 |
| 单核 CPU 能做吗 | ✅ 能 | ❌ 不能 |
| 多核 CPU 能做吗 | ✅ 能 | ✅ 能 |

💡 **重要结论**：
- **单核 CPU 只能并发，不能并行**
- **多核 CPU 既能并发也能并行**（线程数 > 核数时，两种同时存在）

---

## 对 Java 程序员意味着什么？

你写多线程代码时，**不需要关心底层是并发还是并行**：

```java
new Thread(() -> System.out.println("任务A")).start();
new Thread(() -> System.out.println("任务B")).start();
```


# 多线程的启动方式

## 多线程的第一种启动方式：继承 Thread

### 三步走（背下来）

1. 自己定义一个类继承 Thread
2. 重写 run 方法
3. 创建子类的对象，并启动线程

---

### 完整代码

```java
// 第一步：定义一个类继承 Thread
public class MyThread extends Thread {

    // 第二步：重写 run 方法（线程要干的活写这里）
    @Override
    public void run() {
        for (int i = 1; i <= 100; i++) {
            System.out.println(getName() + "执行第 " + i + " 次");
        }
    }
}
```

```java
// 第三步：创建对象并启动
public class Demo {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        MyThread t2 = new MyThread();

        t1.setName("线程1");     // 给线程起名字
        t2.setName("线程2");

        t1.start();              // ⚠️ 是 start()，不是 run()
        t2.start();
    }
}
```

# 多线程的第二种启动方式：实现 Runnable

## 四步走（比第一种多一步）

1. 自己定义一个类实现 Runnable 接口
2. 重写里面的 run 方法
3. 创建自己的类的对象 ← 多出来的这一步
4. 创建一个 Thread 类的对象，并开启线程


---

## 完整代码

```java
// 第一步：定义一个类实现 Runnable 接口
public class MyRun implements Runnable {

    // 第二步：重写里面的 run 方法
    @Override
    public void run() {
        for (int i = 1; i <= 100; i++) {
            // ⚠️ 不能直接写 getName()！见下面说明
            System.out.println(Thread.currentThread().getName() + "执行第 " + i + " 次");
        }
    }
}
```

```java
public class Demo {
    public static void main(String[] args) {
        // 第三步：创建 MyRun 的对象（表示多线程要执行的任务）
        MyRun mr = new MyRun();

        // 第四步：创建线程对象，把任务对象传进去
        Thread t1 = new Thread(mr);
        Thread t2 = new Thread(mr);

        // 给线程设置名字
        t1.setName("线程1");
        t2.setName("线程2");

        // 开启线程
        t1.start();
        t2.start();
    }
}
```

# 多线程的第三种实现方式：实现 Callable

> **特点：可以获取到多线程运行的结果**（前两种拿不到返回值）

## 五步走（比前两种都多）

1. 创建一个类 MyCallable 实现 Callable 接口
2. 重写 call 方法（是有返回值的，表示多线程运行的结果）
3. 创建 MyCallable 的对象（表示多线程要执行的任务）
4. 创建 FutureTask 的对象（作用：管理多线程运行的结果）
5. 创建 Thread 类的对象，并启动（表示线程）


**和前两种对照：**

| | 继承 Thread | 实现 Runnable | **实现 Callable** |
|---|---|---|---|
| 任务方法 | `run()` | `run()` | **`call()`** |
| 有没有返回值 | ❌ | ❌ | ✅ **有** |
| 能不能抛异常 | ❌ | ❌ | ✅ 可以 |
| 要不要中间对象 | 不要 | 不要 | ✅ **要 FutureTask** |
| 取结果 | 取不到 | 取不到 | `ft.get()` |

---

## 完整代码

```java
// 第一步：定义类实现 Callable 接口
// ⚠️ Callable<V> 是泛型接口，V 就是 call() 的返回类型
public class MyCallable implements Callable<Integer> {

    // 第二步：重写 call（有返回值，还能抛异常）
    @Override
    public Integer call() throws Exception {
        int sum = 0;
        for (int i = 1; i <= 100; i++) {
            sum += i;
        }
        System.out.println(Thread.currentThread().getName() + " 算完了");
        return sum;      // ← 这个值会被 FutureTask 收走
    }
}
```

```java
public class Demo {
    public static void main(String[] args)
            throws ExecutionException, InterruptedException {   // ⚠️ 要处理两个异常

        // 第三步：创建任务对象
        MyCallable mc = new MyCallable();

        // 第四步：创建 FutureTask 对象（管理结果）
        FutureTask<Integer> ft = new FutureTask<>(mc);

        // 第五步：创建线程对象并启动
        Thread t1 = new Thread(ft);
        t1.setName("计算线程");
        t1.start();

        // 获取多线程运行的结果（会阻塞，直到 call() 跑完）
        Integer result = ft.get();
        System.out.println("结果是：" + result);   // 5050
    }
}
```

# 多线程三种实现方式对比（优缺点）

## 课件的原表

| | 优点 | 缺点 |
|---|---|---|
| **继承 Thread 类** | 编程比较简单，可以直接使用 Thread 类中的方法 | 可以扩展性较差，不能再继承其他的类 |
| **实现 Runnable 接口** | 扩展性强，实现该接口的同时还可以继承其他的类 | 编程相对复杂，不能直接使用 Thread 类中的方法 |
| **实现 Callable 接口** | 同上 | 同上 |

---

## 一图看懂：优缺点其实是"一体两面"

**核心矛盾只有一句话：继承名额只有一个。**&#8203;

|                 | 继承 Thread       | 实现 Runnable / Callable                |
| --------------- | --------------- | ------------------------------------- |
| `extends` 名额    | **被 Thread 占了** | **留着**（可以 extends 别的类）                |
| `implements` 名额 | 空着（还能实现别的接口）    | 被占用（但接口能实现多个，问题不大）                    |
| 想用 `getName()`  | 直接写             | 得用 `Thread.currentThread().getName()` |

> **结论：继承 Thread 是"用继承名额换方便"，实现接口是"用一点麻烦换自由度"。**&#8203;

---

## ⚠️ 重要补充：那句"不能直接使用 Thread 类中的方法"要打个折扣

课件说实现接口的学生"不能直接使用 Thread 类中的方法"，这句话其实**不完整**。准确说是：

| Thread 方法类型 | 实现接口的方式能否用 |
|---|---|
| **实例方法**（`getName()` / `setName()` / `getPriority()`） | ❌ 不能直接调用（没有 this 可继承） |
| **静态方法**（`Thread.currentThread()` / `Thread.sleep()` / `Thread.yield()`） | ✅ **完全能用！** |

```java
// ❌ 编译报错：找不到符号
System.out.println(getName());

// ✅ 静态方法谁都调得动，拿到当前线程对象再操作
Thread t = Thread.currentThread();
System.out.println(t.getName());

// ✅ 睡眠更是天天用
Thread.sleep(1000);
