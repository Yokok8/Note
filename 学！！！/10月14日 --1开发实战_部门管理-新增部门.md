# 新增部门 · 思路分析

## 一、接口文档（先看这个再写代码）
| 项 | 值 |
|---|---|
| 请求路径 | /depts |
| 请求方式 | **POST** |
| 接口描述 | 该接口用于添加部门数据 |
| 请求参数格式 | **application/json** |
| 参数 | name（string） |
| 请求样例 | { "name": "教研部" } |

注意和查询/删除的区别：**参数不再是 `?id=8`，而是放在请求体里的 JSON** → 后面代码里要用 `@RequestBody` 接收。

## 二、三层架构职责
| 层 | 职责 | 说明 |
|---|---|---|
| **Controller** | ① 接收请求参数（/depts）② 调用 Service 层 ③ 响应结果 | 收到 JSON 里的 name |
| **Service** | ① **补全基础属性** ② 调用 Mapper 接口方法 | ⭐ 本页核心 |
| **Mapper** | 执行 insert SQL | 把 3 个字段写进表 |

## 三、⭐ 什么是"补全基础属性"
前端只传了一个 name：
    { "name": "教研部" }

但 dept 表要 3 个非空字段：name、create_time、update_time。
**创建时间和修改时间由后端补上**（取当前时间），这就是 Service 层的活：

| 字段 | 谁负责填 | 值 |
|---|---|---|
| name | 前端传 | 教研部 |
| createTime | **Service 补** | 当前时间 |
| updateTime | **Service 补** | 当前时间 |

**为什么要 Service 补**：时间应该以**服务器为准**，不能信前端传的（客户端时间可能不准、也可能被篡改）。

## 四、Mapper 的 SQL
    insert into dept (name, create_time, update_time) values (?,?,?)

- 表名 dept，括号里是**要插入的字段**
- 三个 `?` 对应三个字段的值 —— 注意是 **3 个**，不是 1 个（很多人以为只传了 name 就只写一个）
- 注解写法里对应 `#{name}`、`#{createTime}`、`#{updateTime}`

## 五、三层数据形态变化
前端 JSON {name:"教研部"} → Controller 收到 name → Service **补成完整 Dept 对象** → Mapper 把 3 个值写库

一句话：**进来时是半成品，交给 Mapper 前必须补成完整对象。**&#8203;

## 六、易错点
| 易错 | 说明 |
|---|---|
| 只插 name 一个字段 | 表里 create_time 非空 → 插入失败 |
| 时间由前端传 | 应该后端补，更可靠 |
| 用 @RequestParam 接 | JSON 在请求体里，必须用 **@RequestBody** |
| insert 字段和值个数对不上 | 报 Column count doesn't match value count |
| 忘了给 Dept 对象赋值就传下去 | 入库字段为 null |

## 七、口诀
- **POST 传 JSON，@RequestBody 接**
- **前端只给 name，时间和属性后端补**
- **insert 三个字段三个值，一一对应不能错**

# Controller 接收 JSON 参数（@RequestBody）

## 一、场景
    POST  /depts
    请求体：{ "name": "教研部" }

参数不在 URL 里，而在**请求体**里。

## 二、两条规则（课件原文）
1. JSON 格式的参数，通常会使用一个**实体对象**进行接收
2. JSON 数据的**键名**与方法形参对象的**属性名相同**，并需要使用 **@RequestBody** 注解标识

## 三、代码
    @PostMapping("/depts")
    public Result add(@RequestBody Dept dept){
        System.out.println("添加部门： " + dept);
        deptService.add(dept);
        return Result.success();
    }

- `@PostMapping("/depts")`：只接 POST 请求
- `@RequestBody`：告诉 Spring **从请求体里读 JSON**，并自动转成 Dept 对象
- 一个 Dept 对象顶一堆参数，所以叫"**用实体对象接收**"

## 四、配套的实体类
    public class Dept {
        private Integer id;
        private String name;              // ← 前端只传这个
        private LocalDateTime createTime;
        private LocalDateTime updateTime;
    }

对照关系：
| JSON 键名 | Dept 属性名 | 结果 |
|---|---|---|
| name | name | ✔ 匹配，能接收 |
| （没传） | id | 值为 null |
| （没传） | createTime | 值为 null |
| （没传） | updateTime | 值为 null |

**关键**：进 Controller 时这个 dept 对象是"半成品"，后面 Service 要把时间补上。

## 五、@RequestBody vs @RequestParam（重要对比）
| | @RequestParam | @RequestBody |
|---|---|---|
| 数据在哪 | URL 的 `?` 后面 | **请求体**里 |
| 典型格式 | /depts?id=8 | { "name": "教研部" } |
| 内容类型 | 表单/查询字符串 | **application/json** |
| 用在 | 查询、删除 | **新增、修改** |

记忆法：**参数在 URL 上用 RequestParam，参数在请求体里用 RequestBody。**&#8203;

## 六、兜底机制：对象靠什么接收 JSON
Spring 底层用 **Jackson**（HttpMessageConverter）把 JSON 字符串转成 Java 对象，靠的是：
- 属性有 **getter/setter**（Lombok 的 @Data 自动生成）
- 键名与属性名匹配（也可以用 @JsonProperty 指定）

所以 Dept 上必须加 `@Data`，否则接不到值。

## 七、易错点
| 易错 | 说明 |
|---|---|
| 忘了写 @RequestBody | 接不到值，dept 里全是 null（不报错） |
| JSON 键名写成 deptName | 和属性 name 对不上 → null，**静默失败最坑** |
| 用 @RequestParam 接 JSON | 报错 400 或接不到 |
| 忘了加 @Data | 没有 setter，Jackson 赋不进值 |
| 前端没设 Content-Type | 后端解析不了，报 415 |

## 八、口诀
- **JSON 参数用对象接，注解必须 @RequestBody**
- **键名 = 属性名，才对得上**
- **URL 上的用 RequestParam，身上的用 RequestBody**

# 新增部门 · 功能实现（三层完整代码）

## 一、DeptController
    @PostMapping("/depts")
    public Result add(@RequestBody Dept dept){
        System.out.println("添加部门： " + dept);
        deptService.add(dept);
        return Result.success();
    }
- @PostMapping：只接 POST
- @RequestBody：从请求体读 JSON → 转成 Dept 对象
- 打印 dept 能用是因为 @Data 自动生成了 toString

## 二、DeptServiceImpl（本页核心）
    @Override
    public void add(Dept dept) {
        dept.setCreateTime(LocalDateTime.now());
        dept.setUpdateTime(LocalDateTime.now());
        deptMapper.add(dept);
    }
**这就是"补全基础属性"**&#8203;：
| 顺序 | 动作 | 对象状态 |
|---|---|---|
| ① 进来时 | 只有 name 有值 | createTime / updateTime 为 null |
| ② set 两个时间 | LocalDateTime.now() | 三个属性都有值 |
| ③ 传给 Mapper | deptMapper.add(dept) | 能完整入库 |

**关键**：set 必须写在 `deptMapper.add(dept)` **之前**，顺序反了入库还是 null。
`LocalDateTime.now()` 取当前系统时间（需 import java.time.LocalDateTime）。

## 三、DeptMapper
    @Insert("insert into dept(name, create_time, update_time) values(#{name}, #{createTime}, #{updateTime})")
    void add(Dept dept);

### ⭐ 这里有个必考细节
参数是 **Dept 对象**时，`#{}` 里写的是**对象的属性名**：
- ✔ 正确：`#{name}`、`#{createTime}`、`#{updateTime}`
- ✘ 错误：`#{dept.name}`、`#{dept.createTime}`

原理：MyBatis 拿到 dept 对象后，**用属性名去找对应的 getter**（getName / getCreateTime）反射取值。

## 四、三个功能的横向对比（复习用）
| | 查询部门 | 删除部门 | 新增部门 |
|---|---|---|---|
| 请求方式 | GET | DELETE | **POST** |
| 参数位置 | URL 上的 ?id | URL 上的 ?id | **请求体 JSON** |
| 接参注解 | 无 / @RequestParam | @RequestParam | **@RequestBody** |
| 参数形态 | 单个 id | 单个 id | **Dept 对象** |
| 返回类型（Controller） | Result | Result | Result |
| 返回类型（Service/Mapper） | List\<Dept\> | void | **void** |
| 是否需要补全属性 | 否 | 否 | **是** |

## 五、易错点
| 易错 | 说明 |
|---|---|
| set 写在 mapper 调用之后 | 入库的时间是 null |
| `#{}` 里写 dept.name | 报错找不到属性 |
| 忘 import LocalDateTime | 编译不过 |
| 用 new Date() 代替 | 类型和实体类 LocalDateTime 不一致 |
| 表里 create_time 非空但没补 | 报错 Field 'create_time' doesn't have a default value |
| 参数对象忘了 @Data | getter 取不到值，`#{}` 全 null |

## 六、口诀
- **POST 传 JSON，@RequestBody 变对象**
- **Service 里先 set 时间，再交给 Mapper**
- **对象传参 #{} 写属性名，不写对象名**
