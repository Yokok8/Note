# 多表查询与笛卡尔积

## 一、多表查询
**指从多张表中查询数据。**&#8203;

为什么需要：一张表的信息不够用。
比如查员工列表要显示"部门名称"，但 emp 表里只有 dept_id，部门名称在 dept 表里 → 必须**两张表一起查**。

## 二、⭐ 笛卡尔积（课件原文）
> 指在数学中，两个集合（A 集合和 B 集合）的**所有组合情况**。
> （在多表查询时，**需要消除无效的笛卡尔积**）

课件示例：
- A 表 2 行：X,3 / Y,2
- B 表 4 行：1,zhan / 2,li / 3,wang / 4,qian
- 结果：**2 × 4 = 8 行**，每一行 A 都和 4 行 B 全部配了一遍

**规律：笛卡尔积行数 = A 表行数 × B 表行数。**&#8203;

## 三、什么时候会产生
只要你 `select ... from A, B` 而**不写关联条件**，就必然得到笛卡尔积：

    -- 危险：产生笛卡尔积
    select * from emp, dept;

emp 有 500 条、dept 有 6 条 → 直接查出 **3000 条**，且 99% 是无意义组合（张三是研发部、张三又是学工部…）。

## 四、怎么消除：加关联条件
    -- 方式一：用 where 加关联条件
    select * from emp, dept where emp.dept_id = dept.id;

    -- 方式二：用 inner join ... on（推荐，语义更清晰）
    select * from emp inner join dept on emp.dept_id = dept.id;

两张写法结果一样，都是"只保留能对上的行"。

## 五、为什么叫"无效"的笛卡尔积
笛卡尔积本身在数学上没错，**只是业务上大多没意义**：

| 结果行 | 是否有意义 |
|---|---|
| 宋江（dept_id=2）+ 研发部（id=2） | ✔ 有效 |
| 宋江（dept_id=2）+ 学工部（id=1） | ✘ 无效组合，要剔除 |

所以不是"删除笛卡尔积"，而是"**用关联条件筛掉无效部分**"。

## 六、易错点
| 易错 | 说明 |
|---|---|
| 忘了写关联条件 | 数据量爆炸，页面直接卡死（500×6=3000 行，大表能到几百万） |
| 关联字段写反 | on 两边字段类型要一致，逻辑上要用**外键 = 主键** |
| 用错连接类型 | `where` 式连接 = 内连接，会丢掉不匹配的行（包括部门为空的员工） |
| 以为笛卡尔积是 bug | 是 SQL 的**正常行为**，只是要自己加条件消除 |

## 七、口诀
- **多表查询 = 从多张表里查数据**
- **不带条件查两张表 → 笛卡尔积（行数相乘）**&#8203;
- **加 where / on 关联条件，只留有效组合**

# 多表查询分类

## 一、分类结构（就这三大块）
    ｜— 内连接：查 A、B 的交集部分
    连接查询 —｜
              ｜— 外连接 —｜— 左外连接：查左表所有数据（含交集）
                          ｜— 右外连接：查右表所有数据（含交集）

    子查询（后面单独讲）

## 二、三种连接一句话对照
| 类型 | 查什么 | 集合含义 |
|---|---|---|
| **内连接** | 只查两表**都对得上**的数据 | A ∩ B（交集） |
| **左外连接** | **左表全要**，右表对不上就补 null | A 全部 + A∩B |
| **右外连接** | **右表全要**，左表对不上就补 null | B 全部 + A∩B |

## 三、怎么选
- 只要"匹配上的数据" → **内连接**（比如查员工的部门名，员工一定有部门）
- 要"左表一条都不能少" → **左外连接**（比如查所有部门及其员工数，没员工的部门也要显示）
- 要"右表一条都不能少" → **右外连接**

## 四、口诀
- **内连接要交集，外连接保一方**
- **左外保左表，右外保右表，对不上就补 null**
- **子查询另算一类**

# 内连接

## 一、定义
内连接查询的是两张表**交集部分**的数据。
（就是 A ∩ B：两张表**都对得上**的那些行）

## 二、两种语法

### 1. 隐式内连接（常见）
    select 字段列表 from 表1, 表2 where 连接条件 ...;

### 2. 显式内连接
    select 字段列表 from 表1 [inner] join 表2 on 连接条件 ...;

`[inner]` 是**可省略**的，所以 `join` 单独写就是内连接。

**两者查询结果完全相同**，只是写法风格不同。企业项目里两种都能见到。

## 三、起别名，简化书写
    select 字段列表 from 表1 [as] 别名1, 表2 [as] 别名2 where 条件 ...;

- `as` 可以省略：`from emp e, dept d` 就等于 `from emp as e, dept as d`
- 好处：字段不用写全表名，`e.name` 代替 `emp.name`

## 四、完整示例（emp + dept）
    -- 隐式内连接：查员工姓名和部门名称
    select e.name, d.name from emp e, dept d where e.dept_id = d.id;

    -- 显式内连接：同样的结果
    select e.name, d.name from emp e inner join dept d on e.dept_id = d.id;

    -- 带条件筛选（内连接 + where 追加业务条件）
    select e.name, d.name from emp e, dept d
    where e.dept_id = d.id and e.gender = 1 and d.name = '研发部';

## 五、⭐ 起别名的坑（最容易出错）
**一旦给表起了别名，原来的表名就不能再用了！**

    -- ✔ 正确：全用别名
    select e.name, d.name from emp e, dept d where e.dept_id = d.id;

    -- ✘ 错误：起了别名 e 还写 emp.name → 报错 Unknown column
    select emp.name, d.name from emp e, dept d where e.dept_id = d.id;

## 六、易错点
| 易错 | 说明 |
|---|---|
| 起了别名还用原表名 | 直接报错，别名就是"改名" |
| 忘写连接条件 | 变成笛卡尔积 |
| 两个表有同名字段（都叫 name） | 必须用 `表名.字段名` 区分，否则 `Column 'name' is ambiguous` |
| on 和 where 混用位置 | 显式连接用 on 写连接条件，业务筛选条件用 where |
| 以为 inner 必须写 | 可省略，`join` 默认就是内连接 |

## 七、口诀
- **内连接取交集，两种写法：逗号 + where，join + on**
- **显式显式都一样，结果完全相同**
- **起别名省事，但原名就不能再用了**

# 外连接

## 一、两种语法（课件原文）
外连接分为**左外连接**和**右外连接**。

### 1. 左外连接（常见）
    select 字段列表 from 表1 left [outer] join 表2 on 连接条件 ...;

### 2. 右外连接
    select 字段列表 from 表1 right [outer] join 表2 on 连接条件 ...;

`[outer]` 可省略 → 直接写 `left join` / `right join`。

## 二、⭐ 课件提示（重点）
> 对于外连接，**常用的是左外连接**，因为**右外连接的 SQL 也可以改造成左外连接（两张表调换个顺序）**&#8203;。

    -- 右外连接
    select * from emp e right join dept d on e.dept_id = d.id;

    -- 完全等价，改成左外连接（表顺序调换）
    select * from dept d left join emp e on d.id = e.dept_id;

**结论：右外连接不用特意记语法，会左外 + 会调换表顺序就够了。**&#8203;

## 三、外连接的本质：主表一条不能少
| 连接类型 | 谁是"主表" | 从表对不上怎么办 |
|---|---|---|
| 左外连接 | **左表** | 右表字段显示 **null** |
| 右外连接 | **右表** | 左表字段显示 **null** |
| 内连接 | 没有主表 | **整行丢掉** |

举例：查所有部门及其员工（没员工的部门也要显示）
    select d.name, e.name
    from dept d left join emp e on d.id = e.dept_id;

→ 刚成立、还没员工的部门，也会显示一行，e.name 为 **NULL**。
如果用内连接，这个部门就**直接消失了**。

## 四、什么时候必须用外连接
| 需求 | 用哪种 |
|---|---|
| 查员工的部门名（员工一定有部门） | 内连接就够 |
| **查所有部门及员工数（含 0 人的部门）**&#8203; | **左外连接** |
| 统计某门课程被选了多少次（含 0 次的课） | 左外连接 |

**判断口诀：只要"主表里有数据没匹配上也要显示"，就必须外连接。**&#8203;

## 五、易错点
| 易错 | 说明 |
|---|---|
| 把条件写在 where 里 | 外连接的条件要写在 **on 之后**，写在 where 里会让外连接"退化成内连接" |
| 以为左右表可随便换 | 换了结果就不一样（left 变 right，语义完全不同） |
| 忘了 null 的影响 | 对 null 做 count/sum 要小心（count(*) 会算进去，count(字段) 不会） |
| 用内连接统计"0 条的也想要" | 结果直接少一行，业务就错了 |

## 六、口诀
- **左外 left join 保左表，右外 right join 保右表**
- **右外能改成左外：两表换个位置**
- **对不上的补 null；想保留"没有匹配的"就用外连接**

# 子查询

## 一、定义（课件原文）
**SQL 语句中嵌套 select 语句，称为嵌套查询，又称子查询。**&#8203;

形式：
    select * from t1 where column1 = (select column1 from t2 ...);
                                      ↑ 这一段就是子查询

## 二、子查询能放在哪
- **外部语句可以是 insert / update / delete / select 的任何一个**
- **最常见的是 select**

    -- 用在 select（最常见）
    select (select name from dept where id = 1) as dept_name;

    -- 用在 update
    update emp set salary = 5000 where dept_id = (select id from dept where name = '教研部');

    -- 用在 delete
    delete from emp where dept_id = (select id from dept where name = '测试部');

## 三、⭐ 四种分类（按返回结果形状分）
| 分类 | 返回结果 | 常用搭配 | 例子 |
|---|---|---|---|
| **标量子查询** | **单个值**（1 个格子） | `= > < >= <=` | `where dept_id = (select id from dept where name='教研部')` |
| **列子查询** | **一列**（多行 1 列） | `in / not in` | `where dept_id in (select id from dept where name in ('教研部','学工部'))` |
| **行子查询** | **一行**（1 行多列） | `(字段1, 字段2) = (...)` | `where (job, dept_id) = (select job, dept_id from emp where id = 5)` |
| **表子查询** | **多行多列**（像个临时表） | 放在 **from 后面**当表用 | `from (select * from emp where gender = 1) e` |

记忆方式：**看子查询吐出来几个格子** → 1 个 = 标量；一竖列 = 列；一横排 = 行；一片 = 表。

## 四、⭐ 课件的做题提示（方法论）
> **子查询的要点是：先对需求做拆分，明确具体的步骤，然后再逐步编写 SQL 语句。**&#8203;

拆题三步：
1. 需求要什么？（结果字段）
2. 中间需要先查出什么？（这就是子查询）
3. 把第 2 步的 SQL 塞进第 1 步里

举例："查询教研部的所有员工"
- 第 1 步：`select * from emp where dept_id = ?`
- 第 2 步：问号是啥？→ `select id from dept where name = '教研部'`
- 合并：`select * from emp where dept_id = (select id from dept where name = '教研部')`

**先写外层，再把内层塞进去 —— 比直接憋一坨长 SQL 靠谱得多。**&#8203;

## 五、易错点
| 易错 | 说明 |
|---|---|
| 标量子查询返回了多行 | 报错 `Subquery returns more than 1 row`，该用 `in` |
| 列子查询用 `=` | 应该用 `in` |
| 表子查询忘了起别名 | from 后面的子查询**必须给别名** |
| 内外层字段搞混 | 建议内层字段加表名限定 |
| 子查询嵌套太深 | 性能差，能用 join 就用 join |

## 六、口诀
- **SQL 里套 select，就是子查询**
- **看返回几个格子分四类：标量、列、行、表**
- **单值用等号，一列用 in，一行用括号，多行多列放 from**
- **先拆需求再写 SQL，外层写完塞内层**
